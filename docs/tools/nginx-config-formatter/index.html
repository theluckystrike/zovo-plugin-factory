Questions
Is my config uploaded anywhere?
No. The page reads your files inside this tab. Its Content Security Policy sets connect-src to none, so it cannot send your config, hostnames or paths anywhere, and it loads no library from another site. Open the Network tab of your browser tools and you will see no request when a file opens.
Can the formatter break my config?
No. It puts one statement on each line and indents blocks, keeps comments, strings and regexes byte for byte, and keeps long log_format values on their own lines. Then it parses its own result, and if the statements and comments are not the same as before, it changes nothing. A file with unbalanced braces or an unclosed string is not formatted, and the page names the line.
Which problems does it find?
A missing ; at the end of a line, unclosed or extra braces, unclosed strings, a directive in a block where nginx does not allow it (listen in a location, proxy_set_header inside if), the same root or listen twice in a block, two servers with the same name on one port, ssl on, and typos in directive names. The page can apply the two quick fixes, the missing ; and the typo, and save the fixed file.
Does it follow include files?
Yes, among the files you pick. Pick your config folder, for example /etc/nginx, and include lines such as conf.d/*.conf or /etc/nginx/sites-enabled/* are read the way nginx reads them, in sorted order. The Servers and locations tab starts from nginx.conf and lists every server with its listen ports and names, and each location with what it does.
Is this the same as nginx -t?
No. The page reads your files; it does not run nginx. Some errors only nginx itself can find, such as a missing certificate file or a module that is not loaded.
Does it work offline?
Yes. After the first visit the page keeps a copy of its own files, so it formats and checks configs with no connection.
