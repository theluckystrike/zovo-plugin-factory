Questions

Is my .env file uploaded anywhere?

No. The page reads the file inside this tab. Its Content Security Policy sets connect-src to none, so it cannot send your keys anywhere, and it loads no library from another site. Open the Network tab of your browser tools and you will see no request when a file opens. Values of secret-looking keys also stay hidden on screen until you choose Show all values.

Which values are hidden?

Keys whose names hold PASSWORD, SECRET, TOKEN, API_KEY, PRIVATE, DSN, DATABASE_URL and similar words. Hide all values hides every value, and Show all values shows them. Template files such as .env.example, .env.sample and .env.template are never hidden, since they should hold no real secrets.

What problems does it find?

A key set twice (the dotenv package keeps the first value, shells and Docker Compose keep the last), spaces around =, a quote that is never closed, text after a closing quote, a line with no =, an invalid name such as 2FA_KEY, trailing spaces, a value with spaces and no quotes, and ${NAME} that no line of the file sets.

What do Fix and Format change?

Fix applies the quick fix shown in the row, the same one the VS Code extension offers. Format removes the spaces around = and trailing spaces and keeps comments, order and quotes. Undo steps back, and Save .env downloads the changed file. Your original file is never changed.

Which syntax does it follow?

KEY=value, an optional export in front, # comments, single quotes taken as written, double quotes with escapes and line breaks, backticks, and an unquoted value that ends at a space before #. Where the dotenv package, python-dotenv and Docker Compose disagree, the problem says so.

Does it work offline?

Yes. After the first visit the page keeps a copy of its own files, so it checks .env files with no connection.
