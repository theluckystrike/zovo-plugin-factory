Questions

Is my binary uploaded anywhere?

No. The page reads the file inside this tab. Its Content Security Policy sets connect-src to none, so the page cannot send your file anywhere, and it loads no library. Open the Network tab of your browser tools and you will see no request when a file opens.

Does it run the program?

No. The page reads bytes and shows them. Nothing in the file is loaded or run, and names and strings from the file are written as plain text, never as HTML.

What does it show for ELF files?

The header, sections, segments (program headers), imports with their library and symbol version (such as GLIBC_2.17), exports, the symbols of .symtab and .dynsym, the dynamic section and notes such as the build ID. 32 and 64-bit, little and big endian, .so, .o, .ko and Linux executables.

What does it show for EXE and DLL files?

The DOS, COFF and optional headers, security flags (ASLR, DEP, Control Flow Guard), data directories, sections, imports by name and ordinal, delay-load imports, exports with forwarders, resources, the PDB path of the debug info and the .NET runtime header.

Does it read macOS binaries?

Yes. Mach-O files show the header, load commands, segments and sections, linked libraries, imports with their library, exports from the export trie, symbols, the UUID and the platform and SDK. For a universal binary you pick the architecture, such as arm64 or x86_64.

Is a hostile or broken file safe to open?

Every offset and count from the file is checked against the file size, loops in import tables, resource trees and export tries are caught, and reading stops after 8 seconds. A damaged file shows the part that could be read and a note on what is wrong.
