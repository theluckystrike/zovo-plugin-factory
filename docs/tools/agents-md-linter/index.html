Questions

Is my repo uploaded anywhere?

No. The page reads the files inside this tab with the File API. Its Content Security Policy sets connect-src to none, so the page cannot send your files anywhere. When you choose a folder, Chrome asks whether to upload the files to this site: that is the browser's standard wording for giving a page a folder. Nothing is uploaded, and the Network tab of your browser tools shows no request.

What does it check?

Scripts that are not in package.json (npm run, pnpm, yarn, bun run), make targets that are not in the Makefile, just recipes and Taskfile tasks (CD001); backticked paths and Markdown links that do not exist, and globs that match nothing (CD002); pnpm, yarn, bun or npm when the lockfile or packageManager says another (CD003); Node, Python and Go versions that do not match .nvmrc, engines, .python-version, pyproject.toml or go.mod (CD004); two files in one folder that give different commands for test, build or lint (CD005); @imports in CLAUDE.md and GEMINI.md that point to missing files (CD007); and an AGENTS.md over the Codex 32 KiB limit (CD008).

What works with just one file?

With one file, or pasted text, you get the size table (bytes, about how many tokens and what is left of the Codex 32 KiB limit), the CD008 check, the heading outline and a list of every command, path, import and version the file states. Pick package.json, a Makefile or .nvmrc too and the command, package manager and version checks run. Paths, imports and globs need the whole folder.

How does it avoid false alarms?

It skips text that reads as negated, historical or an example: "do not run npm run eject", "dropped Python 3.8", anything under an Example heading. It skips placeholders such as <name> and path/to/, URLs, ~/ and absolute paths, build folders such as dist and build, .env files and paths in the root .gitignore. In SKILL.md it checks only the skill's own scripts, references and assets. These are word rules, so an unusual sentence can still be read the wrong way.

Can I turn a finding off?

Yes, with the same HTML comments as the extension: a context-drift-disable-next-line comment with the rule id, such as CD002, above a line (or above a code fence for the whole block), or a context-drift-disable comment for the whole file. In Cursor .mdc frontmatter use a YAML comment. Findings turned off are listed dimmed.

What does the extension add?

The Context Drift extension shows the findings as you type, with quick fixes and Apply all. It also checks cargo, uv run and poetry run commands, every workspace package, git ignore rules with git check-ignore, sparse checkouts and stale files (CD006), and the same check runs in CI from the command line.
