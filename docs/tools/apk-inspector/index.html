    Questions

    Is my APK uploaded anywhere?

    No. The page reads the file inside this tab, in a background worker of the page. Its Content Security Policy sets connect-src to none, and the reader has no network code. Open the Network tab of your browser tools and you will see no request when an APK opens.

    What does it show?

    The package name, versionName and versionCode, min, target and compile SDK with the Android version, the app label when it is a plain string, the debuggable, allowBackup and cleartext traffic flags, every permission with the dangerous ones flagged, each activity, service, receiver and provider with its exported flag and the reason, DEX method counts, the size of every folder, file type and file, native libraries per ABI, and the signing schemes with the certificate.

    How is the exported flag worked out?

    If the manifest sets android:exported, that value is shown. Without it, a component with an intent filter counts as exported when targetSdk is below 31, and Android 12 and newer refuse to install an app that leaves it out. Without an intent filter the default is not exported. The Why column says which rule applied, and the launcher activity is marked.

    What is the 65,536 method limit?

    One DEX file can address at most 65,536 method references. The DEX tab shows the references in each classes.dex file and its share of the limit, with field, string, type and prototype counts. Apps above the limit split their code over several DEX files.

    Can it open big APKs and App Bundles?

    Yes. Only the central directory, the manifest, the DEX files and the signature data are read, in 64 KB blocks, so a large APK opens without reading its assets. For an .aab bundle the files, sizes, DEX counts, native ABIs and signing are shown; its manifest is a protocol buffer, which is not decoded. For .apks and .xapk files the APKs inside are listed and the base APK is read.

    Does it check the signature?

    No. It shows what is there: v1 (JAR) signature files, the APK Signing Block with its v2, v3 and v3.1 blocks, and the signer certificate with its SHA-256 and SHA-1, subject, issuer, validity and key type. It does not verify the signatures.

    Is a damaged or hostile APK safe to open?

    Every count and offset is checked against the bytes that are really there, an entry is unpacked only up to the size its header gives, so a zip bomb is stopped early, and the reader is stopped after 30 seconds. Values are written as plain text, never as HTML.
