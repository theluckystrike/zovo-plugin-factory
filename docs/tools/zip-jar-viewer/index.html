Questions
Is my JAR uploaded anywhere?
No. The page reads the file inside this tab. Its Content Security Policy sets connect-src to none, so the page cannot send your code anywhere, and it loads no library. Open the Network tab of your browser tools and you will see no request when a file opens.
Does it run the code in the JAR?
No. The page reads bytes and shows them. A class file is parsed as data by a reader written in JavaScript, nothing is loaded into a Java runtime, and names and text from the archive are written as plain text, never as HTML.
What does the overview show?
The format (JAR, WAR, Spring Boot JAR, EAR or AAR), size, entries, classes and packages, Main-Class, Start-Class, Created-By, the module name, Multi-Release, whether the JAR is signed, and a count of the Java versions the classes were compiled for. Class file 52 is Java 8, 61 is Java 17 and 65 is Java 21.
What do I see for a class?
A javap -c -p style bytecode listing with every opcode, switches, resolved constants, exception tables, line numbers and local variables, the fields and methods as Java declarations with generics, the constant pool, and the class info: flags, super class, interfaces, inner classes and every attribute. It needs no Java.
Can it show the Java source?
Not on this page: decompiling needs a Java runtime. The free JAR Viewer & Java Decompiler extension for VS Code decompiles any class to Java source with the bundled CFR decompiler and the Java already on your computer.
Is a hostile or broken archive safe to open?
Entries are unpacked one at a time when you click them, up to 64 MB each, and an entry that claims more than 1,000 times its packed size or unpacks to more than its header says is stopped. Names with .. or absolute paths are marked and never written anywhere. Every count in a class file is checked against the bytes that are left.
