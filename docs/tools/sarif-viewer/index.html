Questions

Is my SARIF log uploaded anywhere?

No. The page reads the log inside this tab with JavaScript. Its Content Security Policy sets connect-src to none, so the page cannot send your results anywhere. Open the Network tab of your browser tools and you will see no request when a log opens.

Which scanners does it work with?

Any tool that writes SARIF 2.1.0: CodeQL, Semgrep, ESLint, Bandit, Trivy, Checkov, Gitleaks, Snyk, SpotBugs, Roslyn analyzers and more. A log with several runs shows a tool filter. SARIF 2.0 logs open with a note, because some fields have other names there.

What does it show for each result?

The level, rule id and name, message, file, line and column, the snippet, the rule help, the help link, CWE links, security severity, precision, tags, fingerprints, suppressions with their justification, related locations and every step of the code flow. Paths that use uriBaseId such as %SRCROOT% are joined with their base when the log names it.

What if the log has no results?

The page says so clearly, with the tool name and the number of rules it ran, so you know the scan ran and found nothing. If the log says the run did not finish, the page says that too, with the notes the tool wrote.

Can I jump to the code?

Not from a browser page, because it cannot open files on your computer. The free SARIF Viewer extension for VS Code opens each result at its line, maps CI paths to your workspace and steps through code flows in the editor.

Is a hostile log safe to open?

Messages, rule help and paths are shown as plain text, never as HTML, and nothing in the log runs. Only http and https help links are made clickable, and they open only when you click them. A log that is not valid JSON gets a message with the line and column of the error.

Does it work offline?

Yes. After the first visit the page keeps a copy of its own files, so it opens SARIF logs with no connection.
