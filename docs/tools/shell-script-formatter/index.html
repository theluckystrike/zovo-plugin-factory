Questions

Is my script uploaded anywhere?

No. The page reads the script inside this tab and formats it in a background worker of the same tab. Its Content Security Policy sets connect-src to none, and the shfmt engine is part of the page, so nothing is sent anywhere. Open the Network tab of your browser tools and you will see no request when you format a script.

Is the output the same as the shfmt command?

Yes. The page runs shfmt 3.14.1 compiled to WebAssembly, the same file the Shell Formatter extension ships. With the same options it gives the same output as the shfmt command line tool. The line under the result shows the matching shfmt flags, so you can run the same check in CI.

Which shell dialect does it use?

It reads the shebang line first (bash, sh, dash, zsh, ksh, mksh, bats), then the file name (.bash, .zsh, .zshrc, .bats, .ksh), else bash. That is the same order as shfmt. If a script without a shebang uses a feature of another dialect, it tries the dialect the parser names. You can also pick the dialect yourself.

What happens with a syntax error?

Nothing is changed. The page shows the error from shfmt with its line and column and marks that line in your script.

What is the same commands check?

Before the result is shown, the page parses the formatted script again and compares it with the original, with layout and comment places removed. If they would not run the same commands, the result is not shown. The check is skipped when Simplify is on, as in the extension.

Does it format fish, csh, Dockerfiles or .env files?

No. shfmt cannot parse fish or csh, so those scripts are refused. A Dockerfile or a .env file is not a shell script, and the extension never changes them either.
