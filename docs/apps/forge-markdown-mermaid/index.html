Markdown + Mermaid for Confluence

Markdown + Mermaid is a Forge app for Confluence Cloud. It adds two macros, and both render in the browser.

  • Markdown + Mermaid takes pasted GitHub-flavoured Markdown. Tables, task lists, highlighted code and footnotes all render, and every fenced mermaid code block becomes a diagram.
  • Mermaid diagram shows one Mermaid diagram on its own.

The app has no backend, no storage and no egress. All JavaScript ships as Forge static resources, so it's built to qualify for Runs on Atlassian. Confluence still applies the badge automatically after deploy, and you can check it with forge eligibility.

---

How it works

Confluence page ──► Custom UI iframe (static/ui/build/view)
                      ├─ @forge/bridge view.getContext() → macro config {source, theme, maxHeight, showSource}
                      ├─ marked (GFM) + marked-footnote + highlight.js core (20 languages), with a cost guard (render.js RENDER_GUARD)
                      ├─ DOMPurify (HTML profile, hooks for links/images/inputs, SANITIZE_NAMED_PROPS)
                      └─ mermaid (lazy chunk, prefetched while Markdown renders; securityLevel 'strict',
                         locked themeCSS/fontFamily/dompurifyConfig, image-free labels) → DOMPurify SVG pass + CSS clean
Macro editor ──────► Custom UI config (static/ui/build/config): editor + options + live preview → view.submit({config})

There's no resolver and no src/index.js. The app has no backend functions, so permissions.scopes is [] and it has no external permission.

Config values are saved as strings in the macro's parameters, which Confluence stores in the page itself. The app has no storage of its own.

Content security policy

Scripts load only from the app's own resource directory ('self'). The manifest sets permissions.content.styles: [unsafe-inline] because Mermaid writes <style> elements and style attributes into its SVGs. Raw HTML in Markdown can't use it, since style tags and attributes are stripped from Markdown output. In diagram labels, author style attributes and images are removed before Mermaid draws them.

Mermaid's own CSS (from style/classDef statements) stays. But before Mermaid sees the diagram, every url(, image(, image-set(, cross-fade(, element(, src( and @import in its source gets an invisible word joiner (U+2060), so a browser doesn't treat it as CSS that loads a file.

One case is left alone. In flowchart/graph, architecture and mindmap diagrams, a node or service id written before its shape (src(Source) --> build, service url(internet)[Web]) stays as written, because Mermaid's parser would reject the joiner there. The exception only applies outside quotes, brackets, HTML tags, frontmatter, directives and comments. It never applies on lines with classDef/style/linkStyle/class, or after : or ,. Mermaid's flowchart parser also rejects ( in style/classDef values.

Flowchart image shapes (A@{ img: "https://…" }) get an error before Mermaid runs, because Mermaid would load that image during layout. Base64 PNG/GIF/JPEG/WebP data URLs work. Diagrams that spell these functions with CSS escapes (\75 rl() get an error too. The final SVG is cleaned again, with remote url(), @import and fixed/sticky positioning removed, and directives can't set themeCSS or fontFamily.
