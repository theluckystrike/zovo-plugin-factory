Tickoff Checklists for Jira

Tickoff puts a checklist on any Jira work item. Add the steps, tick them off, and see the progress in the same panel. The checklist is free. Checklist templates and copying a checklist from another work item are paid features.

The checklist is saved on the work item itself, as a Jira issue property. So Jira search can find it, a workflow can wait for it, and it stays with the work item.

Use the checklist

Open a work item and add the Checklist panel from the Apps button. Then do these steps.

  1. Type an item in the "New item" field and select Add.
  2. Tick the box next to an item when it is done.
  3. Use Edit, Up, Down or Delete on an item to change it.

The panel shows a line like "3 of 5 done" and a progress bar. A checklist can have up to 100 items. Each item can have up to 255 characters.

Changes go to the latest saved checklist, item by item. If two people tick different items at the same time, both changes stay. If you change an item that someone else deleted, the panel says "The checklist changed. Reload to see the latest version." and shows the latest checklist.

To change a checklist, you need permission to edit the work item. People who can only view the work item see the checklist, but they cannot change it.

Find work items with JQL

Jira indexes the checklist of each work item. You can use these fields in any JQL search, filter or board.

JQLFinds
checklistOpen > 0Work items with items that are not done
checklistTotal > 0 AND checklistComplete = "yes"Work items with a checklist where every item is done
checklistTotal = 0Work items whose checklist had items that were all deleted

A work item that never had a checklist has no value for these fields, so these searches do not find it.

Block a transition until the checklist is done

Tickoff adds the workflow validator "Checklist is complete". A Jira admin adds it to a transition in the workflow editor. The transition then stops with "Finish all checklist items before this transition." while the work item has open items. A work item with no checklist can move on.

Templates and copy (paid features)

These features need an active subscription or a free trial. Without one, the panel shows "Checklist templates is a paid feature of Tickoff. A Jira admin can start a free trial or subscribe in Manage apps." The checklist itself keeps working.

  • Save as template. Saves the item text of this checklist under a name. Templates are shared by all users of the site. A site can keep up to 50 templates.
  • Apply template. Adds the template items to the end of the checklist, or replaces the checklist. New items start as not done.
  • Delete template. Removes the template for everyone on the site.
  • Copy from a work item. Enter a work item key, for example ABC-123. Tickoff adds the items of that checklist to this one, as not done. You must be able to see the other work item.

The Templates and Copy sections open only when you select them.

Tickoff is free for up to 10 users. Larger sites pay per user through Atlassian. If a subscription ends, the checklists stay and the panel keeps working.

Privacy and data

Tickoff runs on Atlassian Forge. It has no outside servers, and it sends no data out of Atlassian.

  • Checklists are saved in the issue property tickoff-checklist on each work item, in your Jira site.
  • Templates are saved in Forge app storage. A template holds its name and the item text only.
  • Tickoff stores no account IDs, names or email addresses.
  • All Jira calls run as the signed-in user, so Jira permissions decide who can see or change a checklist.

The app asks for three scopes. read:jira-work reads the checklist property. write:jira-work saves it. storage:app keeps the templates.
