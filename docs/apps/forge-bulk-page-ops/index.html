Bulk Page Operations for Confluence

Move, copy, label and archive up to 500 selected Confluence pages in one job, after a dry run shows you what will happen to each page.

Bulk Page Operations is a Forge app for Confluence Cloud. It adds a page to each space's settings. You pick pages with CQL or by choosing a parent page, pick what to do with them, check the dry run, and start the job. The job runs in the background and you can watch it, cancel it, and undo label changes later.

What it does

OperationWhat happens in Confluence
MoveEach top-level selected page moves under the target page, children included
CopyEach page is copied under the target page, either on its own or with all its children
Add labelsUp to 10 labels are added to every selected page
Remove labelsUp to 10 labels are removed from every selected page
ArchiveEach selected page is archived with Confluence's archive API

You can select pages in two ways.

  • CQL, such as label = "draft" AND lastmodified < now("-180d"). The app always adds space = "<this space>" AND type = page around your query, so a job can't reach pages in other spaces. An ORDER BY is dropped, and unbalanced quotes or parentheses are refused before anything runs.
  • A parent page (ID or link) and everything below it, with or without the parent itself.

The dry run

Nothing changes until you've seen a preview. It lists every selected page with one of three results.

  • Will change.
  • Goes along with a parent. For a move, or a copy with children, a page whose selected ancestor is being moved or copied isn't handled twice. A skipped ancestor doesn't count, so its selected children are handled on their own.
  • Skipped, with the reason. Examples are a move into the page's own subtree, a page that's already a direct child of the target, a copy title that would go past 255 characters, and a same-space copy with no title prefix (Confluence needs unique titles in a space).

The preview also reads your permissions in the space (or in the target page's space for move and copy) and warns you if Confluence says you can't edit, add or archive pages there. It's a warning, not a block. Confluence still decides page by page when the job runs, because page restrictions can differ.

When you start the job, the server runs the same search and plan again. If any selected page or its result differs from the preview, the job doesn't start and you're asked to preview again. That holds even when the count is the same, for example when one page drops out of a CQL date range and another comes in. Children that aren't selected aren't part of this check, so a copy with children copies the children a page has when the job runs.

Running jobs

Jobs run as a chain of Forge async events. Each step handles pages for up to about 30 seconds, saves its progress after every page, and queues the next step. The page shows a progress bar, the counts and the first 100 failures with Confluence's own error message for each. Details in the job history lists every page of a job with its result (only for the person who started it).

  • Copy with children and archive start Confluence long tasks. The job waits for each task to finish (checked every 5 seconds, for up to about 10 minutes per task) before it moves on. A task that's still running after that is reported as a failure that may still finish, and it isn't sent again.
  • Archive requests go in batches of 25. If Confluence refuses a batch, the job retries those pages one at a time so you can see which page failed. Pages the batch did archive count as done.
  • If Confluence rate-limits the app, the job pauses for 30 seconds and retries the same page, up to 3 times. A copy or archive request that gets a server error isn't sent again, because Confluence may have done the work. The failure tells you to check.
  • Cancel stops the job before its next page. A copy or archive task that Confluence has already started may still finish.
  • One job can run per space at a time. A job that makes no progress for 15 minutes is shown as stalled and no longer blocks new jobs.

Forge allows a limited chain of background events, so a job stops after 900 steps and says how many pages are left. Normal jobs need far fewer.

You can always see and cancel the jobs you started. Other people's jobs are listed only for space admins, and only a space admin can cancel someone else's job. The server checks this with Confluence as you each time (your space operations must include administer on the space). If Confluence doesn't confirm it, you see only your own jobs. Admins see the operation, status and counts of other people's jobs. Page titles, the target page's title and failure details are shown only to the person who started the job.

Undo for label jobs

Label jobs keep an undo log for 30 days. It records only what the job changed. A label that was already on a page before an add job isn't removed by undo, and a page that never had the label isn't touched.

The job notes each label change in the log before it sends it. If Confluence's answer gets lost (a server error after the change was made, or a background step cut off mid-request), the next attempt reads the page's labels again and logs the change if it happened. If the page fails for good, the job reads the labels once more and keeps only the changes it finds. Undo also checks each page before it changes anything, so it only reverses a label that's still in the state the job left it in. Only the person who started the job can undo it. Undo runs as a new job you can watch like any other, and if it fails or is cancelled you can run it again.

Move, copy and archive jobs can't be undone by the app. The confirmation dialog says so before you start.

Permissions

Every call to Confluence runs as the person using the app (asUser()), in the settings page and in the background steps. The app never calls Confluence as itself. So a job can only do what that person could do by hand, and each background step checks that it's running as the person who started the job before it touches anything.

ScopeWhy
search:confluenceCQL page search
read:confluence-content.summaryRead labels and Confluence task status

read:page:confluenceCheck the target page and the parent page
read:space:confluenceFind the space and read your permissions in it

The app has no external permissions, no remote back end and no egress. All code runs on Atlassian's Forge platform, so it's built to qualify for Runs on Atlassian. Atlassian decides eligibility, and forge eligibility checks it after deploy.

Once a week a scheduled trigger reports the stored account IDs to Atlassian with the Forge personal data reporting API (privacy.reportPersonalData). Job records of accounts that Atlassian reports as closed lose their account ID.

PRIVACY.md lists what's stored and for how long.

Not included

  • Changing page owners. I couldn't confirm a Confluence REST endpoint that changes only the owner. Updating the page itself would mean sending the whole body back and adding a page version for every page, so this version leaves it out.
  • Delete. Archive is the safer option, since archived pages can be restored in Confluence.
  • Blog posts, whiteboards and databases. Only pages are selected (type = page).

Known limitations

  • It hasn't run on a live Confluence site yet. The logic is covered by unit tests against a fake site, and the UI Kit page was syntax and import checked but not rendered. NOTES.md has the smoke test for the first deploy.
  • If the platform cuts off a background step mid-page and sends it again, the new attempt continues from the last saved page after 60 seconds. The page that was in progress may be sent twice, which can make a second copy. If no new attempt comes, the job shows as stalled after 15 minutes and you can cancel it and start a new one.
  • The space admin check and the permission warnings read GET /wiki/api/v2/spaces/{id}/operations. Its live answer hasn't been checked yet. If it doesn't list administer for space admins, admins see only their own jobs and can't cancel other people's jobs. A stuck job from someone else then stops blocking new jobs after 15 minutes.
  • The personal data report hasn't run against Atlassian yet. Run forge lint to see if it needs a scope, and check the trigger's log line after the first week.
  • Moving pages to another space follows Confluence's move rules. A title that already exists in the target space makes that page fail with Confluence's message.
