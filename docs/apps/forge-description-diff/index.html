Description Diff for Jira

See exactly what changed in an issue's Description: which words were added, which were removed, who made the change and when. Pick any two versions from the change history and compare them word by word or line by line. Summary, Environment and custom text fields (for example "Acceptance Criteria") work the same way.

Built on Atlassian Forge with UI Kit. It reads the issue's change history as the signed-in user and has no external servers, no egress and no app storage.

Where it appears

Open any issue in the new Jira issue view. In the Activity section, next to Comments, History and Work log, choose the Description diff tab.

What you can do

  • The tab opens on the most recent edit of the Description. Added text is green and bold. Removed text is red and struck through.
  • Pick two versions in the From and To pickers and compare them, even when they're far apart or in reverse order. The pickers list the original and the 199 newest versions (plus the pair you're viewing), each with its number, date, time and author. On an issue with more than 200 versions, the ones in between aren't in the pickers.
  • Older change and Newer change step one edit at a time, through every version.
  • Words mode shows the exact words that changed inside each line. Lines mode shows whole lines removed and added, like a code diff.
  • By default you only see the changed lines, with 2 unchanged lines of context and a "⋯ N unchanged lines" marker. Show full text shows the whole version with the changes marked.

The counts read like "+12 words added, −3 words removed" for the selected pair. In Lines mode they count lines.

If Summary, Environment or a single-line or multi-line text custom field has been edited, a Field picker appears. Each field shows its number of recorded changes. The app checks at most 240 fields per view for text, Description included. When more fields than that have changed, a notice says so.

How it works

Jira records each edit of a text field in the issue's change history, with the text before and after. The app reads that history (GET /rest/api/3/issue/{id}/changelog) and rebuilds every version:

  • "#1 Original" is the text before the first recorded edit. It is "(empty)" when the issue was created without one.
  • Each later version is the text after one recorded edit, labelled with its date (in your browser's time zone) and author.
  • If an edit starts from text that does not match the previous version, the app adds a version marked "Not in history". It shows the text the edit started from, and a notice says that at least one edit is missing from the history Jira returned. The app does not guess what the missing edit was.

The diff runs inside the app's Forge function. Lines are matched first (Myers' algorithm), then the words inside each changed block are compared. Chinese and Japanese text is compared character by character. When an unchanged word sits between two changes and isn't longer than them, it's shown as part of one replacement. So a rewritten sentence reads as "old sentence → new sentence" instead of fragments.

The word counts come from the exact word diff, with two exceptions. Each one comes with a notice.

  • A very large changed passage (for example a find-and-replace across the whole text) can be too big to compare as a whole. Then its lines are compared line by line. The app first lines up similar lines (lines whose shared start and end cover more than half of the longer line), so an added or removed line doesn't shift everything after it. If that's also too big and both sides have the same number of lines, it pairs them one to one, in order. Each pair's counts are exact. But near a moved, added or removed line, a line can end up paired with its neighbour, and then the counts are higher than the real change.
  • A part that is too different to compare in detail is shown as removed text followed by added text. The counts then cover that whole part.

The app shows the text exactly as Jira stores it in the change history. Formatting such as bold text, headings, lists or links can appear as markup characters. The tab says so under the diff.

Permissions and data

Scoperead:jira-work only: read the issue's change history and the names and types of its fields
Runs asThe signed-in user (asUser). You only see history for issues and fields that Jira lets you see.
Writes to JiraNever. The app has no write scope.
Stores dataNo. There is no app storage and no cache. Each view is read from Jira when you open it.
External callsNone. No egress, no remote back end.

The first time you open the tab, Forge asks you to allow the app to read Jira data as you. It's Forge's standard consent screen.

Requirements

  • Jira Cloud (Jira, Jira Software or Jira Service Management) with the new issue view. Forge's issue activity module does not support the old issue view.
  • The tab uses your browser's language and time zone for dates.

Support

Report problems through the Marketplace listing's support link. Please include the issue type and, if you can, the number of changes in the issue's History tab. Do not send issue text unless you are allowed to share it.
