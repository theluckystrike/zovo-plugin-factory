Relire et reprendre votre historique Claude Code dans VS Code

Installez Claude Code History & Codex History Viewer (Agent Session Viewer). L’extension liste vos sessions Claude Code de ~/.claude/projects et vos sessions Codex de ~/.codex/sessions dans une même vue latérale, ouvre chacune comme une transcription lisible et la reprend dans un terminal en un clic. La lecture, la recherche, la reprise et l’export d’une session en Markdown sont gratuits, sans compte. Zovo Pro (19 USD, payé une seule fois) ajoute un rapport d’utilisation et de coût, un export de partage avec les secrets masqués et l’export groupé en Markdown, avec 3 essais gratuits pour chaque outil Pro.

Étapes dans VS Code

  1. Installez Agent Session Viewer depuis le Marketplace, ou appuyez sur Ctrl+P (Cmd+P sur macOS) et lancez ext install zovo.agent-session-viewer.
  2. Cliquez sur l’icône Agent Sessions dans la barre d’activité. La vue Sessions liste les sessions Claude Code et Codex, groupées par dossier de projet, avec les sous-agents sous la session qui les a lancés.
  3. Cliquez sur une session pour la lire. Les appels d’outils sont repliés, les appels en échec ont une marque rouge et les modifications de fichiers s’affichent en diff. L’en-tête montre le modèle, la branche git, le nombre de tours et les totaux de tokens.
  4. Pour retrouver une ancienne session, cliquez sur l’icône de recherche en haut de la vue, ou lancez « Agent Sessions: Search Sessions » depuis la Command Palette. Choisissez un résultat pour ouvrir la session à l’endroit trouvé.
  5. Cliquez sur l’icône de terminal à côté de la session (Resume in Terminal). Un terminal s’ouvre dans le dossier du projet et lance claude --resume <id> ou codex resume <id>.
  6. Pour un fichier de session .jsonl situé dans un autre dossier, faites un clic droit dessus, choisissez Open With puis Agent Session Viewer.

Ce qui est gratuit et ce qu’ajoute Zovo Pro

L’arbre Sessions, la lecture des sessions, la recherche dans toutes les sessions, Resume in Terminal, Copy Resume Command, l’export d’une session en Markdown, la vue brute et Reveal in File Manager sont gratuits. L’historique n’est pas limité, et aucune connexion à un compte n’est demandée.

Share-safe export enregistre une session, ou toutes les sessions d’un projet, dans une seule page HTML autonome ou un seul fichier Markdown. Les clés d’API, les tokens, les mots de passe dans les URL, les valeurs .env, les clés privées, les adresses e-mail et votre dossier personnel sont remplacés par [REDACTED ...], et le message liste ce qui a été masqué. Vous pouvez envoyer une session pour une pull request, un audit ou une passation sans la nettoyer à la main.

Utiliser Share-safe export (Zovo Pro)

  1. Ouvrez la session, puis cliquez sur le bouton Share-safe export dans la barre d’outils de la session. Vous pouvez aussi faire un clic droit sur une session ou un dossier de projet dans l’arbre Sessions et choisir « Share-Safe Export, Secrets Redacted (Pro)… ».
  2. Avec une session ouverte, vous pouvez aussi lancer « Agent Sessions: Share-Safe Export, Secrets Redacted (Pro)… » depuis la Command Palette.
  3. Choisissez le format, page HTML ou Markdown, avec ou sans les sorties des outils. Choisissez ensuite où enregistrer le fichier.
  4. Relisez l’export avant de le partager. Un essai ne compte que si le fichier est enregistré. Échap ou Cancel ne coûte rien.

Share-safe export fonctionne 3 fois sur votre ordinateur avant de demander une licence. Il n’y a ni fenêtre surgissante ni compte à rebours.

Étapes dans Cursor, Windsurf ou VSCodium

  1. Ouvrez la vue Extensions avec Ctrl+Maj+X (Cmd+Maj+X sur macOS).
  2. Cherchez zovo.agent-session-viewer et cliquez sur Install. Cursor, Windsurf et VSCodium installent les extensions depuis Open VSX, où celle-ci s’appelle zovo/agent-session-viewer.
  3. Si votre éditeur n’a pas de galerie, téléchargez le fichier .vsix sur la page Open VSX et lancez « Extensions: Install from VSIX... ».
  4. Ensuite, tout fonctionne comme dans VS Code.

Ce que fait Agent Session Viewer

  • Les sessions Claude Code dans ~/.claude/projects (ou $CLAUDE_CONFIG_DIR/projects) et les sessions Codex dans ~/.codex/sessions (ou $CODEX_HOME/sessions).
  • Les sous-agents des deux outils, imbriqués sous la session qui les a lancés.
  • Un en-tête avec l’outil, le modèle, le dossier du projet, la branche git, la durée, le nombre de tours, les totaux de tokens et le coût quand le fichier l’enregistre (Claude Code l’écrit, Codex non).
  • Les modifications de fichiers en diff (Edit, Write et apply_patch), la réflexion (thinking) et les résumés de raisonnement de Codex, repliés.
  • Les noms des fils Codex lus dans session_index.jsonl, pour que les fils renommés gardent leur nom.

Ce qu’il ne fait pas

  • Elle lit seulement Claude Code et Codex. Les sessions Cursor, Copilot et Gemini CLI ne sont pas encore prises en charge.
  • Elle est en lecture seule. Elle ne modifie, ne déplace et ne supprime jamais les fichiers de session, et n’a pas de commande de suppression.
  • La recherche porte sur du texte simple, pas sur des expressions régulières, et s’arrête à 300 résultats.
  • Resume in Terminal demande que Claude Code ou Codex soit installé et dans le PATH du terminal.
  • Les fichiers sont lus jusqu’à 256 Mo par défaut (agentSessionViewer.maxFileSizeMB). Les fichiers plus gros s’ouvrent avec leur première partie. Le raisonnement Codex stocké chiffré ne peut pas être affiché.

Questions fréquentes

Où Claude Code enregistre-t-il l’historique des conversations ?

Dans ~/.claude/projects, avec un dossier par projet et un fichier .jsonl par session. Si CLAUDE_CONFIG_DIR est défini, l’historique se trouve sous ce dossier.

Est-ce gratuit ?

Oui. La lecture, la recherche, la reprise et l’export d’une session en Markdown sont gratuits, sans limite d’historique. Les trois outils Pro (rapport d’utilisation et de coût, export de partage, export groupé) ont 3 essais gratuits chacun, puis Zovo Pro coûte 19 USD, payés une seule fois pour toutes les extensions Zovo.

Peut-on supprimer d’anciennes sessions depuis la visionneuse ?

Non. Elle lit seulement vos fichiers de session et ne les modifie, ne les déplace et ne les supprime jamais.

Est-elle faite par Anthropic ?

Non. Elle n’est ni faite par Anthropic ou OpenAI, ni affiliée à ces sociétés. Elle ne fait aucun appel réseau et n’a pas de télémétrie.
