Renommer automatiquement les balises HTML, JSX et Vue dans VS Code

Installez l’extension gratuite Auto Rename Tag & Close Tag Sync et changez le nom dans une balise ouvrante ou fermante. La balise correspondante change pendant que vous tapez. Le renommage utilise l’édition liée de VS Code (editor.linkedEditing). L’extension active ce réglage pour ses langages et trouve la balise correspondante en HTML, JSX, TSX, Vue, Svelte, Astro, PHP, Blade, Twig, XML, Markdown et d’autres langages, si bien qu’une seule annulation rétablit les deux balises. Le renommage, la fermeture automatique et le cadre autour de la balise correspondante sont gratuits. Zovo Pro (19 USD, payé une seule fois) ajoute Rename Tag in All Files et Check Unclosed Tags in All Files, avec 3 essais gratuits pour chaque outil.

Étapes dans VS Code

  1. Installez Tag Auto Rename & Close Tag Sync depuis le Marketplace, ou appuyez sur Ctrl+P (Cmd+P sur macOS) et lancez ext install zovo.zovo-auto-rename-tag.
  2. Ouvrez un fichier HTML, JSX, TSX, Vue, Svelte, PHP ou un autre fichier de template et changez le nom d’une balise ouvrante. La balise fermante change pendant la saisie, et inversement.
  3. Tapez > après une balise ouvrante et la balise fermante apparaît après le curseur. Tapez </ et le nom de l’élément ouvert est complété.
  4. Placez le curseur sur une balise et les deux balises sont encadrées dans les couleurs de crochets de votre thème.
  5. Faites un clic droit dans l’éditeur pour « Go to Matching Tag » et « Select Tag Content ». Pour taper un nouveau nom dans une boîte de saisie, lancez « Tag Sync: Rename Tag Pair… » depuis la Command Palette.
  6. Cliquez sur l’élément Tags de la barre d’état pour voir ce qui est actif pour ce fichier, ou pour désactiver l’extension pour un langage. S’il indique « Tags: rename off », cliquez dessus pour activer le renommage pour ce langage.

Ce qui est gratuit et ce qu’ajoute Zovo Pro

Le renommage pendant la saisie, la fermeture automatique sur > et </, le cadre autour de la balise correspondante, Go to Matching Tag, Select Tag Content, Rename Tag Pair… et le menu de la barre d’état sont gratuits. L’extension n’a pas de publicité, ne demande aucune connexion à un compte et fonctionne hors ligne.

Cet outil renomme un composant ou un élément dans tous les fichiers à balises de l’espace de travail en une fois, par exemple <Button> en <UiButton> dans chaque fichier .tsx, .vue, .html et de template. Seuls les noms de balises changent, jamais le texte, les attributs, les chaînes ou les commentaires. Vous voyez d’abord un décompte, « Preview first » ouvre l’aperçu de refactorisation de VS Code, et une seule annulation (Undo) rétablit tous les fichiers.

Utiliser Rename Tag in All Files (Zovo Pro)

  1. Ouvrez le dossier du projet dans VS Code. L’outil a besoin d’un dossier ouvert.
  2. Lancez « Tag Sync: Rename Tag in All Files… (Pro) » depuis la Command Palette, ou faites un clic droit sur un fichier .html, .htm, .vue, .jsx, .tsx ou .svelte dans l’Explorer et choisissez « Zovo Pro: Rename Tag in All Files ».
  3. Tapez la balise à renommer telle qu’elle est écrite dans les fichiers (par exemple Button), puis le nouveau nom.
  4. Choisissez « Rename », ou « Preview first » pour vérifier les modifications dans l’aperçu de refactorisation. Les fichiers qui n’étaient pas ouverts sont modifiés mais pas enregistrés. File > Save All les garde, et Undo les rétablit.

Étapes dans Cursor, Windsurf ou VSCodium

  1. Ouvrez la vue Extensions avec Ctrl+Maj+X (Cmd+Maj+X sur macOS).
  2. Cherchez zovo.zovo-auto-rename-tag et cliquez sur Install. Cursor, Windsurf et VSCodium installent les extensions depuis Open VSX, où celle-ci s’appelle zovo/zovo-auto-rename-tag.
  3. Si votre éditeur n’a pas de galerie, téléchargez le fichier .vsix sur la page Open VSX et lancez « Extensions: Install from VSIX... ».
  4. Ensuite, tout fonctionne comme dans VS Code.

Ce que fait Tag Auto Rename & Close Tag Sync

  • Renommage en HTML, JSX et TSX, Vue, Svelte, Astro, PHP, Blade, Twig, Jinja, Nunjucks, Liquid, ERB, EJS, Handlebars, XML, SVG et Markdown.
  • Les balises vides comme br, img, input, meta et hr ne sont jamais appariées ni fermées.
  • Dans un fichier .tsx, seul le vrai JSX compte comme balise. Les comparaisons comme a < b && c > d et les génériques comme useState<string>() ne sont pas touchés, et les fichiers .ts non plus.
  • Les commentaires, les chaînes, le contenu de <script> et <style> et les blocs {{ }}, {% %}, <?php ?> et <% %> sont ignorés.
  • Les nouveaux fichiers non enregistrés fonctionnent dès qu’ils ont un langage.

Ce qu’il ne fait pas

  • En JSX et TSX, TypeScript ferme lui-même les balises, donc l’extension lui laisse la fermeture. La balise fermante ajoutée par TypeScript est une étape d’annulation à part.
  • Quand l’extension Vue, Svelte, Astro ou Red Hat XML est installée, c’est elle qui ferme les balises dans son langage, et celle-ci n’intervient pas.
  • Les fichiers de plus de 1 Mo ou de 50 000 lignes n’ont ni renommage en direct, ni fermeture, ni mise en évidence (réglages zovoTags.maxFileSizeKB et zovoTags.maxFileLines). La barre d’état le signale, et les commandes fonctionnent toujours.
  • Les balises écrites dans des expressions {...} de Svelte ou d’Astro ne sont pas renommées.
  • Si l’ancienne extension Auto Rename Tag ou Auto Close Tag est aussi active, les deux peuvent modifier la même balise. Gardez-en une seule.

Questions fréquentes

Quelle différence avec le réglage editor.linkedEditing ?

L’extension utilise editor.linkedEditing pour le renommage. Elle active ce réglage pour chaque langage qu’elle prend en charge et trouve la balise correspondante dans chacun, du HTML et de Vue à PHP, Twig, XML et JSX. Elle ferme aussi les balises, encadre la balise correspondante et ajoute Go to Matching Tag et Select Tag Content. Si vous avez désactivé editor.linkedEditing vous-même, la barre d’état affiche « Tags: rename off », et un clic le réactive pour ce langage.

L’annulation fonctionne-t-elle toujours ?

Oui. Votre modification et le changement de la balise correspondante forment une seule étape d’annulation, car le renommage passe par l’édition liée de VS Code. Une balise fermante ajoutée par la fermeture automatique rejoint l’étape d’annulation du > que vous avez tapé, sauf en JSX et TSX, où c’est TypeScript qui ferme les balises.

Est-ce gratuit ?

Oui. Le renommage, la fermeture automatique, le cadre autour de la balise correspondante et les commandes de l’éditeur sont gratuits. Rename Tag in All Files et Check Unclosed Tags in All Files sont des outils Zovo Pro avec 3 essais gratuits chacun, puis 19 USD payés une seule fois pour toutes les extensions Zovo.

Est-ce que ça marche dans Cursor ?

Oui. Cursor, Windsurf et VSCodium l’installent depuis Open VSX sous le nom zovo/zovo-auto-rename-tag.
