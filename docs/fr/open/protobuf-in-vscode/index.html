Modifier des fichiers .proto dans VS Code avec coloration, formatage et accès à la définition

Installez l’extension gratuite Protobuf & Proto3 Formatter et ouvrez un dossier qui contient des fichiers .proto. Elle ajoute la coloration syntaxique, un formateur qui garde chaque commentaire, l’accès à la définition, la recherche des références et des erreurs avec la formulation de protoc, pour proto2, proto3 et les éditions 2023 et 2024. Elle fonctionne hors ligne avec son propre parseur, donc sans protoc, sans serveur de langage et sans configuration, et tout cela est gratuit. Zovo Pro (19 USD, payés une seule fois) ajoute trois outils, Check Breaking Changes Against Git, Generate API Docs et Decode a Binary Message, avec 3 essais gratuits pour chacun.

Étapes dans VS Code

  1. Installez Protobuf & Proto3 Formatter depuis le Marketplace, ou appuyez sur Ctrl+P (Cmd+P sur macOS) et lancez ext install zovo.zovo-protobuf.
  2. Ouvrez un dossier qui contient des fichiers .proto. La coloration, le plan (outline) et le fil d’Ariane (breadcrumbs) apparaissent tout de suite.
  3. Appuyez sur Shift+Alt+F (Shift+Option+F sur macOS) pour formater, ou activez editor.formatOnSave. Vous obtenez une instruction par ligne, l’indentation de votre éditeur et une seule espace autour de =. Les commentaires, les groupes de lignes vides et vos retours à la ligne dans les longues instructions restent à leur place.
  4. Appuyez sur F12 sur un type ou un import pour aller à sa définition, et sur Shift+F12 pour lister ses utilisations. Ctrl+clic ou Cmd+clic sur un import ouvre le fichier. Survolez un type pour voir ses champs et son commentaire.
  5. Les erreurs s’affichent dans le panneau Problems avec la formulation de protoc : numéros de champ en double (avec le prochain numéro libre), types inconnus, types utilisés sans leur import, numéros et noms réservés, et les règles de proto3 et des éditions. Les imports inutilisés sont estompés.
  6. Si vos imports partent d’un dossier comme proto/ ou third_party/, ils sont trouvés en remontant depuis chaque fichier. Pour d’autres racines, ajoutez-les au réglage zovoProto.importPaths, comme vous le feriez avec protoc -I.

Ce qui est gratuit et ce qu’ajoute Zovo Pro

La coloration (aussi pour les blocs de code proto dans le Markdown), Format Document, l’accès à la définition, la recherche des références, les erreurs au format protoc, le plan, Go to Symbol in workspace, le survol et la complétion, y compris le prochain numéro de champ libre après =, sont gratuits. Il n’y a ni connexion à un compte, ni requête réseau, ni télémétrie.

Avant de fusionner une modification d’un fichier .proto, Check Breaking Changes Against Git compare vos fichiers avec main (ou la branche que vous avez choisie) et liste les champs supprimés, les numéros, types et labels modifiés, les champs et valeurs d’enum renommés, et les méthodes supprimées ou modifiées. Chaque constat indique s’il casse les données binaires, le JSON ou seulement le code généré. Vous voyez ainsi ce que les anciens clients liront mal avant qu’ils ne le fassent. Vous pouvez enregistrer les constats dans un fichier JSON pour la CI.

Utiliser Check Breaking Changes Against Git (Zovo Pro)

  1. Faites un clic droit sur un fichier .proto ou un dossier dans l’Explorer et choisissez « Zovo Pro: Check breaking changes against git », faites un clic droit dans un éditeur .proto et choisissez « Check Breaking Changes Against Git (Pro) », ou lancez « Protobuf: Check Breaking Changes Against Git (Pro) » depuis la Command Palette. Le dossier doit être dans un dépôt git, et git doit être installé.
  2. La vérification compare tous les fichiers .proto du dépôt dans votre copie de travail, modifications non enregistrées comprises, avec la merge base de origin/main, main, origin/master ou master (la première qui existe), ou de la branche indiquée dans le réglage zovoProto.baseBranch. Un rapport Markdown s’ouvre avec les constats regroupés par fichier.
  3. Cliquez sur « Save JSON for CI » dans le message pour garder les constats dans proto-breaking.json.
  4. Un essai ne compte que si le rapport s’est ouvert. Un dossier hors de git ou une branche de base introuvable n’en consomme aucun.

Check Breaking Changes Against Git fonctionne 3 fois sur votre ordinateur avant de demander une licence. Il n’y a ni fenêtre surgissante ni compte à rebours.

Étapes dans Cursor, Windsurf ou VSCodium

  1. Ouvrez la vue Extensions avec Ctrl+Maj+X (Cmd+Maj+X sur macOS).
  2. Cherchez zovo.zovo-protobuf et cliquez sur Install. Cursor, Windsurf et VSCodium installent les extensions depuis Open VSX, où celle-ci s’appelle zovo/zovo-protobuf.
  3. Si votre éditeur n’a pas de galerie, téléchargez le fichier .vsix sur la page Open VSX et lancez « Extensions: Install from VSIX... ».
  4. Ensuite, tout fonctionne comme dans VS Code.

Ce que fait Protobuf & Proto3 Formatter

  • proto2, proto3 et les éditions (2023, 2024), ainsi que les blocs de code proto dans le Markdown.
  • Les règles de portée de protobuf pour l’accès à la définition et la recherche des références à travers les imports : types imbriqués, packages et . initial.
  • Les noms intégrés des types well-known comme google/protobuf/timestamp.proto.
  • Pas de fausses erreurs en rouge : quand un import n’est pas dans votre espace de travail, la ligne d’import le signale et les types qu’il apporterait ne sont pas devinés.
  • La complétion des types, mots-clés, options, chemins d’import et du prochain numéro de champ libre après =.

Ce qu’il ne fait pas

  • Les noms d’options personnalisées sont vérifiés pour leur import, mais pas par rapport au type de champ de l’extension.
  • Les vérifications des features des éditions couvrent enum_type, les labels, packed et les groupes. Les autres règles de features sont laissées à protoc.
  • Le formateur garde vos retours à la ligne dans les longues instructions. Il ne coupe pas les lignes longues et n’aligne pas les = en colonnes.
  • Le formatage demande un fichier qui se parse. Corrigez d’abord l’erreur affichée dans le panneau Problems.
  • Les imports entre fichiers demandent des dossiers sur le disque. Dans un espace de travail virtuel, seuls la coloration, le formatage et le plan fonctionnent.

Questions fréquentes

Est-ce gratuit ?

La coloration, le formatage, l’accès à la définition, la recherche des références, les erreurs au format protoc, le survol et la complétion sont gratuits. Les trois outils Pro, Check Breaking Changes Against Git, Generate API Docs et Decode a Binary Message, ont 3 essais gratuits chacun. Ensuite, ils demandent Zovo Pro, 19 USD une seule fois pour toutes les extensions Zovo.

Faut-il installer protoc ?

Non. L’extension a son propre parseur et fonctionne hors ligne. Les erreurs reprennent la formulation de protoc.

Pourquoi un import affiche-t-il une note au lieu d’erreurs en rouge ?

Le fichier importé n’est pas dans votre espace de travail. Ajoutez son dossier racine à zovoProto.importPaths, comme avec protoc -I.

L’extension fonctionne-t-elle dans Cursor ?

Oui. Cursor, Windsurf et VSCodium l’installent depuis Open VSX, où elle est publiée sous le nom zovo/zovo-protobuf.
