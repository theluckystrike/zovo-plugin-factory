Voir l’image derrière un chemin dans votre code, dans la gouttière et au survol

Installez l’extension gratuite Image Preview & Image Hover et ouvrez un fichier qui nomme une image. Une miniature s’affiche dans la gouttière à côté de la ligne, et le survol du chemin montre l’image, son type, ses dimensions en pixels et son poids. L’extension fonctionne avec les imports JavaScript et TypeScript, le JSX, url() en CSS, le Markdown, src et srcset en HTML, le YAML et les data URIs, sans aucune requête réseau. Zovo Pro (19 USD, payés une seule fois) ajoute trois outils, Find Unused Images, Find Broken Image References et l’Image Weight Report, avec 3 essais gratuits pour chacun.

Étapes dans VS Code

  1. Installez Image Preview & Image Hover depuis le Marketplace, ou appuyez sur Ctrl+P (Cmd+P sur macOS) et lancez ext install zovo.zovo-image-preview.
  2. Ouvrez un fichier qui nomme une image, par exemple import logo from './logo.png', un url() en CSS ou un <img src> en HTML. Les miniatures s’affichent dans la gouttière, une par ligne.
  3. Survolez le chemin. Le survol montre l’image (réduite pour tenir, jamais agrandie), son type, sa largeur × hauteur en pixels, son poids et sa transparence, avec des liens pour ouvrir le fichier ou l’afficher dans l’Explorer.
  4. Si un chemin ne se résout pas, le survol l’indique et liste les chemins essayés. Ajoutez vos propres préfixes dans imgPreview.aliases, par exemple { "@images": "src/assets/images" }, ou des dossiers pour les chemins qui commencent par / dans imgPreview.publicFolders.
  5. Pour masquer les miniatures de la gouttière, lancez « Image Preview: Show or Hide Gutter Thumbnails » depuis la Command Palette.
  6. Pas de projet sous la main ? Lancez « Image Preview: Open the Sample Files » pour ouvrir un petit projet de démonstration avec chaque type de chemin.

Ce qui est gratuit et ce qu’ajoute Zovo Pro

Les miniatures dans la gouttière, le survol, la résolution des chemins avec les alias, les paths de tsconfig.json et jsconfig.json et les paquets de monorepo, ainsi que les data URIs sont gratuits. Il n’y a ni compte, ni requête réseau, ni télémétrie, et tout fonctionne hors ligne.

Find Unused Images liste les images du workspace (ou d’un dossier) qu’aucun fichier de code, de style, Markdown, HTML, JSON ou YAML ne nomme, des plus lourdes aux plus légères, dans un rapport Markdown avec leur poids. Après confirmation, elles sont déplacées dans un dossier _unused-images en gardant leur arborescence, et Edit > Undo les remet en place. Vous débarrassez un projet de ses anciennes images sans vérifier chaque nom à la main.

Utiliser Find Unused Images (Zovo Pro)

  1. Faites un clic droit sur un dossier dans l’Explorer et choisissez « Zovo Pro: Find unused images », ou lancez « Image Preview: Find Unused Images (Pro) » depuis la Command Palette. Avec plusieurs dossiers dans le workspace, choisissez le dossier.
  2. Une notification affiche la progression avec un bouton Cancel. Un rapport Markdown s’ouvre ensuite avec chaque image inutilisée et son poids, des plus lourdes aux plus légères.
  3. Cliquez sur « Move N to _unused-images » pour les déplacer, ou fermez le message pour les laisser où elles sont. Edit > Undo les remet en place.
  4. Un essai ne compte que si le rapport s’est ouvert. Escape n’en consomme jamais.

Étapes dans Cursor, Windsurf ou VSCodium

  1. Ouvrez la vue Extensions avec Ctrl+Maj+X (Cmd+Maj+X sur macOS).
  2. Cherchez zovo.zovo-image-preview et cliquez sur Install. Cursor, Windsurf et VSCodium installent les extensions depuis Open VSX, où celle-ci s’appelle zovo/zovo-image-preview.
  3. Si votre éditeur n’a pas de galerie, téléchargez le fichier .vsix sur la page Open VSX et lancez « Extensions: Install from VSIX... ».
  4. Ensuite, tout fonctionne comme dans VS Code.

Ce que fait Image Preview & Image Hover

  • Des miniatures dans la gouttière pour les fichiers PNG, JPEG, GIF, WebP, AVIF, SVG, BMP et ICO, et pour les URIs data:image/.... Pour les fichiers TIFF et HEIC, le type et les dimensions sont lus dans l’en-tête.
  • Les chemins relatifs au fichier, /logo.png depuis public/, static/ et d’autres dossiers racine web, @/ pour src/, ~ pour node_modules ou votre dossier personnel, et les paths de tsconfig.json ou jsconfig.json avec extends.
  • Les noms de fichier avec des espaces, %20, ?v=2 ou #id. Un simple nom comme beans.jpg dans du JSON est associé à l’image la plus proche qui porte ce nom.
  • Les monorepos, avec le dossier public/ et le tsconfig.json propres à chaque paquet.
  • Une URL distante, qui s’affiche comme un lien et n’est jamais téléchargée.

Ce qu’il ne fait pas

  • Les chemins construits à l’exécution, comme `icons/${name}.svg` ou une concaténation de chaînes, ne peuvent pas être prévisualisés, et ils peuvent faire passer une image pour inutilisée. Vérifiez la liste des images inutilisées avant de déplacer des fichiers.
  • Une seule miniature par ligne, celle de la première image de la ligne. Le survol fonctionne pour chaque chemin de la ligne.
  • Les workspaces distants et virtuels (SSH, WSL, Codespaces, vscode.dev) ne sont pas pris en charge dans cette version.
  • Les alias Webpack, Vite ou Next.js définis seulement dans un fichier de configuration JavaScript ne sont pas lus. Ajoutez-les à imgPreview.aliases ou aux paths de tsconfig.json.
  • Les images de plus de 20 Mo sont mesurées mais pas dessinées (réglage imgPreview.maxFileSizeMB). L’Image Weight Report signale les fichiers lourds mais ne les compresse pas.

Questions fréquentes

Est-ce gratuit ?

Les miniatures dans la gouttière, le survol et la résolution des chemins sont gratuits. Les trois outils Pro, Find Unused Images, Find Broken Image References et l’Image Weight Report, ont 3 essais gratuits chacun. Ensuite, ils demandent Zovo Pro, 19 USD une seule fois pour toutes les extensions Zovo.

Pourquoi mon chemin avec @/ ou un alias n’affiche-t-il aucune image ?

L’alias existe peut-être seulement dans un fichier de configuration Webpack, Vite ou Next.js, qui n’est pas lu. Ajoutez-le à imgPreview.aliases ou aux paths de tsconfig.json.

L’extension fonctionne-t-elle avec Remote SSH ou WSL ?

Pas dans cette version. L’image du survol est lue sur le disque local.

L’extension fonctionne-t-elle dans Cursor ?

Oui. Cursor, Windsurf et VSCodium l’installent depuis Open VSX, où elle est publiée sous le nom zovo/zovo-image-preview.
