Convert a .env file to a Kubernetes Secret in VS Code

A Kubernetes Secret needs every value base64 encoded under data, which is slow and easy to get wrong by hand. Dotenv & .env File Editor converts a .env file into a Secret manifest in one step, and also into a ConfigMap, JSON, YAML, a Docker Compose environment block, a GitHub Actions env block or shell exports. The result opens in a new tab and your .env file is not changed. The converter is a Zovo Pro tool (USD 19 once) with 3 free tries.

Steps in VS Code

  1. Install Dotenv & .env File Editor from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-dotenv.
  2. Right-click the .env file in the Explorer and pick "Zovo Pro: Convert .env to JSON, YAML, Kubernetes", or open it and run "Dotenv: Convert .env to JSON, YAML, Kubernetes (Pro)..." from the Command Palette.
  3. Pick "Kubernetes Secret (base64 data)". For values that are not secret, pick "Kubernetes ConfigMap".
  4. The manifest opens in a new tab beside the file. It is a Secret of type Opaque with one line per key under data, each value base64 encoded.
  5. Check the name. It is the folder name plus -env, for example api-env. Add a namespace if you need one.
  6. Save the tab as a .yaml file and apply it with kubectl apply. Base64 is an encoding, not encryption, so keep the file out of git.

What Dotenv & .env File Editor handles

  • Kubernetes Secret with base64 data, and Kubernetes ConfigMap.
  • JSON object, plain YAML and a Docker Compose service environment block.
  • GitHub Actions env block, with secret-looking keys written as ${{ secrets.NAME }}.
  • Shell export lines, with values quoted where needed.
  • Quoted, multi-line and exported values in the .env file.

What it does not do

  • The Kubernetes name is made from the folder name, and no namespace is set. Change both in the tab if you need to.
  • When a key is set twice, the last value is used.
  • The Docker Compose output puts the keys under a service named app. Rename it to match your file.
  • ${NAME} references in values are written as they are, not filled in.
  • The result is an unsaved tab. Save it yourself, and keep Secret files out of git.

Other options

  • kubectl create secret. kubectl can build a Secret from a .env file with its from-env-file option. Free, needs kubectl.
  • Kustomize secretGenerator. A secretGenerator with an envs entry turns a .env file into a Secret when you build. Free, part of kubectl.

Questions

Is a Kubernetes Secret encrypted?

No. The values are base64 encoded, and anyone can decode them. Keep the file out of git, or use a tool made for secrets in git, such as Sealed Secrets.

Does it change my .env file?

No. It reads the file and opens the result in a new, unsaved tab.

Can I get a ConfigMap instead?

Yes. Pick "Kubernetes ConfigMap". The values are written as plain YAML strings, not base64.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
