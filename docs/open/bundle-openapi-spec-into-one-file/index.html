Bundle a split OpenAPI spec into one file

Swagger Editor & OpenAPI Editing bundles a spec that is split over many files into one file in VS Code. Run "OpenAPI: Bundle $refs into one file" on the root file. Every $ref to another file is copied in, schemas go to components/schemas under their own name (Pet, not a file path), and a diff shows the result before anything is saved. Bundle, $ref completion, go to definition and rename across files are free, and Zovo Pro (USD 19 once) adds a breaking-change report, a mock server and client code, with 3 free tries each.

Steps in VS Code

  1. Install Swagger Viewer & OpenAPI Viewer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.swagger-openapi-viewer.
  2. Open the root file of the spec, the YAML or JSON file with openapi: or swagger: at the top. Lint runs at once, and a $ref that points nowhere shows in the Problems panel as invalid-ref.
  3. Fix broken refs first. $ref completion lists the files of your workspace and the components inside them, F12 opens the target of a ref, and F2 on a schema renames it with every $ref to it, across files.
  4. Right-click in the root file, open the OpenAPI menu and pick "Bundle $refs into one file". You can also run "OpenAPI: Bundle $refs into one file" from the Command Palette.
  5. A diff opens with the root file on the left and the bundled spec on the right. Nothing is written yet.
  6. Click "Save as name.bundled.yaml" (or .json). The new file is saved next to the root file, in the same format, and the split files stay as they are.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.swagger-openapi-viewer and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/swagger-openapi-viewer.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What Swagger Viewer & OpenAPI Viewer handles

  • Refs to other files and to parts of them, such as schemas/pet.yaml or common.yaml#/components/schemas/Error. A target used many times is copied once, and loops stay loops.
  • Schema names come from the ref or the file name (pet.yaml becomes Pet). When two names clash, the second one gets _2.
  • OpenAPI 3.1, 3.0 and Swagger 2.0. In Swagger 2.0 the schemas go to definitions.
  • YAML and JSON. The bundled file uses the format of the root file.

What it does not do

  • If any $ref cannot be loaded, no bundle is made. The message lists the first five refs with the reason, so you can fix them.
  • Refs outside the workspace, absolute paths, file: URLs and remote http or https refs are not bundled. Use relative paths inside the workspace.
  • Bundle has Save as only. It never replaces the root file.
  • With a git ref, the breaking-change report reads only the root file from git. The files it refers to are read as they are now.
  • Lint covers common mistakes with the Spectral rule names. It is not a full JSON Schema validation of the spec.

Questions

Does the preview work without a bundle?

Yes. The preview reads relative $ref files from your workspace and updates when you save any file the spec refers to. Bundle when a tool or a teammate needs one file.

Will my schema names stay readable?

Yes. A schema from another file keeps the name from the ref, such as Pet, not a file path, and goes under components/schemas, so it shows in the model list of the preview.

Does bundling change my split files?

No. Bundle writes a new file next to the root file after you click Save as. The root file and the files it refers to stay as they are.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
