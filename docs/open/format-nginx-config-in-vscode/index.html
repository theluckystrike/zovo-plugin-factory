Format and check an nginx config file in VS Code

Nginx Config Formatter & Lint formats nginx config files in VS Code and never breaks a valid file: it parses its own result and changes nothing if the file would not read the same. It marks a missing ;, unclosed braces, listen in a location, duplicate root or listen and other problems as you type, shows syntax and defaults for about 300 directives on hover, and gives an overview of your servers and locations across include files. All of that is free and runs on your computer. Zovo Pro (USD 19 once) adds a security audit, a location tester and a .htaccess converter, with 3 free tries each.

Steps in VS Code

  1. Install Nginx Config Formatter & Lint from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-nginx-config.
  2. Open the config file. It opens as nginx when it is named nginx.conf or *.nginx, or sits in a folder whose name contains nginx, such as /etc/nginx/sites-enabled/site. For any other file, pick "nginx" as the language mode.
  3. Press Shift+Alt+F (Shift+Option+F on macOS). You get one statement per line with your editor's indentation, and long log_format values keep their line breaks.
  4. Problems show as you type. Press Ctrl+. (Cmd+. on macOS) on one for a quick fix, such as adding the missing ; or fixing proxy_set_heder to proxy_set_header.
  5. Hover a directive for its syntax, default value, allowed blocks and a link to the nginx documentation. Completion offers the directives allowed in the current block, and variables after $.
  6. Run "Nginx: Show Config Overview" to see every server with its ports and names and every location with what it does, across include files, with links to each line.

What Nginx Config Formatter & Lint handles

  • Directives of OpenResty/Lua, headers-more, Brotli, Passenger and other common modules are known and never marked.
  • Lua blocks such as content_by_lua_block are coloured as Lua.
  • Outline of servers with their names and ports, locations, upstreams and maps.
  • Relative includes read from nginxConfig.prefix, the file's folder, its parent folder or /etc/nginx, in that order.

What it does not do

  • The formatter puts one space between a directive and its values, so column alignment such as listen 80; is not kept.
  • The checks read your files and do not run nginx -t. A missing certificate file or a module that is not loaded is only found by nginx itself.
  • Location regexes are tested with JavaScript regular expressions. A few PCRE-only features cannot be tested and are reported as skipped.

Questions

Can VS Code format nginx.conf without an extension?

No. VS Code opens nginx.conf as plain text, with no colours, no formatter and no checks.

Can formatting break my config?

No. The formatter parses its own result and changes nothing if the file would not read the same, so a valid config stays valid.

Does it replace nginx -t?

No. It reads your files and checks the syntax and placement of directives. Run nginx -t on the server for certificates and modules.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
