Decode a binary protobuf message in VS Code

A protobuf message on disk is only bytes: field numbers and wire types, with no names. To read it you normally run protoc in its decode mode or write a small program. Protobuf & Proto3 Formatter has a decoder in VS Code. Right-click a .pb or .bin file, or paste the bytes as hex or base64, pick the message type from your .proto files, and the message opens as JSON with field names, enums, maps and nested messages. The decoder is a Zovo Pro tool (USD 19 once) with 3 free tries. Highlighting, formatting and protoc-style errors for .proto files are free.

Steps in VS Code

  1. Install Protobuf & Proto3 Formatter from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-protobuf.
  2. Open the folder that has your .proto files. The extension reads every .proto file in the workspace, so their message types are ready for the decoder.
  3. Right-click the binary file in the Explorer and pick "Zovo Pro: Decode with a .proto schema". It is there for .bin, .pb, .binpb, .protobuf, .msg and .dat files.
  4. For bytes you copied from a log or a network tool, select them in any editor (or nothing) and run "Decode a Binary Message (Pro)" from the Command Palette. Paste hex such as 0a 03 66 6f 6f or base64 when it asks.
  5. Pick the message type. Type to search by name or package. If you have no schema, pick "No schema" to see field numbers and best guesses for the values.
  6. The result opens in a new JSON tab. A first comment line says which type was used. A captured gRPC message works too, because the 5-byte gRPC frame header is removed for you.

What Protobuf & Proto3 Formatter handles

  • Field names, enums, maps, nested messages and packed repeated fields, from your own .proto schema.
  • Bytes from a file, or pasted as hex or base64.
  • gRPC messages with their 5-byte frame header.
  • Messages with no schema, shown with field numbers.

What it does not do

  • A compressed gRPC message is not unpacked. Only an uncompressed frame header is removed.
  • 64-bit integers larger than 2^53 are shown as strings, and bytes fields as base64. Fields the schema does not list show as "#N" keys with their field number.
  • Messages nested more than 64 levels deep are not decoded.
  • The decoder reads one message. It does not split a file that holds many length-delimited messages.

Other options

  • protoc. The protobuf compiler has a decode mode that reads a message from standard input and prints it as text. Free. You need the schema and the exact type name on the command line.
  • protoscope. A free tool from the protobuf team that prints any protobuf bytes as readable text without a schema.
  • A script with the generated classes. Parse the bytes with the classes protoc generates for your language and print them. Free, but you write and run code each time.

Questions

Can I decode a message without the .proto file?

Yes. Pick "No schema". You see field numbers and best guesses for the values, without names. With the schema in the workspace you get field names and enum names.

Does it decode gRPC messages?

Yes, when the message is not compressed. The 5-byte gRPC frame header is removed for you and the comment line in the result says so.

Is the decoder free?

It is a Zovo Pro tool with 3 free tries on your computer. A try counts only when a message was decoded. Zovo Pro is USD 19 once and turns on the Pro tools in every Zovo extension.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
