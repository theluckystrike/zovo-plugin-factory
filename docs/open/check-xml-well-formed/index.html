Check an XML file for well-formedness errors in VS Code

VS Code colours XML but does not check it, so an unclosed tag or a stray & in a config file often shows up only when a build or a server fails to read it. XML Formatter & XPath Tools checks every file VS Code opens as XML while you type and lists each well-formedness error in the Problems panel with its line and column. A file that is not well formed is never changed by Format. The checks are free, and Zovo Pro (USD 19 once) adds a report for a whole folder of XML files, with 3 free tries.

Steps in VS Code

  1. Install XML Formatter & XPath Tools from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-xml-xpath-tools.
  2. Open the XML file. Errors show in the Problems panel (Ctrl+Shift+M, Cmd+Shift+M on a Mac) with the line and column, and so do undeclared namespace prefixes and entity warnings.
  3. Click a problem to jump to the place in the file.
  4. The XML Tree view in the Explorer also says "Not well formed at line ..., column ..." and shows the part of the file before the error.
  5. If you press Shift+Alt+F on a broken file, nothing changes. A message says why, and its Go to error button takes you there.
  6. Fix the spot. The check runs again shortly after you stop typing, and the problem goes away when the file is well formed.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-xml-xpath-tools and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-xml-xpath-tools.

  4. Then use it the same way as in VS Code.

What XML Formatter & XPath Tools handles

  • Files VS Code opens as XML, such as .xml, .xsd, .xsl, .svg, .xaml, .kml, .gpx, .wsdl, .resx and .xliff.
  • Unclosed and mismatched tags, bad characters such as a lone &, broken attributes and undeclared namespace prefixes.
  • Entity bombs and external entities, which are measured or ignored, never expanded or read.

What it does not do

  • It checks that a file is well formed. It does not validate against an XSD or a DTD.
  • The check, the tree and XPath work on files up to 60 MB (the xmlXpathTools.maxFileMB setting).
  • VS Code does not pass files over 50 MB to extensions, so those files get no check in the editor.

Other options

  • xmllint (libxml2). A free command line tool that reports well-formedness errors and can also validate against a schema. Good in a build script.
  • XML by Red Hat. A VS Code extension that checks XML as you type and validates against an XSD or a DTD.

Questions

Does it validate my file against an XSD?

No. It checks that the file is well formed. Use a schema validator such as xmllint or the XML extension by Red Hat for XSD or DTD validation.

Can a broken file be damaged by Format?

No. Format and Minify change nothing in a file that is not well formed. You get the error with its line and column instead.

Is the file sent anywhere?

No. The extension has no network code and works offline.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
