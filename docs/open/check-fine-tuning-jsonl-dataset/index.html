Open files in VS Code and Cursor / Machine learning files

Check a fine-tuning JSONL dataset before training

A fine-tuning job rejects or wastes examples that are not valid JSON, have no assistant answer or are too long, and in a text editor each example is one long line. JSONL Viewer opens the .jsonl file in VS Code as a table and as a chat, so you read every example as system, user, assistant and tool messages, and it marks lines that are not valid JSON in red. Its Check Fine-Tuning Dataset tool checks every line the way a fine-tuning job reads it and writes a report with a link to each line with a problem. The viewer is free, and the check is part of Zovo Pro (USD 19 once), with 3 free tries on your computer.

Steps in VS Code

  1. Install JSONL Viewer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-jsonl-viewer.
  2. Click the .jsonl file in the Explorer. It opens in JSONL Viewer as a table, one row per line. .ndjson, .jsonlines and .jsonl.gz files open the same way.
  3. Click Chat at the top right. Records with messages (OpenAI), conversations (ShareGPT), contents (Gemini), role and content, or prompt and completion show as chat bubbles. Tool calls, tool results and thinking blocks get their own boxes. Prev and Next move between records.
  4. Look at the status bar. It says All lines are valid JSON, or shows how many bad lines there are. Click that count to see only the bad lines, or click Next bad line to step through them.
  5. Click Table, type a filter such as messages missing in the Filter box and press Enter to list the lines that have no messages key.
  6. Click Open line in editor to fix a record in the text editor beside the viewer.

Where Zovo Pro saves time

Opening the file, the Table, Record and Chat views, the bad line marks, Find, filters, sort, export of the records in view and live tail are free. The viewer makes no network calls and has no telemetry, so the training data stays on your computer.

Reading examples one by one does not work for thousands of lines. Check Fine-Tuning Dataset reads every line once and reports lines that are not JSON, unknown roles, empty or missing content, examples with no assistant answer or that end on a user turn, a system message that is not first, exact duplicates, mixed formats and examples over the token limit. The other Pro tool, Split JSONL File, writes train and validation files with a fixed seed, or parts of N lines.

With Check Fine-Tuning Dataset (Zovo Pro)

  1. Right-click the .jsonl file in the Explorer and pick "Zovo Pro: Check Fine-Tuning Dataset", or run "JSONL Viewer: Check Fine-Tuning Dataset (Pro)..." from the Command Palette.
  2. Read the report that opens next to the file. It gives the number of examples, the estimated tokens and the messages per example, then each kind of problem with a link to each line.
  3. To change the token limit, set jsonlViewer.datasetTokenLimit (65,536 by default) to the limit of your model. A try counts only when the report opens, so Escape or an error uses nothing.

Check Fine-Tuning Dataset works 3 times on your computer before it asks for a license, and a try counts only when you get a result. Opening a file shows no popup and no countdown.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-jsonl-viewer and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-jsonl-viewer.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What JSONL Viewer handles

  • Chat lines with messages, with system, developer, user, assistant and tool roles, tool calls and weight.
  • Prompt and completion lines.
  • ShareGPT conversations and Gemini contents records in Chat view.
  • .jsonl, .ndjson, .jsonlines and gzipped .jsonl.gz files.

What it does not do

  • Token counts are estimates (about 4 characters per token). They are good for budgets and limits, not for exact billing.
  • The Pro tools work on files on disk, not on files in virtual workspaces.
  • Lines over 5 MB show as truncated in the table and the record view.
  • Files must be under 4 GB, and .jsonl.gz files are unpacked in memory up to 512 MB.

Other options

  • OpenAI cookbook data preparation notebook. A Python notebook that checks the format of a chat dataset and counts tokens. Needs Python and tiktoken.
  • jq. A command line JSON tool. A select query finds records with a missing key, one question at a time.

Questions

Does it upload my dataset?

No. JSONL Viewer and its Pro tools make no network calls. The report is made on your computer.

Which chat formats does Chat view read?

OpenAI messages, ShareGPT conversations, Gemini contents, role and content lines, and prompt and completion pairs.

Does the check change my file?

No. The file is only read. Split JSONL File writes new files and never overwrites an existing one.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
