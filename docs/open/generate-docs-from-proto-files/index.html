Generate API documentation from .proto files

protoc-gen-doc and similar plugins need protoc and a command line. Protobuf & Proto3 Formatter writes the docs from VS Code with its own parser, as one Markdown file that reads well on GitHub or as one self-contained HTML page with a contents sidebar. Each service, method, message, field and enum is listed with the comment written above it, and a method with a google.api.http option shows its HTTP route. Generate API Docs is a Zovo Pro tool (USD 19 once) with 3 free tries.

Steps in VS Code

  1. Install Protobuf & Proto3 Formatter from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-protobuf.
  2. Open the folder with your .proto files. The extension indexes them on its own.
  3. Right-click a folder or a .proto file in the Explorer and pick "Zovo Pro: Generate API docs". A folder gives one document for every .proto file under it. "Protobuf: Generate API Docs (Pro)" in the Command Palette covers the whole workspace.
  4. Pick Markdown (one .md file, readable on GitHub) or HTML (one self-contained page with a contents sidebar, light and dark).
  5. Choose where to save. The default name is API.md or api.html. A Markdown file opens in the editor, and for HTML you can pick Open in Browser.

Where Zovo Pro saves time

Highlighting, a formatter that keeps every comment, go to definition and find references across imports, hovers, completion with the next free field number, and protoc-style errors such as a field number used twice are free. They work offline, with no protoc and no sign-in.

Keeping a hand-written API page in step with the schema is slow, and protoc plugins need a toolchain. Generate API Docs builds the page from the schema in one step, with links between the types, so you can run it again after each change. The other Pro tools check your .proto files for breaking changes against git and decode binary protobuf messages to JSON.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-protobuf and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-protobuf.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What Protobuf & Proto3 Formatter handles

  • Services with their methods, request and response types, streaming, and the HTTP route from google.api.http.
  • Messages with each field name, number, type and label, oneof membership and the field comment.
  • Enums with every value, its number and its comment.
  • Deprecated messages, fields and methods, marked as deprecated.
  • proto2, proto3 and editions files.

What it does not do

  • Comments are taken from the line above an element, and for fields and enum values also from the end of their line.
  • Only the files you pick are documented. A type from an import outside them is shown by name, without a link.
  • The output is one file. It is not split into pages per package.
  • HTTP routes are read from the get, put, post, delete or patch entry of google.api.http. Custom verbs and extra bindings are not listed.

Other options

Questions

Do I need protoc?

No. The extension parses the .proto files itself, offline.

Can I document only one package?

Yes. Right-click the folder of that package, or a single .proto file, and the docs cover only those files.

Does the HTML page load anything from the internet?

No. It is one self-contained file with no scripts and no external files.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
