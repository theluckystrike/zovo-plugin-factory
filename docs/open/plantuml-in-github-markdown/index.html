Show the PlantUML diagrams of a Markdown file on GitHub

GitHub draws mermaid blocks in Markdown but not plantuml blocks, so a README shows the code instead of the diagram. The fix is an image file per diagram and a link to it. PlantUML Viewer & Preview draws the blocks in VS Code with the bundled PlantUML jar and your Java, and you can save each one as SVG or PNG for free. Its Markdown Diagrams to Images tool, part of Zovo Pro (USD 19 once) with 3 free tries, renders every block of a file or a folder and adds the image links for you.

Steps in VS Code

  1. Install PlantUML Viewer & Preview from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-plantuml-viewer.
  2. Make sure Java 11 or newer is installed. The preview says so when it is missing.
  3. Open the Markdown file and click the preview button in the editor title, or run "PlantUML: Open Preview to the Side". Every block shows as a diagram, and errors link to their line.
  4. For a few diagrams, click SVG or PNG above each one and save it next to the Markdown file, for example in an images folder.
  5. Under each block, add an image link such as ![Components](images/components.svg). GitHub shows the image and the code stays in the file.
  6. Commit the image files with the Markdown file.

Where Zovo Pro saves time

The live preview of PlantUML files and Markdown blocks, zoom, error links, saving one diagram as SVG or PNG and Copy SVG are free. Diagrams are drawn on your computer, so nothing is sent to a PlantUML server.

With many diagrams, saving and linking each one by hand is slow, and the links go stale. Markdown Diagrams to Images renders every plantuml block of one Markdown file or a whole folder to SVG or PNG and adds an image link under each block. Or it replaces each block with its image and keeps the code folded in a "PlantUML source" section under it. Running it again updates the same links. The other Pro tools export all diagrams in a folder and compare a diagram with a git version.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-plantuml-viewer and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-plantuml-viewer.

What PlantUML Viewer & Preview handles

  • plantuml code blocks and @startuml blocks in Markdown files.
  • Sequence, class, component, state, use case, activity, mind map and Gantt diagrams.
  • C4 and AWS includes from the standard library, which is inside the jar, so they draw offline.

What it does not do

  • Java 11 or newer must be installed. The extension does not download Java.
  • The image is a copy. Change the diagram and you must render it again.
  • The MIT build of PlantUML has no Ditaa and no @startmath.
  • Includes from web addresses are refused, except the C4 and AWS ones read from the copy inside the jar.

Other options

  • PlantUML server image link. An image URL on plantuml.com with the diagram encoded in it. It draws on GitHub, but the diagram text goes to that server on every view.
  • Mermaid. GitHub draws mermaid blocks itself. Rewriting the diagrams in Mermaid avoids image files, but the syntax is different.

Questions

Does GitHub render PlantUML at all?

Not in Markdown code blocks. It shows them as code. Images and Mermaid blocks are shown.

Does GitLab render PlantUML?

Only when the GitLab admin has turned on its PlantUML integration. Image files work everywhere.

Is Graphviz needed for class diagrams?

No. When dot is not installed, PlantUML's built-in Smetana layout is used.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
