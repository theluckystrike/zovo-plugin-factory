Read the signing certificate SHA-256 of an APK

The SHA-256 fingerprint of the signing certificate tells you whether two APKs come from the same key, and services such as Firebase ask for it. APK Analyzer reads the v1 signature files and the APK Signing Block of an .apk in VS Code and shows the signer certificate with its SHA-256, SHA-1, subject, issuer, validity and key type, with no Java and no Android SDK. It shows the signature data but does not verify it. Zovo Pro (USD 19 once) adds a compare of two APKs that flags a changed certificate, with 3 free tries.

Steps in VS Code

  1. Install APK Analyzer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-apk-analyzer.
  2. Click the .apk file in the Explorer. It opens in APK Analyzer.
  3. Read the Overview. The Signing row lists the schemes, such as v1, v2, v3, and the Certificate SHA-256 row shows the fingerprint.
  4. Open the Signing tab for the full record. It lists the APK Signing Block with its size, offset and blocks, the v1 signature files in META-INF, then Certificate SHA-256, Certificate SHA-1, Subject, Issuer, Valid and Key.
  5. Click a row and press Ctrl+C (Cmd+C on macOS) to copy it. The fingerprints are lowercase hex with no colons.
  6. To check two APKs, open both and compare their Certificate SHA-256 rows. The same value means the same signing certificate.

What APK Analyzer handles

  • v1 (JAR) signatures, the .SF file with an .RSA, .DSA or .EC file in META-INF.
  • The APK Signing Block with v2, v3 and v3.1 blocks. Source stamp and Google Play blocks are named.
  • The key type and the signature algorithm of the certificate, and its validity dates.
  • .aab bundles, and the base APK of .apks and .xapk files.

What it does not do

  • APK Analyzer shows the signature data. It does not verify signatures, so it cannot tell you that an APK was not changed after signing.
  • The tab shows one signer certificate. When a v1 signature is present, its certificate is the one shown. With key rotation in v3 or v3.1, the certificate shown can be the older one.
  • v4 signatures live in a separate .idsig file, which is not read.
  • A signature file in META-INF larger than 1 MB is not read.

Other options

  • keytool. Comes with the JDK. keytool -printcert -jarfile app.apk prints the SHA-1 and SHA-256 of the signer. It reads the v1 signature only, so it shows nothing for an APK signed with v2 or v3 alone.
  • apksigner. Part of the Android SDK build tools. It verifies the signature and prints the certificate digests. Needs the SDK and Java.

Questions

Why do keytool and the Play Console show colons?

They print the same digest in uppercase pairs with colons. APK Analyzer prints it as lowercase hex. Compare the letters and digits and ignore the case and the colons.

Why is the SHA-256 not the one in the Play Console?

With Play App Signing, Google signs the APKs it delivers with the app signing key, and you sign your uploads with an upload key. An APK you built yourself shows the upload certificate. An APK from Google Play shows the app signing certificate.

Does it check that the signature is valid?

No. It reads and shows the certificate and the signature blocks. Use apksigner to verify a signature.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
