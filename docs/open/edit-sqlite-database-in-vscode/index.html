Edit a SQLite database in VS Code

SQLite Editor & Viewer opens a .db or .sqlite file in VS Code as a table, read-only. Click Enable editing to change cells and rows, run INSERT or UPDATE, or import a CSV file. Every change waits in a pending list with its SQL and Undo, and Save makes a backup copy before it replaces the file. All of that is free. Steps in VS Code

  1. Install SQLite DB Viewer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.sqlite-table-viewer.
  2. Click a .db, .sqlite, .sqlite3, .db3, .s3db, .sl3, .vscdb or .gpkg file. It opens as a table, read-only.
  3. Click Enable editing. Double-click a cell (or press Enter or F2, or just type), change it and press Enter. Each change waits in a pending list with its SQL and an Undo.
  4. To add data from a file, click Import CSV in the toolbar. To make a new database from a CSV, right-click the .csv in the Explorer and pick "Import CSV into a new SQLite database".
  5. For bigger changes, use the SQL tab. INSERT, UPDATE, DELETE, REPLACE, CREATE, DROP and ALTER go into the same pending list.
  6. Press Save (Ctrl+S or Cmd+S). It checks the foreign keys, copies the file to a backup such as name.db.20261109-143000.bak, and replaces the file in one step.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.sqlite-table-viewer and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/sqlite-table-viewer.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What SQLite DB Viewer handles

  • Cells, rows, NULL, long text, JSON and BLOB values.
  • INSERT, UPDATE, DELETE, CREATE, DROP and ALTER from the SQL tab, staged with Undo.
  • CSV and TSV import with the delimiter, encoding and header row guessed and changeable.
  • Databases in WAL mode, including the committed transactions in the -wal file.

What it does not do

  • Editing works up to 256 MB (setting sqliteTableViewer.editMaxFileSizeMB). Larger files, up to 512 MB, open read-only.
  • Files on remote or virtual file systems open read-only.
  • Encrypted databases (SQLCipher, SEE) cannot be opened.
  • Closing the tab with unsaved changes drops them, and the file stays as it was.

Other options

  • DB Browser for SQLite. A free, open source desktop app to browse and edit SQLite files, outside VS Code.
  • The sqlite3 command-line shell. Free. Run UPDATE and INSERT statements by hand. Good for scripts, with no grid.

Questions

Is my database changed when I only open it?

No. It opens read-only. Nothing is written before you click Enable editing and then Save.

What if my app writes to the database while I edit?

If the file changed on disk since you opened it, Save refuses and keeps your changes. It also stops when the -wal file holds transactions that are not in the main file yet.

Is editing free?

Yes. Opening, editing, Save and CSV import are free, with no sign-in. Only the compare, the ER diagram and the export of all tables are Pro, with 3 free tries each.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
