Reach a Redis inside your Dev Container

Redis Client & Redis GUI runs in the remote extension host, the same place as your workspace. In a Dev Container or a Remote SSH window, a Redis in that container or on that network is reachable as localhost or by its Docker Compose service name. When a connection fails, the message names the step that failed, such as DNS, TCP, TLS or AUTH. Zovo Pro (USD 19 once) adds Memory Analysis and Bulk TTL / Delete by Pattern, with 3 free tries each.

Steps in VS Code

  1. Install Redis Client & Redis GUI from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-redis-client.
  2. Open your folder in the Dev Container or Remote SSH window. If the Extensions view shows the extension as installed only on your computer, install it in the container or on the remote host too.
  3. Click the Redis icon in the Activity Bar, then Add Connection.
  4. Type the host as the container sees it. Use localhost when Redis runs in the same container, or the service name, such as redis, when it is its own Docker Compose service. A URL such as redis://redis:6379/0 works too.
  5. Click Test connection. It shows each step, and a failure names the step (DNS, TCP, TLS or AUTH) with a hint.
  6. Expand the connection and a database, then click a key. Right-click the connection for the console, server info and pub/sub.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-redis-client and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-redis-client.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What Redis Client & Redis GUI handles

  • Redis, Valkey and KeyDB, on a single node, a cluster or a sentinel set.
  • TLS with a CA file, and ACL users.
  • Dev Containers and Remote SSH, because the extension runs where the workspace runs.
  • Binary keys and values, shown as \xNN and written back byte for byte.

What it does not do

  • A cluster in Docker may announce internal IP addresses. Connect from inside the same network (a Dev Container or Remote SSH) or use the addresses the cluster announces.
  • String values over 5 MB open as a size message with Show the first 64 KB and Save to a file (setting redisClient.maxValueSizeMB).
  • Keys load with SCAN in pages of 10,000 (setting redisClient.scanPageSize). Load more from the end of the list.

Other options

  • redis-cli. Free and always next to Redis. Run docker compose exec redis redis-cli. No tree view and no editors.
  • Redis Insight. The free desktop GUI from Redis. It runs on your computer, so a Redis inside a container needs a forwarded port.
  • Redis for VS Code. The extension from Redis Ltd. A March 2025 Marketplace review says it does not support remote development (SSH, Dev Containers).

Questions

Why does localhost work here but not in my desktop GUI?

In a Dev Container window this extension runs inside the container, so localhost is the container. A desktop app runs on your computer, where localhost is your computer.

Redis runs on my computer, not in the container. What host do I type?

Then the extension inside the container has to reach your computer. With Docker Desktop that host is usually host.docker.internal.

Is my password saved?

It is kept in VS Code's secret storage. Clear "Save the password" in the form and it is asked once per window instead.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
