Why an XPath returns nothing on XML with a namespace

In XPath 1.0, a name with no prefix matches only elements in no namespace. A pom.xml, SVG, XAML or .csproj file declares a default namespace, so //dependency finds nothing in a strict XPath tool. XML Formatter & XPath Tools runs XPath 1.0 in VS Code with the prefixes the file declares, and plain names also match the default namespace, so the query works as you wrote it. Steps in VS Code

  1. Install XML Formatter & XPath Tools from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-xml-xpath-tools.
  2. Open the XML file and click the search button in the editor title, or run "XML: Evaluate XPath..." from the Command Palette.
  3. Type the XPath as you would for a file with no namespace, such as //dependency/artifactId. Plain names also match elements in the default namespace.
  4. For elements with a prefix, use the prefix the file declares, such as //soap:Body/m:GetStockPrice. You do not bind it yourself. If a prefix is not declared, the message lists the prefixes the file does declare.
  5. Results list in XPath Results with their line. Click one to select it in the editor, or right-click it to copy its value or its XPath.
  6. For a query that works in any XPath 1.0 tool, put the cursor on the element, click the XPath in the status bar and pick the portable local-name() form.

What XML Formatter & XPath Tools handles

  • Default namespaces in Maven pom.xml, SVG, XAML, .csproj and KML files.
  • Prefixes declared anywhere in the file. When one prefix is bound to two namespaces, the first binding is used and a note says so.
  • Copied paths are checked in the tests. For sampled elements in 22 files, each of the 3 styles selects that one element and nothing else.
  • Numbers, strings and booleans, such as count(//dependency), show on one line.

What it does not do

  • XPath 1.0 only. There is no XPath 2.0 or 3.1, XQuery or XSLT.
  • Matching plain names in the default namespace is not strict XPath 1.0. Turn on xmlXpathTools.xpath.strictNamespaces to test a query the way other tools run it.
  • Up to 5,000 results are listed (setting xmlXpathTools.xpath.maxResults).
  • VS Code does not pass files over 50 MB to extensions, so XPath does not run on them.

Other options

  • xmllint. Free with libxml2. Its XPath option has no way to bind a prefix to the default namespace, so write //*[local-name()='dependency'] there.
  • XML Tools. Its own description: "XML Formatting, XQuery, and XPath Tools for Visual Studio Code".
  • Your own code. In Python lxml, Java or .NET, bind a prefix such as m to the namespace URI of the file and write //m:dependency.

Questions

Why does //dependency work here but not in my code?

Strict XPath 1.0 matches a plain name only in no namespace. This extension also matches the default namespace. In code, bind a prefix to the namespace URI or use local-name().

How do I find the namespace URI?

Look at the xmlns="..." attribute on the root element. In a Maven pom.xml it is http://maven.apache.org/POM/4.0.0.

Does it send my file anywhere?

No. The extension has no network code, and a test checks that.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
