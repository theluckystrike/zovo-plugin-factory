Open files in VS Code and Cursor / Tables and data

Find out why a Parquet file will not open

A Parquet file starts and ends with the 4 bytes PAR1, and its schema sits in a footer just before the last PAR1. When a download or copy stops early the end is missing, and pyarrow says "Parquet magic bytes not found in footer". Parquet Grid Viewer opens the file in VS Code and says what is wrong, for example that the file starts with PAR1 but has no footer, that it is encrypted, or that it looks like an ORC, Avro, Arrow, ZIP or gzip file. To find every damaged file in a folder of shards, Folder report and schema drift (Zovo Pro, USD 19 once, 3 free tries) lists a problem for each file it cannot read.

Steps in VS Code

  1. Install Parquet Grid Viewer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-parquet-viewer.
  2. Click the .parquet file in the Explorer. If another editor opens it, right-click it and pick "Open in Parquet Grid Viewer".
  3. If the file does not open, read the message and the code under it. TRUNCATED means the file starts with PAR1 but has no footer, so it was cut off or a program is still writing it. NOT_PARQUET means it does not start or end with PAR1, and the message says when it looks like ORC, Avro, Arrow, ZIP, gzip or text.
  4. Other messages name an encrypted file, a footer that claims more bytes than the file has, metadata that cannot be read, or a file of 0 bytes.
  5. For a cut-off file, copy it again from the source, then click Try again.
  6. If the file opens but some rows cannot be read, the message names the rows and the row group. The Schema tab gives the row count of each row group, to compare with the source.

What Parquet Grid Viewer handles

  • Files cut off by an interrupted download, copy or write.
  • Files that are not Parquet, such as ORC, Avro, Arrow IPC, ZIP or gzip files with a .parquet name.
  • Encrypted files, empty files and files with a damaged footer.
  • Metadata over the size limit, with a message that gives the size and the setting to change.

What it does not do

  • The viewer cannot repair a file. A cut-off file has to be copied again from the source.
  • Encrypted Parquet files cannot be read, because the viewer does not ask for keys.
  • Files whose column chunks live in other files (file_path in the metadata) are not supported.
  • Files on remote or virtual file systems are read whole, up to 512 MB (setting parquetViewer.maxVirtualFileMB).

Other options

  • tail in a terminal. tail -c 4 file.parquet prints PAR1 for a whole Parquet file. Anything else means the end is missing or the file is not Parquet.
  • pyarrow. pyarrow.parquet.read_metadata() fails with the magic bytes error on a cut-off file, but gives the same message for a file that is not Parquet.

Questions

Can the viewer fix a truncated Parquet file?

No. The footer holds the schema and where each row group starts, so a file without it cannot be read. Copy the file again from the source.

What does "a program is still writing it" mean?

A writer adds the footer last. If you open the file while a job is still writing it, the footer is not there yet. Wait for the job to finish and click Try again.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
