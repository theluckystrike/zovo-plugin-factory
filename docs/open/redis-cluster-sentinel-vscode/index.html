Connect VS Code to a Redis Cluster or a Sentinel setup

A cluster spreads keys over several primary nodes, and with Sentinel the primary can move to another host after a failover. A client that knows only one host and port sees part of the keys or loses the connection. Redis Client & Redis GUI has a Cluster type that reads the keys from every primary, and a Sentinel type that asks the sentinels for the current primary and follows a failover. Keys load with SCAN in pages, never with KEYS *, and all of this is free. Zovo Pro (USD 19 once) adds Memory Analysis and Bulk TTL / Delete by Pattern, with 3 free tries each.

Steps in VS Code

  1. Install Redis Client & Redis GUI from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-redis-client.
  2. Click the Redis icon in the activity bar, then Add Connection.
  3. For a cluster, pick Cluster as the Type and enter one or more nodes as host:port. The rest of the cluster is found from them. A redis+cluster:// URL works too.
  4. For Sentinel, pick Sentinel, enter the sentinels as host:port (often port 26379) and the Primary name from sentinel monitor. Fill in the Sentinel password only when the sentinels have their own. Or paste a URL such as redis+sentinel://host:26379/mymaster.
  5. Add the ACL user and password, tick TLS for rediss://, and click Test connection. It shows each step, so a failure names DNS, TCP, TLS or AUTH.
  6. Expand the connection. In a cluster, the keys are scanned on each primary in turn and grouped into folders by :. Right-click a database or a folder to filter by pattern and type.
  7. Right-click the connection and open Server Info, Slow Log and Clients to see memory, the slow log and the clients of each node.

What Redis Client & Redis GUI handles

  • Redis Cluster with keys on many primaries, read with SCAN on each one.
  • Sentinel sets, with a separate sentinel user and password, and a failover to a new primary.
  • TLS with a CA file, and Redis 6 ACL users.
  • Redis, Valkey and KeyDB.

What it does not do

  • A cluster has only database 0, as in Redis itself.
  • If a node does not answer during the scan, its keys are missing from the list and a message names the node. Refresh scans again.
  • The key tree loads 10,000 keys per page (setting redisClient.scanPageSize). Load More Keys reads the next page.
  • A string over 5 MB opens as a size message with "Show the first 64 KB" and "Save to a file".

Other options

  • redis-cli. redis-cli -c follows cluster redirects, and its scan option lists keys with SCAN. Free, in the terminal, with no key tree.
  • Redis Insight. The free desktop GUI from Redis Ltd. It runs outside VS Code.

Questions

Does it run KEYS on my server?

No. The key tree uses SCAN in pages. If you type KEYS in the console, it asks first, because KEYS walks every key in one call and blocks the server until it finishes.

What happens after a Sentinel failover?

The client follows the new primary that the sentinels report. You do not need to edit the connection.

Can I make the connection read-only?

Yes. Each connection has a read-only switch. Writes are refused before they reach the server.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
