Open and edit a BPMN diagram in VS Code

BPMN Diagram Editor & Viewer opens a .bpmn file in VS Code as a diagram you can pan, zoom and edit: events, tasks, gateways, pools, lanes and message flows. Saving writes standard BPMN 2.0 XML and changes only the lines your edit touched, so Camunda, Zeebe and Flowable settings, comments and your own formatting stay as they were. It is free, offline and needs no account. Zovo Pro (USD 19 once) adds a model check, a visual compare of versions, and SVG, PNG and PDF export, with 3 free tries each.

Steps in VS Code

  1. Install BPMN Diagram Editor & Viewer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-bpmn-editor.
  2. Click a .bpmn, .bpmn2 or .bpmn20.xml file in the Explorer. It opens as a diagram. No file at hand? Run "BPMN: Open the Sample Diagram" or "BPMN: New BPMN Diagram".
  3. Add elements from the palette: start, end and intermediate events, tasks, sub-processes, gateways, data objects, pools, lanes and message flows.
  4. Click an element for its menu: append the next step, change its type, connect, add a lane above or below, or delete. The properties panel edits the id, name, documentation and the condition of a flow.
  5. Click XML to open the same file as text beside the diagram. Type in the XML and the diagram redraws, and undo and redo work across both views.
  6. Save with Ctrl+S (Cmd+S on macOS). A rename changes one line, and a moved task changes only its coordinates and the arrows that follow it.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-bpmn-editor and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-bpmn-editor.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What BPMN Diagram Editor & Viewer handles

  • BPMN 2.0 files from Camunda 7 and 8 (Zeebe), Flowable, Activiti and other modeling tools.
  • Vendor attributes and extension elements, XML comments, blank lines, indentation, attribute order and namespace prefixes stay byte for byte when you save.
  • Camunda, Zeebe or Flowable settings of the selected element listed read-only in the properties panel.
  • A file that is not valid XML shows the reason and the line, and the file is never touched.

What it does not do

  • Vendor settings such as Camunda input and output mappings, Zeebe task definitions and Flowable listeners are kept and listed, but edited in the XML text, not in a form.
  • Simulation, token play and process deployment are not part of this extension.
  • Files from git history and other read-only places open as a viewer with no palette.
  • The bpmn.io logo in the corner of the canvas is part of the bpmn-js license and stays visible.

Questions

Can VS Code open a .bpmn file as a diagram without an extension?

No. VS Code opens a .bpmn file as XML text. You need an extension that draws the diagram.

Will saving rewrite my Camunda or Zeebe settings?

No. Only the lines your edit touched change. Vendor attributes, extension elements, comments and formatting stay byte for byte.

Can I edit the XML and the diagram together?

Yes. Click XML to open the same file as text. Typing in the XML redraws the diagram, and undo and redo work across both.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
