Open a .wasm file in VS Code and read it as WAT text

WebAssembly Viewer (WASM, WAT) opens a .wasm file in VS Code as WAT text in the wasm2wat layout, with one fold per function, instead of binary noise. The Overview tab lists the sections with their sizes, the imports, exports, memories, tables, globals and custom sections. It validates the module, saves the text as .wat, and compiles .wat files back to .wasm, with no toolchain to install, no account and no network. All of that is free. Zovo Pro (USD 19 once) adds a size profiler, a compare of two builds and source mapping, with 3 free tries each.

Steps in VS Code

  1. Install WebAssembly Viewer (WASM, WAT) from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-wasm-viewer.
  2. Click a .wasm file in the Explorer. It opens in the viewer as WAT text, with names from the name section (such as $main) when the module has them.
  3. Click the arrow next to a function to unfold it, or use Fold all and Unfold all. Large modules open folded and print a function only when you open it.
  4. Click a call, a ref.func or an export to go to its function. Type in Find in all code and press Enter to search every function, folded or not.
  5. Switch to Overview for the file and code size, each section with its offset and size, the imports with their types, the exports, memories in pages and bytes, tables, globals, custom sections and producers.
  6. Click Validate to check the whole module, or Save as WAT to write the text to a .wat file.

What WebAssembly Viewer (WASM, WAT) handles

  • Core WebAssembly modules with SIMD and relaxed SIMD, threads and atomics, exception handling (old and new), GC and reference types, tail calls, multi-memory, memory64 and multi-value.
  • .wat and .wast files with syntax colors, an outline, folding and errors with line and column while you type.
  • Compile WAT to WASM writes name.wasm next to the file and opens it in the viewer. Errors go to the Problems view.
  • Byte offsets next to each instruction (the Offsets box), for crash reports and hex dumps.

What it does not do

  • WebAssembly components (the component model) are not read yet. Core modules are.
  • The text is flat, like the default wasm2wat output. The folded s-expression style is not offered.
  • Open as WAT Text asks first for modules over 16 MB, because the text can be hundreds of MB. Save as WAT works for any size.
  • Files over 512 MB open with a message by default (the wasmViewer.maxFileSizeMB setting).
  • The viewer never writes to a .wasm file.

Questions

Why does a .wasm file look like gibberish in VS Code?

A .wasm file is a binary module, and VS Code shows binary files as text or refuses to open them. WebAssembly Viewer turns it into readable WAT text.

Do I need wabt or Emscripten installed?

No. Validate and WAT to WASM use wabt, bundled as WebAssembly inside the extension, so there is nothing else to install.

Can it open large modules?

Yes. Large modules open folded and print a function only when you open it. The README measures a 35 MB module opening in about a second.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
