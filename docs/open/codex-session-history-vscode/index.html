Find and resume an old Codex session in VS Code

Codex saves each thread as a rollout file under ~/.codex/sessions, and each subagent thread as its own file. Agent Session Viewer lists them in a VS Code side view, grouped by project folder, under the names they have in Codex, with subagent threads nested under the thread that started them. Click one to read it with tool calls, diffs and reasoning summaries, search all of them, and resume one with codex resume <id> in a terminal in the project folder. Zovo Pro (USD 19 once) adds a bulk export to Markdown, a share-safe export with secrets redacted and a usage and cost report, with 3 free tries each.

Steps in VS Code

  1. Install Agent Session Viewer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.agent-session-viewer.
  2. Click the Agent Sessions icon in the activity bar. Codex sessions sit under Codex, grouped by project folder, newest first.
  3. Expand a thread to see its subagent threads, named by the agent's nickname or type and its task.
  4. Click a thread to read it. Tool calls are folded with their input and output, file edits from apply_patch show as diffs, and reasoning summaries are folded.
  5. To find an old thread, click the search icon at the top of the view and type a word you remember. Pick a result to open the thread at that spot.
  6. Click the terminal icon next to a thread, or "Resume in terminal" in the thread, to run codex resume <id> in a new terminal in the project folder.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.agent-session-viewer and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/agent-session-viewer.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What Agent Session Viewer handles

  • Codex rollout files in ~/.codex/sessions, or in $CODEX_HOME/sessions when you set it.
  • Subagent threads, each in its own file, nested under the thread that started them.
  • Thread names from Codex's session_index.jsonl, so threads you renamed keep their names.
  • Token totals per thread, including reasoning tokens.

What it does not do

  • Codex usually stores reasoning encrypted. Only the summaries it writes in plain text can be shown.
  • Codex does not write a cost into its files, so the thread header shows tokens, not a price.
  • Resume in terminal needs Codex installed and on the terminal's PATH.
  • Search matches plain text, not regular expressions, and stops at 300 results.

Other options

  • codex resume. Running codex resume in a terminal opens a picker of recent sessions. It shows no transcript and no diffs.
  • Codex History Viewer. Another extension for local Codex and Claude Code history, on Open VSX.

Questions

Where does Codex store old sessions?

In ~/.codex/sessions/YYYY/MM/DD/, one rollout-*.jsonl file per thread. With CODEX_HOME set, under that folder instead.

Can I delete a session from the viewer?

No. It has no delete, move or rename command, so a click can never lose history.

Does it show Claude Code sessions too?

Yes, in the same view. See Claude Code history viewer.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
