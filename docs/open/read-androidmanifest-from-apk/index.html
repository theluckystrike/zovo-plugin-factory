Read the AndroidManifest.xml and permissions of an APK

The AndroidManifest.xml inside an APK is Android binary XML, so unzipping the APK gives you an unreadable file. APK Analyzer decodes it in VS Code with no Android SDK and no Java. Click the .apk to get the manifest as indented XML, every permission with the dangerous ones flagged, and every component with its exported flag and the reason for it. Steps in VS Code

  1. Install APK Analyzer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-apk-analyzer.
  2. Click the .apk file in the Explorer. .aab, .apks and .xapk files open too. The Overview shows the package name, versionName and versionCode, the min, target and compile SDK, and the debuggable, allowBackup and cleartext traffic flags.
  3. Open the Manifest tab. It shows AndroidManifest.xml decoded into indented XML. Click Copy, or Open as XML document to get it in an editor tab where you can search it.
  4. Open the Permissions tab. The Protection column says dangerous, special access, or normal or signature, from a built-in list of Android permissions. Permissions the app declares itself are listed too.
  5. Open the Components tab to see each activity, service, receiver and provider with its exported flag and why. A component with an intent filter and no android:exported on targetSdk 31 or higher shows "not set", because Android 12 and later refuse to install such an app.
  6. Open the Signing tab for the v1, v2 and v3 signature blocks and the signer certificate with its SHA-256, SHA-1, subject, issuer and validity.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-apk-analyzer and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-apk-analyzer.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What APK Analyzer handles

  • The merged manifest inside the APK, so permissions that libraries add show up too.
  • Exported flags set in the manifest, implied by an intent filter on targetSdk below 31, or left at the default. The launcher activity is marked.
  • v1 (JAR) signatures and the APK Signing Block with v2, v3 and v3.1 blocks.
  • .apks and .xapk sets, where the base APK is read in the other tabs.

What it does not do

  • It shows the signature data but does not verify the signature.
  • Resource references stay as ids such as @0x7f0e001b, because resources.arsc is not read. An app label stored as a string resource shows its id.
  • In an .aab bundle the manifest is a protocol buffer, which this version does not decode.
  • Files on remote or virtual file systems are read up to 256 MB.

Other options

  • APK Analyzer in Android Studio. Free. Build, then Analyze APK shows the decoded manifest. It needs the full Android Studio install.
  • apkanalyzer. A command-line tool in the Android SDK. apkanalyzer manifest print app.apk prints the decoded manifest.
  • apktool. Free. apktool d app.apk decodes the manifest and the resources into a folder. It needs Java.

Questions

Why is AndroidManifest.xml unreadable after I unzip the APK?

The build tools store it as Android binary XML, not as text. The viewer decodes that format back to XML.

Does it need the Android SDK or Java?

No. The extension reads the APK itself, in JavaScript, and makes no network calls.

Does it check that the signature is valid?

No. It shows the signature blocks and the signer certificate, but it does not verify them. apksigner from the Android SDK does that.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
