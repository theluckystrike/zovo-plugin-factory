Find which nginx server and location answer a URL

nginx picks a location by fixed rules. An exact = match wins, then the longest prefix, which ends the search when it has ^~. Otherwise regex locations are tried in config order, and the first match wins. If no regex matches, the longest prefix is used. Nginx Config Formatter & Lint lists every server and location across your include files for free. Its Location tester applies these rules to a URL you type and shows each step. What Nginx Config Formatter & Lint handles

  • The location modifiers =, ^~, ~ and ~*, prefix locations and nested locations.
  • Exact, wildcard and regex server names, and default_server.
  • proxy_pass with and without a URI part, root, alias, try_files, return and rewrite lines.
  • Include files, with patterns such as conf.d/*.conf.

What it does not do

  • Location regexes are tested with JavaScript regular expressions. A regex with PCRE-only syntax is reported as skipped.
  • A rewrite is listed as a step, but the tester does not run it and search the locations again with the new URI.
  • It reads your files. It does not run nginx or send a request to your server.

Other options

  • A test header and curl. Add a header such as add_header X-Loc api; to each location, reload nginx and check the response with curl -I. Works on the real server, but you edit the config.
  • nginx documentation. The page "How nginx processes a request" explains the server and location choice in full.

Questions

Does a regex location beat a longer prefix?

Yes, unless the longest prefix match has ^~ or the match is exact with =. Regex locations are tried in config order after the longest prefix is found, and the first match wins.

Does it follow include files?

Yes. Relative includes are read from nginxConfig.prefix, the file's folder, its parent folder or /etc/nginx, in that order.

Is the overview free?

Yes. Only the Location tester, the Security audit and the .htaccess converter are Pro.
