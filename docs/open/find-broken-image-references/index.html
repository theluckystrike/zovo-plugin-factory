Find every image path that points to a missing file

When an image is renamed or moved, the old paths in CSS, JSX, HTML and Markdown stay in place and only show up as a 404 in the browser. Image Preview & Image Hover tells you on hover, for free, when one path does not resolve. Its Find Broken Image References tool checks every text file of a folder at once and lists each image path that points to a missing file, with file and line, in a Markdown report and in the Problems panel. It is part of Zovo Pro (USD 19 once), with 3 free tries on your computer.

Steps in VS Code

  1. Install Image Preview & Image Hover from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-image-preview.
  2. Open the project folder in VS Code.
  3. Right-click a folder in the Explorer and pick "Zovo Pro: Find broken image references". Or run "Image Preview: Find Broken Image References (Pro)" from the Command Palette for the whole workspace folder.
  4. Read the report. It groups the broken paths by file, with a link to each line.
  5. Open the Problems panel with Ctrl+Shift+M (Cmd+Shift+M on a Mac). Each broken path is a warning that starts with "Image not found", and a click takes you to it.
  6. Fix the path or the file name, then hover the path. Once it resolves, the hover shows the picture and the gutter shows the thumbnail. Run the tool again for a fresh list.

Where Zovo Pro saves time

Hovering a path is free. If the file is missing, the hover says "Image not found" and lists the paths it looked for, with a pointer to the imgPreview.aliases setting for prefixes it does not know. A line whose image is missing gets no thumbnail in the gutter.

Hovering finds one broken path at a time, and only in files you open. Find Broken Image References reads every code, style, Markdown and HTML file of a folder and resolves each image path the same way the hover does, with tsconfig paths, public folders and your aliases. It lists the ones that point nowhere, and the list stays in the Problems panel while you fix them. The other two Pro tools are Find Unused Images and Image Weight Report.

What Image Preview & Image Hover handles

  • Paths in imports, JSX, CSS url(), HTML src and srcset, Markdown images and YAML.
  • Relative paths, / paths from public/, static/ and other web root folders, @/, ~ and tsconfig.json paths with extends.
  • File names with spaces, %20, ?v=2 or #id.
  • Each package of a monorepo, with its own public/ folder and tsconfig.json.

What it does not do

  • Remote URLs and data URIs are not checked. The extension never downloads anything.
  • Paths built while the code runs, such as template strings with a variable, cannot be checked.
  • A plain file name with no folder in a code string, such as "logo.png", is not reported, because it may be a name and not a path.
  • Aliases that exist only in a Webpack, Vite or Next.js config file are not read, so their paths show up as broken. Add them to imgPreview.aliases or to tsconfig.json paths.
  • Text files over 2 MB are not read.

Questions

Does it fix the paths?

No. It lists them. You fix each path, and the hover confirms it once the file is found.

Why is a path with a Vite alias reported?

The extension does not read JavaScript config files. Add the alias to imgPreview.aliases, for example { "@images": "src/assets/images" }, and run the tool again.

Is the free hover enough?

For the files you have open, often yes. The tool is for a whole folder at once.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
