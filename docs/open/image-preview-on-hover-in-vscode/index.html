See the image behind a path in your code, in the gutter and on hover

Image Preview & Image Hover shows a thumbnail in the gutter next to every line that names an image, and a hover with the image, its type, its size in pixels and its file size. It works in JavaScript and TypeScript imports, JSX, CSS url(), Markdown, HTML src and srcset, YAML and data URIs, and it resolves /public paths, @/ and tsconfig paths. All of that is free, with no network requests. Zovo Pro (USD 19 once) adds a finder for unused images, a finder for broken image references and an image weight report, with 3 free tries each.

Steps in VS Code

  1. Install Image Preview & Image Hover from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-image-preview.
  2. Open a file that names an image, such as import logo from './logo.png', a CSS url() or an HTML <img src>. Thumbnails appear in the gutter.
  3. Hover the path to see the image (scaled to fit, never enlarged), its type, width and height in pixels, file size and transparency, with links to open the file or show it in the Explorer.
  4. If a path does not resolve, the hover says so and lists the paths it looked for. Add your own prefixes in imgPreview.aliases, for example { "@images": "src/assets/images" }, or folders for / paths in imgPreview.publicFolders.
  5. To hide the gutter thumbnails, run "Image Preview: Show or Hide Gutter Thumbnails". "Image Preview: Open the Sample Files" opens a small demo project with every kind of path.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-image-preview and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-image-preview.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What Image Preview & Image Hover handles

  • PNG, JPEG, GIF, WebP, AVIF, SVG, BMP and ICO thumbnails, and data:image/... URIs. TIFF and HEIC files get their size and type from the header.
  • Paths relative to the file, /logo.png from public/, static/ and other web root folders, @/ for src/, ~, and tsconfig.json or jsconfig.json paths with extends.
  • File names with spaces, %20, ?v=2 or #id, and each package's own public/ folder and tsconfig.json in a monorepo.
  • A remote URL shows as a link and is never downloaded.

What it does not do

  • Paths built when the code runs, such as `icons/${name}.svg`, cannot be previewed, and they can make an image look unused: check the unused list before you move files.
  • One thumbnail per line: the first image on that line. The hover works for each path on the line.
  • Remote and virtual workspaces (SSH, WSL, Codespaces, vscode.dev) are not supported in this version.
  • Webpack, Vite or Next.js aliases that exist only in a JavaScript config file are not read. Add them to imgPreview.aliases or tsconfig.json paths.

Other options

  • Image preview (kisstkondoros.vscode-gutter-preview, 4.3 million installs, on Open VSX). Its own description: "Shows image preview in the gutter and on hover".
  • The built-in image viewer. Click an image file in the Explorer and VS Code shows it in a tab, one file at a time, with no thumbnail next to the code that names it.

Questions

Can VS Code show an image preview on hover without an extension?

No. VS Code opens an image file in its own viewer, but it shows no thumbnail or hover for a path written in your code.

Why does my @/ or alias path show no image?

The alias may exist only in a Webpack, Vite or Next.js config file, which is not read. Add it to imgPreview.aliases or to tsconfig.json paths.

Does it work over Remote SSH or WSL?

Not in this version. The hover image is read from the local disk.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
