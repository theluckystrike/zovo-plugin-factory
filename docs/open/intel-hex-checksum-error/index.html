Find checksum errors and bad records in an Intel HEX file

Each Intel HEX line ends with a checksum byte, and one wrong digit, a cut download or a hand edit makes the flasher reject the file. Intel HEX Viewer checks every record and lists each bad line with its line number on the Problems tab. For a wrong checksum it also gives the right value, as in "Checksum 1F is wrong; it should be 1E." Finding the problems is free. Zovo Pro (USD 19 once) adds Convert, which writes a new file with every record written fresh, plus compare and CRC tools, with 3 free tries each.

Steps in VS Code

  1. Install Intel HEX Viewer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-intel-hex-viewer.
  2. A .hex file opens as text first. Click the board icon in the editor title, or right-click the file and pick Open in Intel HEX Viewer. .ihex, .ihx, .srec, .s19, .s28, .s37 and .mot files open in the viewer when you click them.
  3. If the file has problems, the Overview shows a Problems card and a Problems tab appears. Each row has the line number, the kind (syntax, length, checksum or record) and a plain message.
  4. Click line on a row to jump to that line in the Raw text tab, where every problem line is marked.
  5. Read the notes on the Overview too. A missing end record (:00000001FF) means the file may be cut short, and lines after the end record are not read. That often happens when two HEX files are pasted together and the first one keeps its end record.
  6. Open the Memory map to see where the data lands. When two records write the same address, an Overlaps tab lists them.

What Intel HEX Viewer handles

  • Wrong checksums, and byte counts that do not match the length of the line.
  • Lines that do not start with a colon, odd numbers of hex digits, characters that are not hex digits, and records that are too short or too long.
  • Unknown record types and address records with the wrong length.
  • Motorola S-records, with wrong checksums and wrong S5 or S6 counts.

What it does not do

  • The Problems tab keeps the first 10,000 problems and counts the rest.
  • Text files up to 256 MB, about 6 million lines.
  • It does not edit the file in place. Fix a line in the text editor, or write a new file with Convert.
  • Plain .bin files have no records or checksums and are not read here.

Other options

  • SRecord. Free command-line tools that read Intel HEX and S-record files, check each record and convert between formats.
  • The intelhex Python package. Free. Loading a file with a bad record raises an error that names the line.
  • A text editor. Shows the lines, but you add up the bytes of each record yourself.

Questions

How is the Intel HEX checksum computed?

Add every byte of the record after the colon, so the byte count, the two address bytes, the record type and the data. Keep the low byte of the sum and take its two's complement. For :0300300002337A1E the bytes add up to 0xE2, and 0x100 minus 0xE2 is 0x1E.

Why does my .hex file open as text?

Many .hex files are not Intel HEX, so .hex files open as text. Click the board icon in the editor title to open the file in the viewer.

Is the data of a bad line still used?

Yes. The viewer keeps the data of a line with a wrong checksum and says so in the message, so you still see where it would go in memory.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
