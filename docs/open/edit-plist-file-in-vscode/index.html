Open and edit a binary or XML plist file in VS Code

Plist Viewer & Editor opens binary, XML and OpenStep property lists in VS Code as a Key, Type and Value tree, the way Xcode shows them, and you edit them in place. A binary plist is saved back as binary and an XML plist as XML with its own indent. Info.plist, entitlements, privacy manifests and provisioning profiles open too. It works offline on macOS, Windows and Linux, with no plutil and no account. All of that is free. Steps in VS Code

  1. Install Plist Viewer & Editor from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-plist-editor.
  2. Click a .plist file in the Explorer. It opens in the tree editor, binary, XML or OpenStep, and the format shows in the toolbar.
  3. Double-click a key or value to edit it, and click the type to change it (String, Number, Boolean, Date, Data, Array, Dictionary). + adds an item, - deletes one, Alt+Up and Alt+Down reorder rows.
  4. Press Ctrl+F (Cmd+F on macOS) to filter keys and values. Known Info.plist, entitlements and profile keys show a readable name next to the raw key.
  5. Save. A binary plist stays binary, and an XML plist keeps its prolog, indent and line ends. A file you only open is never rewritten.
  6. To read the XML, click Show XML for a live read-only copy, or Open as Text. Save a Copy As writes XML, binary, JSON or OpenStep.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-plist-editor and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-plist-editor.

  4. Then use it the same way as in VS Code.

What Plist Viewer & Editor handles

  • Binary (bplist00), XML and OpenStep (old-style text) plists, .entitlements and PrivacyInfo.xcprivacy.
  • .mobileprovision and .provisionprofile files, read-only, as a tree with expiry, team, devices and entitlements.
  • Copy a key, a value, a key path, or a subtree as XML or JSON from the right-click menu.
  • Large files stay fast, because only the rows on screen are drawn.

What it does not do

  • Comments in OpenStep and XML plists are not kept when you save, because the file is written again from the tree.
  • An XML plist formatted by hand is written in Apple's layout when you save it; the values do not change.
  • Signed provisioning profiles are read-only, because editing would break the signature.
  • .strings files and Xcode project.pbxproj files are not opened by default, since saving drops their comments.

Questions

Why does a .plist file look like gibberish in VS Code?

It is a binary plist (it starts with bplist00). VS Code shows binary files as text. Plist Viewer & Editor reads it as a tree and saves it back as binary.

Can I edit a plist on Windows or Linux?

Yes. The extension reads and writes binary, XML and OpenStep plists itself, with no plutil, so it works on Windows and Linux too.

Will saving change my XML plist?

Only the values you change. The prolog, indent and line ends stay, and a file you only open is never rewritten. Comments are not kept.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
