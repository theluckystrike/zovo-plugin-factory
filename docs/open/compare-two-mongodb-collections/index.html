Compare two MongoDB collections

Counting documents in mongosh tells you that two collections differ, not which documents or which fields. Compare Two Collections in MongoDB Client & MongoDB GUI reads both collections in _id order, on the same server or on two, and writes a report of the documents that are equal, different, only in A or only in B, with the field paths that changed. It also writes a mongosh script that makes B match A, which you read and run yourself. It is a Zovo Pro tool (USD 19 once) with 3 free tries. Browsing, editing, queries and export stay free.

Steps in VS Code

  1. Install MongoDB Client & MongoDB GUI from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-mongodb-client.
  2. Open the MongoDB view in the activity bar and add both connections with Add Connection. They can be two different servers, such as staging and production.
  3. Right-click the first collection (A) and pick "Zovo Pro: Compare Two Collections".
  4. Pick the second collection (B). Both are read in _id order as streams, with a progress message and a Cancel button.
  5. A Markdown report opens with the number of equal, different, only-in-A and only-in-B documents. Each different document lists the field paths that changed.
  6. A mongosh script opens beside it, with insertOne, replaceOne and deleteOne calls that make B match A. Nothing has run. Read it, then run it in mongosh against the B server.

What MongoDB Client & MongoDB GUI handles

  • Two collections on the same server or on two connections.
  • Large collections, read as two streams, with a Cancel button.
  • Documents that differ only in field order. They count as equal, and the report says how many there are.
  • Atlas, replica sets and the MongoDB-compatible servers the extension connects to.

What it does not do

  • The report lists the first 1,000 documents of each kind. The counts cover all of them.
  • The script stops at 20 MB. If more differences remain, a comment says to run the compare again after it.
  • If a server does not return the documents in _id order, for example with mixed _id types on some MongoDB-compatible servers, the compare stops and says so.
  • The script is never run for you.

Other options

  • A mongosh script. A loop over two cursors sorted by _id can do the same check. Free, but you write and test the comparison yourself.
  • MongoDB Compass. The free desktop GUI from MongoDB, Inc. for browsing, querying and editing documents. It runs outside VS Code.

Questions

Can the two collections be on different servers?

Yes. Pick any two collections from any two connections, for example a local copy against Atlas.

Does the compare change either collection?

No. Both collections are only read. The sync script opens in an editor tab and is never run for you.

How do I read the field paths?

Each different document lists up to 12 changed paths, such as address.city, next to its _id.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
