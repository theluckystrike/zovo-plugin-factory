Find the environment variables that your code reads and .env does not set

An app that reads process.env.API_KEY gets nothing when no .env file sets that key, and the error often shows up far from the cause. Dotenv & .env File Editor has a report that reads the code of your workspace and every .env file, then lists the variables that code reads and no .env file sets, with file and line, and the keys that no code reads. It covers JavaScript, TypeScript, Python, Ruby, Go, Java, Kotlin, C#, PHP, Rust, YAML and shell, and it is a Zovo Pro tool (USD 19 once) with 3 free tries.

Steps in VS Code

  1. Install Dotenv & .env File Editor from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-dotenv.
  2. Open the project folder in VS Code. The report reads the whole workspace.
  3. Run "Dotenv: Find Keys Missing in Code or .env (Pro)" from the Command Palette, or right-click a folder in the Explorer and pick "Zovo Pro: Find keys missing in code or .env". A progress bar counts the files, and Cancel stops it.
  4. Read the first list, "Read in code, set in no .env file". Each name comes with up to 5 places in the code, as file and line.
  5. Read the second list, "Set in a .env file, read nowhere in code". Check those keys by hand before you delete one, because a framework can read a key that no line of your code names.
  6. Add the missing keys to your .env file. Names that the system or CI sets, such as NODE_ENV, PATH or GITHUB_TOKEN, are left out. The envFile.ignoreKeys setting holds that list.

What Dotenv & .env File Editor handles

  • process.env.X, process.env["X"], import.meta.env.X, Bun.env.X and Deno.env.get("X") in JavaScript and TypeScript.
  • os.environ and os.getenv in Python, ENV["X"] in Ruby, os.Getenv and os.LookupEnv in Go.
  • System.getenv in Java and Kotlin, Environment.GetEnvironmentVariable in C#, getenv and env() in PHP, std::env::var in Rust.
  • ${NAME} in shell and YAML files, and ${{ env.X }} or ${{ secrets.X }} in GitHub Actions workflows.

What it does not do

  • Only literal names are found. A name built at run time, such as process.env[name], is not seen.
  • Every .env file in the workspace counts, .env.example too. A key that only the template lists counts as set.
  • It reads at most 5,000 code files (setting envFile.codeMaxFiles), skips files over 2 MB and leaves out folders such as node_modules, dist, build and .venv.
  • GitHub Actions names such as ${{ secrets.X }} count as reads, so a secret that lives only in GitHub shows up in the first list.

Other options

  • envalid. A Node.js library that checks the variables your app needs when it starts, from a schema you write. It finds gaps at run time, not in the editor.
  • ripgrep. Search the code for process.env. or getenv and compare the names with your .env file by hand. Free, but slow for a large project.

Questions

Does it read my secret values?

It reads the .env files on your computer to know which keys are set, but the report lists key names, files and line numbers only. Nothing is sent anywhere.

Why is NODE_ENV not in the list?

Names that the system or CI usually sets, such as NODE_ENV, PATH, PORT and GITHUB_TOKEN, are ignored. Change the list in the envFile.ignoreKeys setting.

Which files does it read as code?

JavaScript, TypeScript, Vue, Svelte, Astro, Python, Ruby, Go, Java, Kotlin, C#, PHP, Rust, YAML and shell files. The envFile.codeInclude setting holds the file pattern.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
