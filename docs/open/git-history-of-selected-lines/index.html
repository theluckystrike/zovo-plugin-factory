Open files in VS Code and Cursor / Developer files

See every commit that changed the selected lines

Blame shows only the last commit that touched each line. To see how a block of code got to where it is, git has git log -L, which follows a line range back through history. Git Commit Graph & History Log runs it when you select the lines and pick "Show Line History for Selection", and lists every commit that changed those lines with the change shown inline. Line history is free, and Zovo Pro (USD 19 once) adds a branch comparison report, an interactive rebase editor and saved graph filters, with 3 free tries each.

Steps in VS Code

  1. Install Commit Graph from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-git-commit-graph.
  2. Open a file from a git repository and select the lines you want to trace.
  3. Right-click in the editor and pick "Show Line History for Selection", or run "Commit Graph: Show Line History for Selection".
  4. A Line History tab opens with the commits that changed those lines, newest first. Each one shows its subject, short hash, author, date and the change to those lines.
  5. Click a commit to open the VS Code diff of the file at that commit. Its Graph button shows the commit in the graph, and Open shows the file as it was then.
  6. For the whole file, pick "Show File History" instead. It follows renames.

What Commit Graph handles

  • Any text file in a git repository, in any language.
  • Line ranges that moved inside the file, which git log -L follows.
  • Files in nested repositories and submodules.
  • Whole-file history that follows renames, from Show File History.

What it does not do

  • The line numbers are those of the last commit. Commit your edits first, or the range may point at other lines.
  • At most 300 commits are listed, and a very long change is cut at 20,000 characters.
  • Uncommitted changes are not part of the history.
  • Lines that moved to another file are not followed.

Other options

  • git log -L in a terminal. git log -L 10,20:src/app.js prints the same history as text. Free, but you type the range and the path yourself.
  • GitLens. A VS Code extension with inline blame and file and line history views. Some features need a paid plan.
  • VS Code Timeline. The Timeline view in the Explorer lists the commits of the current file. It does not narrow the list to selected lines.

Questions

Is this the same as git blame?

No. Blame shows the last commit for each line. Line history lists every commit that changed the selected lines, the old ones too.

Why is my latest edit missing?

Line history reads committed history only. Commit the file to see your latest change in the list.

Does it follow the lines when code moves?

Within the file, yes, as git log -L does. Lines that moved to another file are not followed.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
