Compare an old commit with your current changes

The Source Control view compares your changes with HEAD only. To see everything that changed since an older commit, your uncommitted edits included, you would run git diff with that commit in a terminal. In Git Commit Graph & History Log you click the commit in the graph and then Compare with Working Tree, and you get the list of changed files with +/- counts, each one a click away from the VS Code diff. The compare is free, and Zovo Pro (USD 19 once) adds a branch comparison report, an interactive rebase editor and saved graph filters, with 3 free tries each.

Steps in VS Code

  1. Install Commit Graph from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-git-commit-graph.
  2. Click Graph in the status bar, or run "Commit Graph: Show Commit Graph".
  3. Find the old commit. Scroll, or type part of its message, its hash or the author in the search box and press Enter.
  4. Click the commit, then click Compare with Working Tree below the graph. You can also right-click the commit and pick Compare with Working Tree.
  5. Read the list. It says how many files differ and shows the status and the +/- lines of each file. Staged and unstaged changes both count.
  6. Click a file to open the VS Code diff. The commit version is on the left and your working file on the right, so you can edit and save it there.

What Commit Graph handles

  • Any commit in the graph, on local or remote branches and tags.
  • Staged and unstaged changes to tracked files.
  • Renamed files, shown with their old path.
  • Nested repositories and submodules, each picked from the repository list.

What it does not do

  • New files that git does not track yet are not in this list. Stage them with git add to include them.
  • At most 5,000 files are listed (setting zovoGit.maxFilesInDetails).
  • Files over 50 MB at the commit are not loaded into the diff (setting zovoGit.maxFileMB).
  • Binary files are listed as binary, without line counts.

Other options

  • git diff. git diff with a commit hash prints every change since that commit as text. Free, but there is no file list to click.
  • GitLens. A VS Code extension that can compare a commit with the working tree from its commit views. Some features need a paid plan.

Questions

Can I compare two old commits instead?

Yes. Click one commit, then Ctrl+click (Cmd+click on macOS) the other. The list shows the files that differ between them.

Can I edit the file in the diff?

Yes. The right side is your real working file, so you can edit and save it as in any VS Code diff.

Does it change anything in git?

No. Comparing only reads. Check out, reset and the other actions ask first and show the git command.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
