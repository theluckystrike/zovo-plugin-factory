Check if a .dylib or Mac binary is universal

A universal (fat) Mach-O file holds one slice per CPU. An arm64 app on an Apple silicon Mac cannot load a .dylib that has only an x86_64 slice. ELF Viewer & PE Viewer opens the file in VS Code on any OS. For a universal file the Overview says Mach-O universal (fat) and lists the architectures, for example x86-64, ARM64, and a picker at the top reads each slice on its own. Zovo Pro (USD 19 once) adds a compare of two builds, slice by slice, with 3 free tries.

Steps in VS Code

  1. Install ELF Viewer & PE Viewer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-elf-pe-viewer.
  2. Click the .dylib file in the Explorer. It opens in the viewer. For a macOS executable with no extension or a .bundle file, right-click it and pick "Open in ELF & PE Viewer".
  3. Read the Overview. A universal file shows Format Mach-O universal (fat) and an Architectures row, such as x86-64, ARM64. A file with one architecture shows a single Architecture row instead.
  4. Pick an architecture in the picker at the top. The tabs then show that slice, with its header, load commands, segments, libraries, imports, exports and symbols.
  5. Check the Platform row of each slice for the platform, the minimum OS version and the SDK.
  6. Open the Architectures tab for the CPU type, subtype, offset, size and alignment of each slice.

  4. Then use it the same way as in VS Code.

What ELF Viewer & PE Viewer handles

  • Mach-O 32-bit and 64-bit files in either byte order, thin or universal, with up to 16 slices.
  • ARM64, ARM64e, x86-64, x86-64h, ARMv7, ARMv7s and x86 slices.
  • Dylibs, bundles, executables and object files, with install name, RPATH, UUID and code signature size.
  • Linux ELF and Windows PE files in the same viewer.

What it does not do

  • Static libraries (.a archives) are not read, also when they are universal.
  • The viewer reads the code signature size but does not check the signature.
  • No disassembly. Tables stop at 100,000 rows each.
  • Files on remote or virtual file systems are read up to 256 MB.

Other options

  • lipo. On a Mac with the Xcode command line tools, lipo -archs libfoo.dylib prints the architectures, such as x86_64 arm64.
  • file. On macOS and Linux, file libfoo.dylib says "Mach-O universal binary with 2 architectures" and names them.

Questions

What does "universal" mean?

The file holds one Mach-O image per CPU, glued together behind a small header. macOS loads the slice that matches the process.

Can I check a dylib on Windows or Linux?

Yes. The extension reads the file itself, so it works on any OS where VS Code runs.

Why does my app say "incompatible architecture" when it loads a library?

The library has no slice for the CPU of the process, such as an arm64 app that loads an x86_64-only dylib. The Architectures row shows which slices the file has.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
