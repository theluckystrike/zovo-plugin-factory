Squash several commits in VS Code

Git Commit Graph & History Log shows your repository as a graph in VS Code. Click the newest commit you want to join, Shift+click the oldest, and pick Squash These Commits…. You type the first line of the new message, then a preview shows the git rebase -i command and its todo list before anything runs. Git does the work, so the result is the same as on the command line. Steps in VS Code

  1. Install Commit Graph from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-git-commit-graph.
  2. Run "Commit Graph: Show Commit Graph" from the Command Palette, or click the Graph button in the status bar or in Source Control.
  3. Click the newest commit you want to join, then Shift+click the oldest. Both must be on the checked-out branch. Commit or stash uncommitted changes first.
  4. Click Squash These Commits… below the graph, or right-click the range and pick Squash N Selected Commits…. Type the first line of the new message. The full messages of the squashed commits follow as the body.
  5. Read the preview. It shows the git rebase -i --no-autosquash command, the todo list, the commits and how many later commits are replayed unchanged. Click Squash.
  6. If git stops on a conflict, a bar shows Continue, Skip and Abort.

What Commit Graph handles

  • A straight range of commits, also when later commits sit on top. They are replayed unchanged.
  • Squash merge of a branch (git merge --squash), which stages the changes for you to commit.
  • Reset soft, mixed or hard, with the git command shown first and a warning for hard.
  • Continue, Skip and Abort when a rebase, merge or cherry-pick stops on a conflict.

What it does not do

  • Squash works on a straight line of commits on the checked-out branch. A merge commit in the range, or between the range and HEAD, stops it with a message.
  • Uncommitted changes to tracked files must be committed or stashed first.
  • Push in the graph is a normal git push. After you squash commits that are already on a remote, git refuses it, and you need a force push.
  • Squash rewrites the commits of the current branch. The old commits stay only in the reflog, for a while.

Other options

  • git rebase -i in a terminal. Free. Mark the commits as squash or fixup in the todo list that opens in your editor.
  • Git in a terminal. Free. git reset --soft HEAD~3 and then git commit join the last 3 commits into one, with a new message.
  • GitLens. A VS Code extension with a visual editor for git rebase -i todo lists.

Questions

What if I already pushed the commits?

Squash rewrites them, so a normal push is refused. Run git push --force-with-lease in a terminal, or turn on git.allowForcePush and run "Git: Push (Force)" in VS Code. Do this only on a branch nobody else builds on.

Can I undo a squash?

Yes, for a while. The old commits stay in the reflog. Run git reflog, find the commit from before the squash and run git reset --hard with its hash.

Is squash free?

Yes. The graph, search, squash and every git action are free. Only the interactive rebase editor, the branch comparison report and saved graph filters are Zovo Pro, with 3 free tries each.
