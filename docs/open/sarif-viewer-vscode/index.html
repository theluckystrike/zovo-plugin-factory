Open a SARIF file in VS Code

Install the free SARIF Viewer by Zovo and click the .sarif file. The results open as a table grouped by rule, worst first. Click a result to open its line. Paths from CI such as /home/runner/work/app/app/src/db.js are matched to your workspace. You can step through code flows, show only new results against a baseline, and compare two logs.

Install in VS CodeMarketplace pageOpen VSX (Cursor, Windsurf, VSCodium)JetBrains IDEs

Free, MIT license. Extension ID zovo.zovo-sarif-viewer, version 0.1.0. Needs VS Code 1.90.0 or newer.

Steps in VS Code

  1. Install SARIF Viewer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-sarif-viewer.
  2. Click a .sarif or .sarif.json file. No log at hand? Run "SARIF: Open a Sample SARIF Log".
  3. Pick how to group results: by rule, file, level, tool or baseline state.
  4. Click a result to open its line. Use Previous and Next (Alt+Up and Alt+Down) to walk through a code flow.
  5. Click "Compare..." to mark each result new, unchanged or fixed against an older log, or "Show in Problems" to list the results in the Problems panel.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-sarif-viewer and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-sarif-viewer.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What SARIF Viewer handles

  • SARIF 2.1.0 from CodeQL, Semgrep, ESLint, Bandit, Trivy, Checkov, Gitleaks and other tools. 2.0 files open with a note.
  • Filters for level, baseline state, suppressions with their justification, tool and text.
  • Rule help rendered from Markdown, CWE links, security severity and fingerprints in the details pane.
  • In the release check, a 150 MB log with 313,079 results showed its first rows after 1.5 s.

What it does not do

  • It reads logs. It does not run a scanner or fetch alerts from GitHub.
  • Logs over 300 MB ask before they open, and logs over 500 MB show a message.
  • Raw HTML in rule help shows as text, and only http and https links can be clicked.

In JetBrains IDEs (IntelliJ IDEA, PyCharm, WebStorm, CLion and others)

Questions

Why does a result from CI not open the file?

The log holds paths from the CI machine. SARIF Viewer maps them to your workspace with a few file checks and remembers the match. If a file is not found, "Locate file" asks you once.

Can I see only the new results?

Yes. Filter by baseline state to show only new results, or compare the log with an older one by fingerprint.

Is it safe to open a log someone else made?

Yes. Rule help is escaped before it is shown, results outside your workspace ask before they open, and the viewer makes no network requests.
