Open a JAR and read the decompiled Java source in VS Code

JAR Viewer & Java Decompiler opens .jar, .war, .ear, .aar and .class files in VS Code. Click a class to read its Java source, decompiled by the bundled CFR 0.152 with the Java 8 or newer runtime on your computer, or its bytecode as a javap -c -p style listing that needs no Java. Every view is free. Zovo Pro (USD 19 once) adds export of all decompiled sources of a JAR, compare two JARs and a search across every JAR of a folder, with 3 free tries each.

Steps in VS Code

  1. Install JAR Viewer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-jar-viewer.
  2. Click a .jar, .war, .ear, .aar or .class file in the Explorer. It opens in the viewer. The Overview shows the class and package counts, Main-Class, "Created by" and a chart of the Java versions the classes were compiled for.
  3. Type part of a name in the filter box above the package tree. It finds classes and files as you type. Inner classes sit dimmed under their outer class.
  4. Click a class. The Java source tab shows it decompiled with CFR 0.152, with its inner classes. Copy puts the source on the clipboard, and Open in editor opens it in a normal editor tab.
  5. If no Java is found, a clicked class opens on the Bytecode tab, and the Java source tab says "Decompiled Java source needs a Java runtime (8 or newer)". Set jarViewer.javaPath to a java binary or a JDK folder, or set JAVA_HOME. "JAR Viewer: Check the Java runtime used for decompiling" shows which Java it uses.
  6. Open the Bytecode tab for a javap -c -p style listing with every opcode, the exception tables and the line numbers. Members, Constant pool and Class info show the declarations, the constant pool entries and the class attributes.
  7. In a Spring Boot JAR or a WAR, click a JAR inside BOOT-INF/lib or WEB-INF/lib to select it, then click Open nested archive (or Open in the Overview's "Nested archives" list). It opens one level deep, and a button takes you back to the outer archive.

Where Zovo Pro saves time

The package tree, the overview, decompiled source, bytecode, members, constant pool, class info, resources and nested JARs are free, with no sign-in. CFR comes with the extension and runs on the Java already on your computer, in its own process with a 45-second limit. The archive is read in a worker thread and never changed, and the extension makes no network calls.

When you want a whole library as source, to search it or read it in your editor, this tool decompiles every class of the JAR and saves a folder of .java files, with progress and Cancel. With no Java runtime it saves bytecode listings instead. The other two Pro tools compare two JARs (classes added, removed and changed, method and field signatures and Java versions, as a Markdown report) and find a class, method, field or string in every JAR of a folder.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-jar-viewer and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-jar-viewer.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What JAR Viewer handles

  • JAR, WAR, EAR and AAR archives, and single .class files with their inner classes from the same folder.
  • Archives with up to 200,000 entries, and a filter that finds a class among 50,000 entries as you type.
  • Generic signatures, records, permitted subclasses, nest hosts and annotations in the class data.
  • Spring Boot BOOT-INF/lib, WAR WEB-INF/lib and AAR classes.jar archives, one level deep.

What it does not do

  • Decompiled source needs Java 8 or newer on your computer. Without it, every other view still works.
  • CFR output can differ from the original source, for example in local variable names, some generics and lambdas.
  • Entries are unpacked up to 64 MB each, class files up to 16 MB and nested archives up to 128 MB.
  • It is read-only, so you cannot edit or recompile a class. APK and DEX files are not read.

Other options

  • javap. Comes with the JDK. javap -c -p prints the bytecode of a class in a terminal. It does not decompile to Java source.
  • CFR on the command line. The same free decompiler, run as java -jar cfr.jar app.jar to print the sources of a whole JAR.
  • JD-GUI. A free desktop app that shows the decompiled source of a JAR, outside VS Code.

Questions

Why does the Java source tab ask for Java?

CFR is a Java program. The viewer looks for Java in jarViewer.javaPath, then JAVA_HOME, then java on your PATH. Any Java 8 or newer runtime works.

Can I read the bytecode without Java?

Yes. The Bytecode, Members, Constant pool and Class info tabs are read in JavaScript and need no Java.

Is decompiling free?

Yes. Decompiling one class at a time is free, for as many classes as you like. Saving the sources of a whole JAR at once is a Zovo Pro tool with 3 free tries.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
