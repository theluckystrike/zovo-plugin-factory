Why server-level add_header lines vanish inside a location

In nginx, add_header lines are inherited from the outer block only when the inner block has no add_header of its own. So a location that adds one header, such as Cache-Control, drops every header of the server block, including HSTS. Repeat the headers in that location, or put them in a file and include it everywhere. The Security audit of Nginx Config Formatter & Lint lists each location where security headers are lost, with file and line. It is part of Zovo Pro (USD 19 once), with 3 free tries.

Steps in VS Code

  1. Install Nginx Config Formatter & Lint from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-nginx-config.
  2. Find the locations that have their own add_header. The config overview ("Nginx: Show Config Overview") lists every location with its file and line.
  3. In each one, repeat the add_header lines of the server block, or move them to a file such as snippets/security-headers.conf and include it in the server and in each location that has add_header.
  4. Add always to a header that must also be sent with error responses. Without it, add_header applies only to some success and redirect codes.
  5. Run nginx -t, reload nginx, and check the response with curl -I on a URL that this location serves.
  6. To find every location that loses security headers, run the Security audit. Each finding gives the file, the line and the headers that are lost.

What Nginx Config Formatter & Lint handles

  • add_header in the http block, the server block and nested locations.
  • Locations that pull in their add_header lines from include files.
  • The headers Strict-Transport-Security, X-Content-Type-Options and X-Frame-Options (or a Content-Security-Policy with frame-ancestors).

What it does not do

  • The audit reports lost headers only for those three security headers. A lost Cache-Control or CORS header is not reported.
  • It reads your files. It does not run nginx or check the headers your server really sends.
  • An include that matches no file is named at the top of the report and not checked.

Other options

  • gixy. A free command line analyzer for nginx configs. Its add_header_redefinition check finds the same problem.
  • headers-more module. An nginx module whose more_set_headers works differently from add_header. It needs a build or a package with the module.

Questions

Why does one add_header in a location remove the others?

nginx inherits add_header lines only when the current block has none. One add_header in the location replaces the whole list from the server block.

Is an include file a good fix?

Yes. Put the shared headers in one file and include it in the server block and in every location that has its own add_header.
