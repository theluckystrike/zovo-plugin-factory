Browse Azurite from a Dev Container or Codespace

Azure Storage & Blob Explorer runs inside the VS Code extension host in plain JavaScript, with no desktop Storage Explorer, no AzCopy and no native module, so it works in a Dev Container, a Codespace, Remote SSH and WSL. Azurite in the same container is one click away on 127.0.0.1, and an Azurite service in Docker Compose connects by its service name. Browsing, upload, download, queues and tables are free. Steps in VS Code

  1. Install Azure Storage & Blob Explorer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-azure-storage-explorer.
  2. Start Azurite where your code runs. In a Dev Container or Codespace terminal, "Azure Storage: Start Azurite in a Terminal" starts it with npx for you. In Docker Compose, run the mcr.microsoft.com/azure-storage/azurite image as its own service with --disableProductStyleUrl.
  3. Open the Azure Storage view in the Activity Bar. For Azurite in the same container or Codespace, run "Connect to Azurite (Local Emulator)". It connects to 127.0.0.1 on ports 10000, 10001 and 10002 with the Azurite account.
  4. For Azurite in another container, click Add Connection, pick "Azurite on another host" and type the service name, such as azurite, or its IP address.
  5. Expand Blob Containers, Queues or Tables. Text and JSON blobs open in an editor tab, and Save writes them back. Upload Files..., Upload Folder... and Download... are in the right-click menu.
  6. If Azurite listens on other ports, click Add Connection and paste a connection string with the Azurite account, key and your own BlobEndpoint, QueueEndpoint and TableEndpoint.

Steps in Cursor, Windsurf or VSCodium

  1. Open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on macOS).
  2. Search for zovo.zovo-azure-storage-explorer and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-azure-storage-explorer.
  3. If your editor has no gallery, download the .vsix from the Open VSX page and run "Extensions: Install from VSIX...".
  4. Then use it the same way as in VS Code.

What Azure Storage & Blob Explorer handles

  • Azurite on 127.0.0.1 in the same container or Codespace, in one click.
  • Azurite on another host, such as a Docker Compose service named azurite.
  • Blob containers with folders, queues (peek, send, dequeue, clear) and tables (OData query, edit in a grid).
  • Real Azure accounts with a connection string, an account key, a SAS URL or Microsoft Entra ID.

What it does not do

  • "Azurite on another host" uses ports 10000 to 10002. For other ports, paste a connection string with your own endpoints.
  • Azurite reached by a host name such as azurite answers 400 unless it runs with --disableProductStyleUrl. Connecting by IP address works too.
  • "Start Azurite in a Terminal" uses npx, so the container needs Node.js and npm.
  • Text blobs over 10 MB ask first and can show only the first 1 MB (setting azureStorage.maxTextPreviewMB).

Other options

  • Microsoft Azure Storage Explorer. The free desktop app from Microsoft. It runs on your computer, so it reaches Azurite in a container only through a forwarded port.
  • Azure Storage extension by Microsoft. Microsoft's own VS Code extension. Marketplace reviews and GitHub issues report problems with it in Codespaces.
  • Azure CLI. Free. az storage commands take an Azurite connection string. Good for scripts, with no tree view.

Questions

Why does 127.0.0.1 not reach my Azurite container?

The extension runs where your workspace runs. In a Dev Container that is the container, so 127.0.0.1 is the container itself. If Azurite is a separate Compose service, use "Azurite on another host" with its service name.

Do I need an Azure account?

No. Azurite needs no sign-in. For real accounts, a connection string, an account key or a SAS URL also works without an Azure sign-in.

Is this Microsoft's extension?

No. It is an independent extension by Zovo, not made by or affiliated with Microsoft.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
