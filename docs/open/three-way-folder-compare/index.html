Compare and merge three folders (base, yours, theirs)

When two people changed copies of the same folder outside git, a two-way compare cannot tell who changed what, so a three-way compare uses the common original as the base. Folder Compare & Directory Diff compares the base with your copy and with theirs, writes a report of what changed on each side, and can copy the one-sided changes into the base. Files changed differently on both sides are listed as conflicts and left for you. Three-way compare and merge is a Zovo Pro tool (USD 19 once) with 3 free tries.

Steps in VS Code

  1. Install Folder Compare & Directory Diff from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-folder-diff.
  2. Right-click the base folder in the Explorer and pick "Zovo Pro: Three-way compare and merge", or run "Folder Compare: Three-Way Folder Compare and Merge (Zovo Pro)...". In an open compare it is under More.
  3. Pick the folders when asked. First the BASE (the common original), then the LEFT copy (yours), then the RIGHT copy (theirs). If you started from the base folder, you pick only the two copies.
  4. Read the report in the Markdown tab. It lists the conflicts, the files changed on the left only, on the right only, and the files changed the same way on both sides.
  5. Click "Merge N into Base" to copy the one-sided changes into the base folder. A file deleted on one side is deleted in the base, to the Trash by default. Conflicts stay as they are.
  6. Resolve each conflict by hand. Open the two copies of the file in the VS Code diff (Select for Compare, then Compare with Selected) and save the result in the base.

  2. Search for zovo.zovo-folder-diff and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-folder-diff.

What Folder Compare & Directory Diff handles

  • Files added, changed or deleted on either side.
  • Files changed the same way on both sides, which are not conflicts.
  • Any kind of file, compared by content.
  • Folders on this computer, or on the remote machine in a Remote window.

What it does not do

  • The merge works on whole files. A file changed on both sides is a conflict even when the changes are in different lines, and it is not merged line by line.
  • The merge writes into the base folder. Copy the base first if you want to keep the original.
  • Conflicts are only listed in the report. You resolve them yourself.
  • Files left out by the ignore rules, such as node_modules, .git and dist, are not compared.

Questions

Which folder gets changed?

Only the base folder, and only after you confirm the list. Your copy and theirs are never written.

Does it merge changes inside a file?

No. It works file by file. A file changed on both sides is a conflict that you merge by hand.

What if both sides made the same change?

Those files are listed as changed the same way on both sides, not as conflicts.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
