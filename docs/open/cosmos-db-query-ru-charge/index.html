See the request charge (RU) of a Cosmos DB query

Request units (RU) are what a Cosmos DB query costs, and the server reports the charge with each page of results. Cosmos DB Client shows it above the results of every page, with the running RU total, documents loaded against returned, the index hit ratio and the server times. You connect with a connection string or the local emulator, with no Azure sign-in, and all of this is free. Zovo Pro (USD 19 once) adds the Query Cost Report, which runs the query to the end and writes the total RU, index advice and plain hints, with 3 free tries.

Steps in VS Code

  1. Install Cosmos DB Client from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-cosmos-db-client.
  2. Open the Cosmos DB view in the activity bar. Click Connect to Local Emulator, or Add Connection and paste the connection string from Keys in the Azure portal.
  3. Click a container to run SELECT * FROM c, or click New Query and write your own query in a .nosql file. Press Ctrl+Enter (Cmd+Enter on macOS).
  4. Read the line above the grid. It shows the items loaded, the RU total, the RU of the last page, documents retrieved against output and the index hit ratio. Open "Query metrics, page 1" for the server times.
  5. Click Load more to read the next page with the continuation token and see the RU total grow. Load all keeps going until you click Stop.
  6. To compare costs, type a value in Partition key in the results toolbar, run the query again and compare the RU with the query across all partitions.

Where Zovo Pro saves time

Connections, queries with RU and metrics on every page, paging, editing items with an ETag check, export to JSON, JSONL or CSV, import of JSON or JSONL and the read-only switch are free. The extension talks only to the Cosmos DB endpoints you add.

The RU of one page does not tell you what the whole query costs, or why. Query Cost Report runs the query to the end (up to 200 pages by default) and writes a Markdown report with the total RU, RU per item and per page, documents loaded against returned and the index hit ratio. It adds the indexes the server suggests, an indexing policy with them, and plain hints such as a missing partition key filter or a deep OFFSET. The other Pro tool, Copy Container, streams every item of a container to another container or account.

  4. Then use it the same way as in VS Code.

What Cosmos DB Client handles

  • Azure Cosmos DB for NoSQL accounts and the local emulator.
  • Query parameters, written as SQL comment lines: two dashes, then a name and value such as @status = "open".
  • Hierarchical partition keys, typed as a JSON array in the Partition key box.
  • Numbers above 2^53, kept exact.

What it does not do

  • Only the NoSQL API. The MongoDB, Cassandra, Gremlin and Table APIs are not covered.
  • One results view keeps up to 50,000 items (setting zovoCosmos.maxLoadedItems). Export streams every item.
  • Every query you run, including Load all, uses RU on your account.

Other options

  • Data Explorer in the Azure portal. The portal's Data Explorer also shows the request charge and query stats of a query. It needs an Azure sign-in.
  • Azure Cosmos DB extension (Microsoft). Microsoft's own Cosmos DB extension for VS Code. It is not on Open VSX, so Cursor and VSCodium cannot install it from there.

Questions

Do I need an Azure sign-in?

No. A connection string, an endpoint and key, or the local emulator is enough. Microsoft Entra ID is optional.

Why does Load all cost more RU?

Each page is a separate request with its own charge. Load all reads every page, so the total is the sum of all of them.

Does it work with the emulator in Docker?

Yes. Click Connect to Local Emulator. The emulator's self-signed certificate is accepted for localhost only.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
