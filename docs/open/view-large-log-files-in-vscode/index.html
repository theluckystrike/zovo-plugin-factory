Open and search a large log file in VS Code

Log Viewer & Log File Analyzer opens .log files of any size in VS Code. A 2 GB log opens in seconds, because the file is indexed by streaming and only the lines on screen are read. Levels are colored, stack traces stay with their error, you filter by text, /regex/ or a time range, and Follow shows new lines as the file grows, like tail -f. All of that is free, with no network calls. Zovo Pro (USD 19 once) adds pattern and error spike reports, merging log files by time and exporting filtered lines, with 3 free tries each.

Steps in VS Code

  1. Install Log Viewer & Log File Analyzer from the Marketplace, or press Ctrl+P (Cmd+P on macOS) and run ext install zovo.zovo-log-viewer.
  2. Click a .log file (or .log.1 and other rotated names). It opens in Log Viewer. For any other file, right-click it and pick Open in Log Viewer.
  3. Click the level chips to show or hide errors, warnings, info, debug and trace. Alt+click a chip to show only that level.
  4. Type in the filter box to keep matching lines, as text or as /regex/. Fill From and To with times such as 10:00 and 10:30, or -15m for the last 15 minutes. A match inside a stack trace keeps the whole entry.
  5. Click a line to see the whole entry in the detail pane, with a JSON line shown as pretty JSON. Use Go to time or line to jump, and Newest first to turn the order around.
  6. Click Follow to watch the file grow, like tail -f. Rotated or truncated files are read again. Open as text switches back to the normal editor.

Steps in Cursor, Windsurf or VSCodium

  2. Search for zovo.zovo-log-viewer and click Install. Cursor, Windsurf and VSCodium install from Open VSX, where it is published as zovo/zovo-log-viewer.

  4. Then use it the same way as in VS Code.

What Log Viewer & Log File Analyzer handles

  • Levels from plain text, JSON ("level", pino and bunyan numbers), syslog priorities and Android logcat.
  • Timestamps in ISO 8601, syslog, Apache, logcat, Log4j, HDFS, Spark and JSON fields (time, ts, @timestamp, epoch ms).
  • Lines up to 64 KB shown in full, and files that never load into memory.
  • Local files, including Remote SSH and WSL folders.

What it does not do

  • Files are read as UTF-8. UTF-16 logs, written by some Windows tools, show as garbled text.
  • Lines longer than 64 KB are cut in the view, not in the file.
  • Formats without a year (syslog, logcat) take the year the file was last written.
  • The index takes about 22 bytes of memory per line, so 50 million lines need about 1.1 GB (setting zovoLog.maxLines). Virtual file systems are not supported.

Questions

Why does VS Code refuse to open my large log file?

VS Code loads the whole file into the editor, and it turns off features or asks before it opens very large files. Log Viewer indexes the file instead and reads only the lines on screen.

Does it upload my logs?

No. It reads your file and nothing else, with no network calls and no telemetry. Reports and exports are written only where you choose.

Can I tail a log in VS Code?

Yes. Click Follow and new lines appear as the file grows. Rotated or truncated files are read again.

Does it work in Cursor or Windsurf?

Yes. Cursor, Windsurf and VSCodium install extensions from Open VSX. Search for the extension in their Extensions view and install it there.
