คู่มือภาษาไทย

จัดรูปแบบและตรวจไฟล์ config ของ nginx ใน VS Code

ติดตั้ง Nginx Config Formatter & Lint ซึ่งใช้ได้ฟรี เปิดไฟล์ config ของ nginx แล้วกด Shift+Alt+F (บน Mac กด Shift+Option+F) formatter จะ parse ผลลัพธ์ของตัวเอง และไม่เปลี่ยนอะไรถ้าไฟล์จะอ่านได้ไม่เหมือนเดิม config ที่ถูกต้องจึงยังถูกต้อง สีไวยากรณ์ การแจ้งปัญหาขณะพิมพ์พร้อม quick fix, hover help สำหรับ directive ราว 300 ตัว, completion, outline และภาพรวม config ข้ามไฟล์ include ใช้ได้ฟรีและทำงานบนเครื่องของคุณ Zovo Pro (19 ดอลลาร์สหรัฐ จ่ายครั้งเดียว) เพิ่มเครื่องมือ 3 ตัว คือ Security Audit, Location Tester และ Convert .htaccess to nginx และแต่ละตัวลองใช้ฟรีได้ 3 ครั้ง

ขั้นตอนใน VS Code

  1. ติดตั้ง Nginx Config Formatter & Lint จาก Marketplace หรือกด Ctrl+P (Cmd+P บน macOS) แล้วรัน ext install zovo.zovo-nginx-config
  2. เปิดไฟล์ config ไฟล์จะเปิดเป็น nginx เมื่อชื่อ nginx.conf หรือลงท้ายด้วย .nginx หรือ .nginxconf หรือเป็นไฟล์ .conf ในโฟลเดอร์ชื่อ nginx (เช่น /etc/nginx/conf.d/default.conf) หรือเป็นไฟล์ใน nginx/sites-available, nginx/sites-enabled หรือ nginx/snippets สำหรับไฟล์อื่น ให้เลือก "nginx" เป็น language mode
  3. กด Shift+Alt+F (บน Mac กด Shift+Option+F) คุณจะได้หนึ่ง statement ต่อบรรทัดตามการเยื้องของ editor ค่า log_format ที่ยาวยังคงการขึ้นบรรทัดไว้ และบรรทัดว่างติดกันจะเหลือไม่เกินหนึ่งบรรทัด (การตั้งค่า nginxConfig.format.maxBlankLines)
  4. ปัญหาจะแสดงขณะพิมพ์ ได้แก่ ; ที่หายไป ปีกกาที่ไม่ปิดหรือเกิน สตริงที่ไม่ปิด directive ที่อยู่ผิดบล็อก root หรือ listen ซ้ำ และสอง server ที่ชื่อเดียวกันบนพอร์ตเดียวกัน กด Ctrl+. (บน Mac กด Cmd+.) เพื่อใช้ quick fix เช่น "Add the missing ";"" หรือแก้ proxy_set_heder เป็น proxy_set_header
  5. hover ที่ directive เพื่อดูไวยากรณ์ ค่าเริ่มต้น บล็อกที่ใช้ได้ และลิงก์ไปยังเอกสารของ nginx completion จะเสนอ directive ที่ใช้ได้ในบล็อกปัจจุบัน และตัวแปรหลัง $
  6. คลิกไอคอนรายการในแถบชื่อ editor หรือรัน "Nginx: Show Config Overview" เพื่อดูทุก server พร้อมพอร์ตและชื่อ และทุก location พร้อมสิ่งที่ location นั้นทำ ข้ามไฟล์ include คลิกไฟล์และบรรทัดเพื่อไปที่นั่น

อะไรใช้ฟรี และ Zovo Pro เพิ่มอะไร

สีไวยากรณ์ (บล็อก Lua ใช้สีแบบ Lua), Format Document, การแจ้งปัญหาพร้อม quick fix, hover help, completion, outline และภาพรวม config ใช้ได้ฟรี ทุกอย่างทำงานบนเครื่องของคุณ โดยไม่มีการเรียกเครือข่าย

Security Audit ตรวจ config พร้อมไฟล์ include ทั้งหมด และแสดงแต่ละรายการที่พบพร้อมไฟล์ บรรทัด เหตุผลที่สำคัญ และวิธีแก้ โดยเรียงเป็นระดับ high, medium และ low สิ่งที่ตรวจได้แก่ TLS 1.0 และ 1.1, cipher ที่อ่อน, server HTTPS ที่ไม่มี HSTS และ security header อื่น, location ที่มี add_header ของตัวเองซึ่งทำให้ header เหล่านั้นหายไปโดยไม่รู้ตัว, path traversal แบบ off-by-slash ของ alias, proxy_pass ไปยัง host ที่มาจาก request, ไฟล์ .git และ .env ที่ถูกเสิร์ฟ, การแสดงรายการโฟลเดอร์ และ request body ที่ไม่จำกัดขนาด คุณจึงเจอข้อผิดพลาดเหล่านี้ก่อน config ขึ้น production โดยไม่ต้องอ่านไฟล์ include ทุกไฟล์เอง

วิธีใช้ Security Audit (Zovo Pro)

  1. คลิก "Security audit" ในแถว Pro tools ของแถบเครื่องมือในภาพรวม config หรือคลิกขวาที่ไฟล์ .conf หรือ .nginx ใน Explorer แล้วเลือก "Zovo Pro: Security audit" หรือรัน "Nginx: Security Audit (Pro)" จาก Command Palette
  2. ผล audit จะเปิดข้าง editor แต่ละรายการแสดงไฟล์และบรรทัด เหตุผล และวิธีแก้ คลิกไฟล์และบรรทัดเพื่อไปที่นั่น
  3. คลิก "Save report" เพื่อเก็บผลเป็นไฟล์ Markdown
  4. ระบบนับการลองใช้เฉพาะเมื่อ audit แสดงผลแล้ว การกด Escape หรือไฟล์ที่ไม่มีบล็อก http หรือ server จะไม่เสียสิทธิ์

Security Audit ใช้ได้ฟรี 3 ครั้งบนเครื่องของคุณก่อนจะขอไลเซนส์ ไม่มีป๊อปอัปและไม่มีการนับถอยหลัง

ขั้นตอนใน Cursor, Windsurf หรือ VSCodium

  1. เปิดมุมมอง Extensions ด้วย Ctrl+Shift+X (Cmd+Shift+X บน macOS)
  2. ค้นหา zovo.zovo-nginx-config แล้วคลิก Install ทั้ง Cursor, Windsurf และ VSCodium ติดตั้งส่วนขยายจาก Open VSX ซึ่งส่วนขยายนี้ใช้ชื่อ zovo/zovo-nginx-config
  3. ถ้า editor ของคุณไม่มีหน้าค้นหาส่วนขยาย ให้ดาวน์โหลดไฟล์ .vsix จากหน้า Open VSX แล้วรัน "Extensions: Install from VSIX..."
  4. จากนั้นทุกอย่างใช้งานได้เหมือนใน VS Code

Nginx Config Formatter & Lint ทำอะไรได้บ้าง

  • directive ของ OpenResty/Lua, headers-more, Brotli, Passenger และโมดูลทั่วไปอื่น ๆ เป็นที่รู้จักและไม่ถูกแจ้งเป็นปัญหา
  • บล็อก Lua เช่น content_by_lua_block ใช้สีแบบ Lua
  • มุมมอง Outline แสดง server พร้อมชื่อและพอร์ต location, upstream และ map
  • include แบบ relative อ่านจาก nginxConfig.prefix, โฟลเดอร์ของไฟล์, โฟลเดอร์แม่ หรือ /etc/nginx ตามลำดับ
  • การแก้ไขที่ยังไม่บันทึกใน editor ที่เปิดอยู่ถูกใช้โดยภาพรวม config และเครื่องมือ Pro

สิ่งที่ยังทำไม่ได้

  • formatter ใส่ช่องว่างหนึ่งช่องระหว่าง directive กับค่า การจัดให้ตรงคอลัมน์อย่าง listen 80; จึงไม่ถูกคงไว้
  • ไฟล์ที่มีปีกกาหรือสตริงที่ไม่ปิดจะไม่ถูกจัดรูปแบบ ไฟล์จะไม่ถูกเปลี่ยน และแถบสถานะจะบอกเหตุผล
  • การตรวจอ่านไฟล์ของคุณและไม่ได้รัน nginx -t ไฟล์ certificate ที่หายไปหรือโมดูลที่ไม่ได้โหลดจะเจอได้โดย nginx เองเท่านั้น
  • regex ของ location ทดสอบด้วย regular expression ของ JavaScript feature บางอย่างที่มีเฉพาะใน PCRE (possessive quantifier, recursion) ทดสอบไม่ได้และจะรายงานว่าข้ามไป

คำถามที่พบบ่อย

ใช้ฟรีไหม

การจัดรูปแบบ การแจ้งปัญหาพร้อม quick fix, hover help, completion, outline และภาพรวม config ใช้ได้ฟรี เครื่องมือ Pro 3 ตัว คือ Security Audit, Location Tester และ Convert .htaccess to nginx ลองใช้ฟรีได้ตัวละ 3 ครั้ง หลังจากนั้นต้องใช้ Zovo Pro ราคา 19 ดอลลาร์สหรัฐ จ่ายครั้งเดียวสำหรับส่วนขยาย Zovo ทุกตัว

การจัดรูปแบบทำให้ config เสียได้ไหม

ไม่ได้ formatter จะ parse ผลลัพธ์ของตัวเอง และไม่เปลี่ยนอะไรถ้าไฟล์จะอ่านได้ไม่เหมือนเดิม config ที่ถูกต้องจึงยังถูกต้อง

ใช้แทน nginx -t ได้ไหม

ไม่ได้ ส่วนขยายอ่านไฟล์ของคุณและตรวจไวยากรณ์กับตำแหน่งของแต่ละ directive ให้รัน nginx -t บนเซิร์ฟเวอร์เพื่อตรวจ certificate และโมดูล

ใช้ใน Cursor ได้ไหม

ได้ Cursor, Windsurf และ VSCodium ติดตั้งได้จาก Open VSX ซึ่งเผยแพร่ในชื่อ zovo/zovo-nginx-config
