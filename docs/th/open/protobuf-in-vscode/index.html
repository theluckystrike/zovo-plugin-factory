คู่มือภาษาไทย

แก้ไฟล์ .proto ใน VS Code พร้อมไฮไลต์ จัดรูปแบบ และ go to definition

ติดตั้ง Protobuf & Proto3 Formatter ซึ่งใช้ได้ฟรี แล้วเปิดโฟลเดอร์ที่มีไฟล์ .proto ส่วนขยายเพิ่มการไฮไลต์ formatter ที่เก็บ comment ไว้ทุกบรรทัด, go to definition, find references และ error ที่ใช้ถ้อยคำแบบ protoc สำหรับ proto2, proto3 และ editions 2023 และ 2024 ทำงานออฟไลน์ด้วย parser ของตัวเอง จึงไม่ต้องมี protoc ไม่ต้องมี language server และไม่ต้องตั้งค่า และทั้งหมดนี้ใช้ได้ฟรี Zovo Pro (19 ดอลลาร์สหรัฐ จ่ายครั้งเดียว) เพิ่มเครื่องมือ 3 ตัว คือ Check Breaking Changes Against Git, Generate API Docs และ Decode a Binary Message และแต่ละตัวลองใช้ฟรีได้ 3 ครั้ง

ติดตั้งใน VS Codeหน้า MarketplaceOpen VSX (Cursor, Windsurf, VSCodium)

ใช้ฟรี ไลเซนส์ MIT รหัสส่วนขยาย zovo.zovo-protobuf เวอร์ชัน 0.1.0

ขั้นตอนใน VS Code

  1. ติดตั้ง Protobuf & Proto3 Formatter จาก Marketplace หรือกด Ctrl+P (Cmd+P บน macOS) แล้วรัน ext install zovo.zovo-protobuf
  2. เปิดโฟลเดอร์ที่มีไฟล์ .proto การไฮไลต์ outline และ breadcrumbs จะทำงานทันที
  3. กด Shift+Alt+F (บน macOS กด Shift+Option+F) เพื่อจัดรูปแบบ หรือเปิด editor.formatOnSave คุณจะได้หนึ่ง statement ต่อบรรทัด การเยื้องตาม editor ของคุณ และช่องว่างหนึ่งช่องรอบ = comment กลุ่มบรรทัดว่าง และการขึ้นบรรทัดที่คุณเขียนไว้ใน statement ยาว ๆ อยู่ที่เดิม
  4. กด F12 ที่ type หรือ import เพื่อไปยัง definition และกด Shift+F12 เพื่อดูรายการที่ใช้ type นั้น กด Ctrl หรือ Cmd แล้วคลิก import เพื่อเปิดไฟล์ hover ที่ type เพื่อดู field และ comment ของ type นั้น
  5. error จะแสดงในแผง Problems ด้วยถ้อยคำแบบ protoc ได้แก่ field number ซ้ำ (พร้อมหมายเลขว่างถัดไป) type ที่ไม่รู้จัก type ที่ใช้โดยไม่ได้ import หมายเลขและชื่อที่ reserved และกฎของ proto3 และ editions import ที่ไม่ได้ใช้จะเป็นสีจาง
  6. ถ้า import ของคุณเริ่มจากโฟลเดอร์อย่าง proto/ หรือ third_party/ ส่วนขยายจะหาเจอโดยไล่ขึ้นไปจากแต่ละไฟล์ สำหรับ root อื่น ให้เพิ่มไว้ในการตั้งค่า zovoProto.importPaths เหมือนที่ใช้ protoc -I

อะไรใช้ฟรี และ Zovo Pro เพิ่มอะไร

การไฮไลต์ (รวมถึงบล็อกโค้ด proto ใน Markdown), Format Document, go to definition, find references, error แบบ protoc, outline, Go to Symbol in workspace, hover และ completion ซึ่งรวมถึงหมายเลข field ว่างถัดไปหลัง = ใช้ได้ฟรี ไม่ต้องลงชื่อเข้าใช้ ไม่มีการเรียกเครือข่าย และไม่มี telemetry

ก่อน merge การแก้ไขไฟล์ .proto เครื่องมือ Check Breaking Changes Against Git จะเทียบไฟล์ของคุณกับ main (หรือ branch ที่คุณตั้งไว้) และแสดงรายการ field ที่ถูกลบ หมายเลข type และ label ที่เปลี่ยน field และค่า enum ที่เปลี่ยนชื่อ และ method ที่ถูกลบหรือเปลี่ยน แต่ละรายการบอกว่ากระทบข้อมูล binary, JSON หรือแค่โค้ดที่ generate คุณจึงเห็นว่า client เก่าจะอ่านอะไรผิดก่อนที่จะเกิดขึ้นจริง และบันทึกผลเป็นไฟล์ JSON สำหรับ CI ได้

วิธีใช้ Check Breaking Changes Against Git (Zovo Pro)

  1. คลิกขวาที่ไฟล์ .proto หรือโฟลเดอร์ใน Explorer แล้วเลือก "Zovo Pro: Check breaking changes against git" หรือคลิกขวาใน editor ของ .proto แล้วเลือก "Check Breaking Changes Against Git (Pro)" หรือรัน "Protobuf: Check Breaking Changes Against Git (Pro)" จาก Command Palette โฟลเดอร์ต้องอยู่ใน git repository และต้องติดตั้ง git ไว้
  2. การตรวจจะเทียบทุกไฟล์ .proto ของ repository ใน working tree รวมถึงการแก้ไขที่ยังไม่บันทึก กับ merge base ของ origin/main, main, origin/master หรือ master (ตัวแรกที่มีอยู่) หรือของ branch ในการตั้งค่า zovoProto.baseBranch รายงาน Markdown จะเปิดขึ้นพร้อมผลที่จัดกลุ่มตามไฟล์
  3. คลิก "Save JSON for CI" ในข้อความเพื่อเก็บผลเป็น proto-breaking.json
  4. ระบบนับการลองใช้เฉพาะเมื่อรายงานเปิดขึ้นแล้ว โฟลเดอร์ที่ไม่อยู่ใน git หรือไม่มี base branch จะไม่เสียสิทธิ์

Check Breaking Changes Against Git ใช้ได้ฟรี 3 ครั้งบนเครื่องของคุณก่อนจะขอไลเซนส์ ไม่มีป๊อปอัปและไม่มีการนับถอยหลัง

ขั้นตอนใน Cursor, Windsurf หรือ VSCodium

  1. เปิดมุมมอง Extensions ด้วย Ctrl+Shift+X (Cmd+Shift+X บน macOS)
  2. ค้นหา zovo.zovo-protobuf แล้วคลิก Install ทั้ง Cursor, Windsurf และ VSCodium ติดตั้งส่วนขยายจาก Open VSX ซึ่งส่วนขยายนี้ใช้ชื่อ zovo/zovo-protobuf
  3. ถ้า editor ของคุณไม่มีหน้าค้นหาส่วนขยาย ให้ดาวน์โหลดไฟล์ .vsix จากหน้า Open VSX แล้วรัน "Extensions: Install from VSIX..."
  4. จากนั้นทุกอย่างใช้งานได้เหมือนใน VS Code

Protobuf & Proto3 Formatter ทำอะไรได้บ้าง

  • proto2, proto3 และ editions (2023, 2024) รวมถึงบล็อกโค้ด proto ใน Markdown
  • กฎ scoping ของ protobuf สำหรับ go to definition และ find references ข้าม import ได้แก่ nested type, package และ . นำหน้า
  • ชื่อในตัวสำหรับ well-known type เช่น google/protobuf/timestamp.proto
  • ไม่มีเครื่องหมายสีแดงที่ผิด เมื่อไฟล์ที่ import ไม่อยู่ใน workspace บรรทัด import จะบอกไว้ และจะไม่เดา type ที่ไฟล์นั้นจะนำเข้ามา
  • completion สำหรับ type, keyword, option, path ของ import และหมายเลข field ว่างถัดไปหลัง =

สิ่งที่ยังทำไม่ได้

  • ชื่อ custom option ถูกตรวจว่ามี import แต่ไม่ได้ตรวจกับ field type ของ extension นั้น
  • การตรวจ feature ของ editions ครอบคลุม enum_type, label, packed และ group ส่วนกฎ feature อื่นปล่อยให้ protoc ตรวจ
  • formatter คงการขึ้นบรรทัดของคุณใน statement ยาว ๆ ไว้ ไม่ตัดบรรทัดยาวและไม่จัด = ให้ตรงคอลัมน์
  • การจัดรูปแบบต้องใช้ไฟล์ที่ parse ได้ ให้แก้ error ในแผง Problems ก่อน
  • import ข้ามไฟล์ต้องมีโฟลเดอร์อยู่บนดิสก์ ใน virtual workspace ใช้ได้เฉพาะการไฮไลต์ การจัดรูปแบบ และ outline

คำถามที่พบบ่อย

ใช้ฟรีไหม

การไฮไลต์ การจัดรูปแบบ, go to definition, find references, error แบบ protoc, hover และ completion ใช้ได้ฟรี เครื่องมือ Pro 3 ตัว คือ Check Breaking Changes Against Git, Generate API Docs และ Decode a Binary Message ลองใช้ฟรีได้ตัวละ 3 ครั้ง หลังจากนั้นต้องใช้ Zovo Pro ราคา 19 ดอลลาร์สหรัฐ จ่ายครั้งเดียวสำหรับส่วนขยาย Zovo ทุกตัว

ต้องติดตั้ง protoc ไหม

ไม่ต้อง ส่วนขยายมี parser ของตัวเองและทำงานออฟไลน์ error ใช้ถ้อยคำเดียวกับ protoc

ทำไม import แสดงข้อความแทนเครื่องหมายสีแดง

ไฟล์ที่ import ไม่อยู่ใน workspace ของคุณ ให้เพิ่มโฟลเดอร์ root ของไฟล์นั้นใน zovoProto.importPaths เหมือน protoc -I

ใช้ใน Cursor ได้ไหม

ได้ Cursor, Windsurf และ VSCodium ติดตั้งได้จาก Open VSX ซึ่งเผยแพร่ในชื่อ zovo/zovo-protobuf
