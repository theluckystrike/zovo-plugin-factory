What we learned

  • 11 Nov 19:30 Card2 has not lifted checkouts yet. Since 11:17 the card-first pick sits behind every Pro link in 40 listings (1,460 of 1,531 installs). 0 sessions came in about 8,700 install-hours, where the old rate predicts about 2. A 0 by chance is about 14 % likely, so this does not prove harm, but the buttons are not the limit. (F Stripe and gallery, E expected count)
  • 11 Nov 19:30 Few users reach a Pro tool, so better buy buttons barely matter. The last checkout was 09:00. Checkout to email is still 0 of 7, and the new Zovo Stripe page (CHECKOUT1) has had no visitor to test it. (F Stripe)
  • 11 Nov 19:30 README changes do not move search rank. The Marketplace and Open VSX search only the display name, short description and tags. 20 top-20 releases changed only the README, and 54 of 60 VS Code positions stayed the same. The whole phrase in a short display name is what ranks: the median name at #1-3 is 23 characters, ours are 41 to 85. (F RANK15)
  • 11 Nov 19:30 0 ratings is the market rate: the median among 32 popular extensions is 1 rating per 53,800 installs. Rating 2.3 asks later in a session and keeps a Rate row in the Pro pick. It is live in 40 listings. Expect about 1 rating per 1,000 to 3,000 installs. (F RATE6, E rate)
  • 11 Nov 19:30 The site sent 0 checkouts so far: 87 tagged card links and 15 new buyer-intent guide pages (live 13:34) brought no session in 6 h. (F Stripe, SEO7)
  • 11 Nov 09:10 Checkout sessions are a good sign: 7 since card checkout went live on 10 Nov 10:28, 4 of them from inside VS Code by 2 distinct users. One user came back for a second checkout. People want Pro and click to buy. (F, Stripe API)
  • 11 Nov 09:10 Nobody pays yet: 0 of 7 sessions reached the email field. The page said BeLikeNative, showed a coupon field and described Pro as Hex and DOCX only, while Pro is in all 68 listings. The fix is CHECKOUT1 (no release needed; the owner approved the name Zovo). (F, Stripe API, CONV4)
  • 11 Nov 09:10 Buyers drop BEFORE the card button. The card button appears only after 3 used free tries (7 to 13 actions). The buy link every user sees (the footer, on 100 % of opens) still goes to GitHub Sponsors, which needs a GitHub account. About 1 in 466 card-build installs reached Stripe in 8 h. The fix is BUY1: every visible Zovo Pro link opens Pay by card first. (F, CONV4 walk in real VS Code)
  • 11 Nov 09:10 Adding Pro to more listings did not add checkouts: coverage went from 48 to 68 listings overnight and 0 new sessions came in 10 h. Visibility of the card button limits conversion, not coverage. (F, REPORT-0600)
  • 11 Nov 09:10 Our site sent 0 checkouts. All 110 site pages with a buy link tag it (site-product, site-pro, seo-*), and none of those tags reached Stripe. 3 sessions came from the bare buy.stripe.com link. Every shared link must carry a tag, so each sale has a source. (F, Stripe API, site audit)
  • 11 Nov 09:10 VS Code asks 'open external website?' with no default button on every card click; GitHub links do not get this prompt. One line of text before the click can lift the pass rate (BUY1). (F, CONV4)
  • 11 Nov 09:10 Expected value (CONV4 model, mid): about USD 245 in 30 days today; about USD 620 with CHECKOUT1 + BUY1 + ENTRY1. p(first USD in 7 days) about 95 % mid, 18 % low; the fixes matter most in the low case. (E, CONV4)

How we measure

  • Tag every buy link with a source (client_reference_id): editor install id, site-*, seo-*, web-*. An untagged sale teaches us nothing.
  • Change one thing per surface at a time and write it in the experiment log with its start time, so the next numbers can be read against it.
  • Judge an experiment on sessions per 1,000 installs and on checkout to paid, not on installs.
  • Never add popups, toasts or nags on open to push numbers. Free stays free.
