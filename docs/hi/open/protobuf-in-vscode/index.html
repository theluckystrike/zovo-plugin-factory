VS Code में highlighting, formatting और go to definition के साथ .proto फ़ाइलें edit करें

मुफ़्त Protobuf & Proto3 Formatter इंस्टॉल करें और .proto फ़ाइलों वाला फ़ोल्डर खोलें। यह proto2, proto3 और editions 2023 और 2024 के लिए highlighting, हर comment बनाए रखने वाला formatter, go to definition, find references और protoc की भाषा वाले errors जोड़ता है। यह अपने parser के साथ offline चलता है, इसलिए न protoc चाहिए, न language server, न कोई setup, और यह सब मुफ़्त है। Zovo Pro (19 USD, एक बार) तीन टूल जोड़ता है, Check Breaking Changes Against Git, Generate API Docs और Decode a Binary Message, और हर टूल 3 बार मुफ़्त चलता है।

VS Code में स्टेप्स

  1. Marketplace से Protobuf & Proto3 Formatter इंस्टॉल करें, या Ctrl+P (macOS पर Cmd+P) दबाकर ext install zovo.zovo-protobuf चलाएँ।
  2. .proto फ़ाइलों वाला फ़ोल्डर खोलें। Highlighting, outline और breadcrumbs तुरंत शुरू हो जाते हैं।
  3. फ़ॉर्मैट करने के लिए Shift+Alt+F (macOS पर Shift+Option+F) दबाएँ, या editor.formatOnSave चालू करें। आपको हर लाइन में एक statement, आपके editor का indentation और = के दोनों ओर एक space मिलता है। Comments, खाली लाइनों वाले groups और लंबे statements में आपके line breaks अपनी जगह रहते हैं।
  4. किसी type या import की definition पर जाने के लिए F12 दबाएँ, और उसके uses की list के लिए Shift+F12। फ़ाइल खोलने के लिए import पर Ctrl या Cmd दबाकर क्लिक करें। किसी type पर hover करने से उसके fields और उसका comment दिखता है।
  5. Errors Problems panel में protoc की भाषा में दिखते हैं: duplicate field numbers (अगले खाली number के साथ), unknown types, बिना import के इस्तेमाल हुए types, reserved numbers और names, और proto3 व editions के नियम। Unused imports फीके दिखते हैं।
  6. अगर आपके imports proto/ या third_party/ जैसे किसी फ़ोल्डर से शुरू होते हैं, तो वे हर फ़ाइल से ऊपर की ओर जाकर ढूँढ लिए जाते हैं। दूसरे roots के लिए उन्हें सेटिंग zovoProto.importPaths में जोड़ें, जैसे आप protoc -I के साथ करते हैं।

क्या मुफ़्त है और Zovo Pro क्या जोड़ता है

Highlighting (Markdown के proto code blocks के लिए भी), Format Document, go to definition, find references, protoc-style errors, outline, Go to Symbol in workspace, hovers और completion, = के बाद अगले खाली field number समेत, मुफ़्त हैं। कोई sign-in, कोई network request और कोई telemetry नहीं है।

किसी .proto फ़ाइल का बदलाव merge करने से पहले, Check Breaking Changes Against Git आपकी फ़ाइलों की तुलना main (या आपकी सेट की हुई branch) से करता है और हटाए गए fields, बदले हुए numbers, types और labels, rename हुए fields और enum values, और हटाए गए या बदले हुए methods की list देता है। हर finding बताती है कि वह binary data, JSON या सिर्फ़ generated code को तोड़ती है, ताकि पुराने clients के गलत पढ़ने से पहले ही आप देख लें कि वे क्या गलत पढ़ेंगे। Findings को CI के लिए JSON फ़ाइल के रूप में सेव किया जा सकता है।

Check Breaking Changes Against Git का इस्तेमाल (Zovo Pro)

  1. Explorer में किसी .proto फ़ाइल या फ़ोल्डर पर राइट-क्लिक करके "Zovo Pro: Check breaking changes against git" चुनें, किसी .proto editor में राइट-क्लिक करके "Check Breaking Changes Against Git (Pro)" चुनें, या Command Palette से "Protobuf: Check Breaking Changes Against Git (Pro)" चलाएँ। फ़ोल्डर किसी git repository में होना चाहिए, और git इंस्टॉल होना चाहिए।
  2. जाँच repository की हर .proto फ़ाइल को आपके working tree में जैसी है, unsaved edits समेत, origin/main, main, origin/master या master (इनमें से जो पहले मौजूद हो) के merge base से, या सेटिंग zovoProto.baseBranch वाली branch के merge base से मिलाती है। फ़ाइल के हिसाब से grouped findings के साथ एक Markdown report खुलती है।
  3. Findings को proto-breaking.json के रूप में रखने के लिए message में "Save JSON for CI" पर क्लिक करें।
  4. Try तभी गिना जाता है जब report खुली हो। git से बाहर का फ़ोल्डर या न मिलने वाली base branch कोई try नहीं लेती।

Check Breaking Changes Against Git आपके कंप्यूटर पर 3 बार मुफ़्त चलता है, उसके बाद लाइसेंस माँगता है। न कोई पॉप-अप आता है, न कोई काउंटडाउन चलता है।

Protobuf & Proto3 Formatter क्या करता है

  • proto2, proto3 और editions (2023, 2024), और Markdown में proto code blocks।
  • Imports के पार go to definition और find references के लिए protobuf के scoping नियम: nested types, packages और शुरुआत का .।
  • google/protobuf/timestamp.proto जैसे well-known types के built-in नाम।
  • कोई गलत लाल निशान नहीं: जब कोई import आपके workspace में नहीं होता, तो import लाइन यह बताती है, और उससे आने वाले types का अंदाज़ा नहीं लगाया जाता।
  • Types, keywords, options, import paths और = के बाद अगले खाली field number के लिए completion।

यह क्या नहीं करता

  • Custom option names के import की जाँच होती है, पर extension के field type से उनका मिलान नहीं होता।
  • Editions feature checks enum_type, labels, packed और groups को cover करते हैं। बाकी feature नियम protoc पर छोड़े जाते हैं।
  • Formatter लंबे statements के अंदर आपके line breaks रखता है। यह लंबी लाइनें wrap नहीं करता और = को columns में align नहीं करता।
  • Formatting के लिए फ़ाइल का parse होना ज़रूरी है। पहले Problems panel वाली error ठीक करें।
  • फ़ाइलों के पार imports के लिए disk पर फ़ोल्डर चाहिए। Virtual workspace में सिर्फ़ highlighting, formatting और outline काम करते हैं।

अक्सर पूछे जाने वाले सवाल

क्या यह मुफ़्त है?

Highlighting, formatting, go to definition, find references, protoc-style errors, hovers और completion मुफ़्त हैं। तीनों Pro टूल, Check Breaking Changes Against Git, Generate API Docs और Decode a Binary Message, 3-3 बार मुफ़्त चलते हैं। उसके बाद इनके लिए Zovo Pro चाहिए, जो सभी Zovo एक्सटेंशन के लिए एक बार 19 USD का है।

क्या protoc इंस्टॉल होना चाहिए?

नहीं। एक्सटेंशन का अपना parser है और यह offline चलता है। Errors protoc जैसी ही भाषा में आते हैं।

किसी import पर लाल निशान की जगह note क्यों दिखता है?

Import की गई फ़ाइल आपके workspace में नहीं है। उसका root फ़ोल्डर zovoProto.importPaths में जोड़ें, जैसे protoc -I में।

क्या यह Cursor में चलता है?

हाँ। Cursor, Windsurf और VSCodium इसे Open VSX से इंस्टॉल करते हैं, जहाँ यह zovo/zovo-protobuf नाम से है।
