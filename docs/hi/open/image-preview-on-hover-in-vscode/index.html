VS Code में code के image path की image gutter और hover में देखें

मुफ़्त Image Preview & Image Hover एक्सटेंशन इंस्टॉल करें और ऐसी फ़ाइल खोलें जिसमें किसी image का नाम हो। लाइन के बगल में gutter में thumbnail दिखता है, और path पर hover करने से image, उसका type, pixels में size और file size दिखता है। यह JavaScript और TypeScript imports, JSX, CSS url(), Markdown, HTML src और srcset, YAML और data URIs में काम करता है, बिना किसी network request के। Zovo Pro (19 USD, एक बार) तीन टूल जोड़ता है, Find Unused Images, Find Broken Image References और Image Weight Report, और हर टूल 3 बार मुफ़्त चलता है।

VS Code में स्टेप्स

  1. Marketplace से Image Preview & Image Hover इंस्टॉल करें, या Ctrl+P (macOS पर Cmd+P) दबाकर ext install zovo.zovo-image-preview चलाएँ।
  2. ऐसी फ़ाइल खोलें जिसमें image का नाम हो, जैसे import logo from './logo.png', CSS url() या HTML <img src>। Gutter में thumbnails दिखते हैं, हर लाइन पर एक।
  3. Path पर hover करें। Hover में image (फ़िट होने के लिए छोटी की गई, कभी बड़ी नहीं), उसका type, pixels में width × height, file size और transparency दिखते हैं, साथ में फ़ाइल खोलने या Explorer में दिखाने के links।
  4. अगर कोई path resolve नहीं होता, तो hover यह बताता है और वे paths दिखाता है जहाँ उसने ढूँढा। अपने prefixes imgPreview.aliases में जोड़ें, जैसे { "@images": "src/assets/images" }, या / से शुरू होने वाले paths के फ़ोल्डर imgPreview.publicFolders में जोड़ें।
  5. Gutter thumbnails छिपाने के लिए Command Palette से "Image Preview: Show or Hide Gutter Thumbnails" चलाएँ।
  6. कोई project पास नहीं है? "Image Preview: Open the Sample Files" चलाएँ। यह हर तरह के path वाला एक छोटा demo project खोलता है।

क्या मुफ़्त है और Zovo Pro क्या जोड़ता है

Gutter thumbnails, hover, aliases, tsconfig.json और jsconfig.json के paths और monorepo packages के साथ path resolution, और data URIs मुफ़्त हैं। कोई account, कोई network request और कोई telemetry नहीं है, और यह offline काम करता है।

Find Unused Images workspace (या एक फ़ोल्डर) की वे images ढूँढता है जिनका नाम कोई code, style, Markdown, HTML, JSON या YAML फ़ाइल नहीं लेती, और उन्हें उनके size के साथ, सबसे बड़ी पहले, एक Markdown report में दिखाता है। पुष्टि करने पर वे अपने folder structure के साथ _unused-images फ़ोल्डर में चली जाती हैं, और Edit > Undo उन्हें वापस ले आता है। आप हर नाम हाथ से जाँचे बिना project से पुरानी images हटा पाते हैं।

Find Unused Images का इस्तेमाल (Zovo Pro)

  1. Explorer में किसी फ़ोल्डर पर राइट-क्लिक करके "Zovo Pro: Find unused images" चुनें, या Command Palette से "Image Preview: Find Unused Images (Pro)" चलाएँ। एक से ज़्यादा workspace फ़ोल्डर हों तो फ़ोल्डर चुनें।
  2. एक notification में progress और Cancel बटन दिखता है। फिर एक Markdown report खुलती है, जिसमें हर unused image और उसका size होता है, सबसे बड़ी पहले।
  3. उन्हें move करने के लिए "Move N to _unused-images" पर क्लिक करें, या उन्हें वहीं रखने के लिए message बंद कर दें। Edit > Undo उन्हें वापस ले आता है।
  4. Try तभी गिना जाता है जब report खुली हो। Escape कभी try नहीं लेता।

Find Unused Images आपके कंप्यूटर पर 3 बार मुफ़्त चलता है, उसके बाद लाइसेंस माँगता है। न कोई पॉप-अप आता है, न कोई काउंटडाउन चलता है।

Image Preview & Image Hover क्या करता है

  • PNG, JPEG, GIF, WebP, AVIF, SVG, BMP और ICO फ़ाइलों के लिए, और data:image/... URIs के लिए gutter thumbnails। TIFF और HEIC फ़ाइलों का size और type header से पढ़ा जाता है।
  • फ़ाइल के सापेक्ष paths, public/, static/ और दूसरे web root फ़ोल्डरों से /logo.png, src/ के लिए @/, node_modules या आपके home फ़ोल्डर के लिए ~, और extends के साथ tsconfig.json या jsconfig.json के paths।
  • Spaces, %20, ?v=2 या #id वाले file names। JSON में beans.jpg जैसा सादा नाम उस नाम की सबसे पास वाली image से जोड़ा जाता है।
  • Monorepos: हर package का अपना public/ फ़ोल्डर और tsconfig.json इस्तेमाल होता है।
  • Remote URL सिर्फ़ link के रूप में दिखता है और कभी download नहीं होता।

यह क्या नहीं करता

  • Code चलने पर बनने वाले paths, जैसे `icons/${name}.svg` या string concatenation, preview नहीं हो सकते, और उनकी वजह से कोई image unused लग सकती है। फ़ाइलें move करने से पहले unused list जाँच लें।
  • हर लाइन पर एक thumbnail: उस लाइन की पहली image। Hover लाइन के हर path पर काम करता है।
  • Remote और virtual workspaces (SSH, WSL, Codespaces, vscode.dev) इस version में समर्थित नहीं हैं।
  • Webpack, Vite या Next.js के aliases जो सिर्फ़ JavaScript config फ़ाइल में हैं, पढ़े नहीं जाते। उन्हें imgPreview.aliases या tsconfig.json के paths में जोड़ें।
  • 20 MB से बड़ी images का size मापा जाता है, पर वे draw नहीं होतीं (सेटिंग imgPreview.maxFileSizeMB)। Image Weight Report भारी फ़ाइलों को flag करता है, पर उन्हें compress नहीं करता।

अक्सर पूछे जाने वाले सवाल

क्या यह मुफ़्त है?

Gutter thumbnails, hover और path resolution मुफ़्त हैं। तीनों Pro टूल, Find Unused Images, Find Broken Image References और Image Weight Report, 3-3 बार मुफ़्त चलते हैं। उसके बाद इनके लिए Zovo Pro चाहिए, जो सभी Zovo एक्सटेंशन के लिए एक बार 19 USD का है।

मेरे @/ या alias वाले path पर image क्यों नहीं दिखती?

हो सकता है वह alias सिर्फ़ Webpack, Vite या Next.js की config फ़ाइल में हो, जिसे पढ़ा नहीं जाता। उसे imgPreview.aliases या tsconfig.json के paths में जोड़ें।

क्या यह Remote SSH या WSL पर चलता है?

इस version में नहीं। Hover की image local disk से पढ़ी जाती है।

क्या यह Cursor में चलता है?

हाँ। Cursor, Windsurf और VSCodium इसे Open VSX से इंस्टॉल करते हैं, जहाँ यह zovo/zovo-image-preview नाम से है।
