Как редактировать файл .env в VS Code, не показывая секреты на экране

Установите бесплатное расширение Dotenv & .env File Editor и откройте файл .env. Ключи и значения выделяются цветом, а значения ключей вроде DB_PASSWORD или STRIPE_SECRET_KEY показываются точками, пока курсор не окажется на их строке, так что можно спокойно показывать экран. Проблемы с быстрыми исправлениями, Format Document, структура ключей и подсказки при наведении на process.env.X в коде бесплатны и работают офлайн. Как это сделать в VS Code

  1. Установите Dotenv & .env File Editor из Marketplace или нажмите Ctrl+P (Cmd+P на macOS) и выполните ext install zovo.zovo-dotenv.
  2. Откройте файл .env (а также .env.local, .env.production, *.env или .flaskenv). Ключи, export, значения, многострочные значения и ссылки ${NAME} выделяются цветом.
  3. Значения, похожие на секреты, показываются точками, пока курсор не окажется на их строке. Чтобы показать все, нажмите кнопку с глазом в заголовке редактора или выполните "Dotenv: Show or Hide Secret Values". В шаблонах вроде .env.example значения никогда не скрываются.
  4. Проблемы видны в панели Problems. Это ключ, заданный дважды, пробелы вокруг =, незакрытая кавычка, строка без =, недопустимое имя, пробелы в конце строки или ${NAME}, который не задан ни в одной строке. Нажмите Ctrl+. (Cmd+. на Mac) на проблеме, чтобы получить исправление.
  5. Выполните Format Document, чтобы убрать пробелы вокруг = и в конце строк. Комментарии, порядок и кавычки не меняются.
  6. Чтобы скопировать значение, не показывая его, выполните "Dotenv: Copy the Value on This Line". Команда копирует значение без кавычек и экранирования, даже если оно скрыто.
  7. В коде наведите курсор на process.env.DB_HOST, os.getenv("X"), System.getenv("X") и подобные вызовы, чтобы увидеть, какой файл .env задаёт значение, и нажмите F12, чтобы открыть эту строку.

Что умеет Dotenv & .env File Editor

  • Файлы .env, .env.* (например, .env.local и .env.production), *.env и .flaskenv.
  • Скрываются значения ключей, в имени которых есть PASSWORD, TOKEN, SECRET, API_KEY, DSN, DATABASE_URL и похожие слова, или все значения, или ни одно (настройка envFile.maskValues).
  • Подсказки в коде и переход к определению для process.env и import.meta.env (JavaScript, TypeScript), os.environ и os.getenv (Python), os.Getenv (Go), ENV (Ruby), System.getenv (Java), env() (PHP) и других.
  • Автодополнение ключей после process.env..
  • Скрытые значения остаются скрытыми в структуре, подсказках и автодополнении, если вы не отключите это (настройка envFile.hoverShowsSecrets).

Чего расширение не делает

  • Скрытие работает только на экране. Текст по-прежнему есть в файле, в результатах поиска и в силуэте на миникарте, а копирование и вставка копируют настоящее значение.
  • Файл .envrc (direnv) является shell-скриптом, и его оставляют расширениям для shell.
  • Отчёт по коду видит только буквальные имена вроде process.env.API_KEY. Имена, собранные во время выполнения, не находятся.
  • Проблемы определяются по правилам пакета dotenv. Некоторые инструменты (Docker Compose v1, systemd) строже, и предупреждения указывают именно на это.

Частые вопросы

Это бесплатно?

Подсветка, скрытые значения, проблемы с быстрыми исправлениями, форматирование и подсказки в коде бесплатны. Потом для них нужен Zovo Pro, 19 USD один раз за все расширения Zovo.

Меняет ли расширение мой файл .env, чтобы скрыть значения?

Нет. Меняется только отображение, сам файл никогда не изменяется. Копирование и вставка по-прежнему копируют настоящее значение.

Почему мой ключ помечен как заданный дважды?

Один и тот же ключ есть в двух строках. Пакет dotenv берёт первое значение, а shell и Docker Compose берут последнее. Быстрое исправление удаляет вторую строку.

Работает ли расширение в Cursor?

Да. Cursor, Windsurf и VSCodium устанавливают его из Open VSX, где оно опубликовано как zovo/zovo-dotenv.
