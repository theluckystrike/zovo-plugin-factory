Редактирование файлов .proto в VS Code: подсветка, форматирование и переход к определению

Установите бесплатное расширение Protobuf & Proto3 Formatter и откройте папку с файлами .proto. Оно добавляет подсветку синтаксиса, форматирование с сохранением всех комментариев, переход к определению, поиск ссылок и ошибки в тех же формулировках, что у protoc, для proto2, proto3 и editions 2023 и 2024. Расширение работает офлайн со своим парсером, поэтому не нужны ни protoc, ни языковой сервер, ни настройка, и всё это бесплатно. Zovo Pro (19 USD один раз) добавляет три инструмента, Check Breaking Changes Against Git, Generate API Docs и Decode a Binary Message, и у каждого есть 3 бесплатные попытки.

Как это сделать в VS Code

  1. Установите Protobuf & Proto3 Formatter из Marketplace или нажмите Ctrl+P (Cmd+P на macOS) и выполните ext install zovo.zovo-protobuf.
  2. Откройте папку с файлами .proto. Подсветка, структура (outline) и навигационная цепочка (breadcrumbs) появляются сразу.
  3. Нажмите Shift+Alt+F (Shift+Option+F в macOS), чтобы отформатировать файл, или включите editor.formatOnSave. Получается одна инструкция в строке, отступы как в настройках редактора и по одному пробелу вокруг =. Комментарии, группы пустых строк и ваши переносы в длинных инструкциях остаются на месте.
  4. Нажмите F12 на типе или import, чтобы перейти к определению, и Shift+F12, чтобы увидеть все места использования. Ctrl+щелчок или Cmd+щелчок по import открывает файл. Наведите курсор на тип, чтобы увидеть его поля и комментарий.
  5. Ошибки показываются в панели Problems в формулировках protoc: повторяющиеся номера полей (с ближайшим свободным номером), неизвестные типы, типы без нужного import, зарезервированные номера и имена, а также правила proto3 и editions. Неиспользуемые import показываются бледным цветом.
  6. Если ваши import начинаются от папки вроде proto/ или third_party/, расширение находит их, поднимаясь вверх от каждого файла. Другие корневые папки добавьте в настройку zovoProto.importPaths, как в protoc -I.

Что бесплатно и что добавляет Zovo Pro

Подсветка (в том числе блоков кода proto в Markdown), Format Document, переход к определению, поиск ссылок, ошибки в стиле protoc, структура, Go to Symbol in workspace, подсказки при наведении и автодополнение, включая ближайший свободный номер поля после =, бесплатны. Нет входа в аккаунт, сетевых запросов и телеметрии.

Перед слиянием изменения в файле .proto инструмент Check Breaking Changes Against Git сравнивает ваши файлы с main (или с указанной веткой) и перечисляет удалённые поля, изменённые номера, типы и метки, переименованные поля и значения enum, а также удалённые или изменённые методы. Для каждой находки указано, что она ломает: двоичные данные, JSON или только сгенерированный код. Так вы видите, что старые клиенты прочитают неправильно, ещё до того, как это случится. Находки можно сохранить в JSON-файл для CI.

Как запустить Check Breaking Changes Against Git (Zovo Pro)

  1. Щёлкните правой кнопкой по файлу .proto или папке в Explorer и выберите "Zovo Pro: Check breaking changes against git", щёлкните правой кнопкой в редакторе .proto и выберите "Check Breaking Changes Against Git (Pro)" или запустите "Protobuf: Check Breaking Changes Against Git (Pro)" из Command Palette. Папка должна находиться в git-репозитории, и git должен быть установлен.
  2. Проверка сравнивает все файлы .proto репозитория в рабочей копии, включая несохранённые правки, с merge base ветки origin/main, main, origin/master или master (первой из существующих) либо ветки из настройки zovoProto.baseBranch. Открывается отчёт в Markdown с находками, сгруппированными по файлам.
  3. Нажмите "Save JSON for CI" в сообщении, чтобы сохранить находки в proto-breaking.json.
  4. Попытка засчитывается, только если отчёт открылся. Папка вне git или отсутствие базовой ветки попытку не тратят.

Check Breaking Changes Against Git можно запустить на вашем компьютере 3 раза бесплатно, потом расширение попросит лицензию. Никаких всплывающих окон и никакого обратного отсчёта.

Как установить в Cursor, Windsurf или VSCodium

  1. Откройте панель Extensions сочетанием Ctrl+Shift+X (Cmd+Shift+X на macOS).
  2. Найдите zovo.zovo-protobuf и нажмите Install. Cursor, Windsurf и VSCodium ставят расширения из Open VSX, где это расширение опубликовано как zovo/zovo-protobuf.
  3. Если в вашем редакторе нет каталога расширений, скачайте файл .vsix со страницы на Open VSX и выполните "Extensions: Install from VSIX...".
  4. Дальше всё работает так же, как в VS Code.

Что умеет Protobuf & Proto3 Formatter

  • proto2, proto3 и editions (2023, 2024), а также блоки кода proto в Markdown.
  • Правила области видимости protobuf при переходе к определению и поиске ссылок через import: вложенные типы, пакеты и ведущая ..
  • Встроенные имена well-known типов, например google/protobuf/timestamp.proto.
  • Без ложных красных пометок: если импортируемого файла нет в рабочей области, строка import сообщает об этом, а типы из него не угадываются.
  • Автодополнение типов, ключевых слов, опций, путей import и ближайшего свободного номера поля после =.

Чего расширение не делает

  • Имена пользовательских опций проверяются на наличие import, но не сверяются с типом поля расширения (extension).
  • Проверки features в editions охватывают enum_type, метки, packed и группы. Остальные правила features остаются за protoc.
  • Форматирование сохраняет ваши переносы внутри длинных инструкций. Оно не переносит длинные строки и не выравнивает = по столбцам.
  • Для форматирования файл должен разбираться без ошибок. Сначала исправьте ошибку, показанную в панели Problems.
  • Для import между файлами нужны папки на диске. В виртуальной рабочей области работают только подсветка, форматирование и структура.

Частые вопросы

Это бесплатно?

Подсветка, форматирование, переход к определению, поиск ссылок, ошибки в стиле protoc, подсказки при наведении и автодополнение бесплатны. У трёх Pro-инструментов, Check Breaking Changes Against Git, Generate API Docs и Decode a Binary Message, есть по 3 бесплатные попытки. Потом для них нужен Zovo Pro, 19 USD один раз за все расширения Zovo.

Нужно ли устанавливать protoc?

Нет. У расширения свой парсер, и оно работает офлайн. Ошибки сформулированы так же, как в protoc.

Почему у import пометка-пояснение вместо красных ошибок?

Импортируемого файла нет в рабочей области. Добавьте его корневую папку в zovoProto.importPaths, как в protoc -I.

Работает ли расширение в Cursor?

Да. Cursor, Windsurf и VSCodium устанавливают его из Open VSX, где оно опубликовано как zovo/zovo-protobuf.
