Форматирование и проверка конфига nginx в VS Code

Установите бесплатное расширение Nginx Config Formatter & Lint, откройте конфиг nginx и нажмите Shift+Alt+F (Shift+Option+F на Mac). Форматировщик разбирает собственный результат и ничего не меняет, если файл стал бы читаться иначе, поэтому рабочий конфиг остаётся рабочим. Подсветка синтаксиса, проблемы прямо при вводе с быстрыми исправлениями, подсказки при наведении примерно для 300 директив, автодополнение, структура (Outline) и обзор конфига с учётом файлов include бесплатны и работают на вашем компьютере. Zovo Pro (19 USD один раз) добавляет три инструмента, Security Audit, Location Tester и Convert .htaccess to nginx, и у каждого есть 3 бесплатные попытки.

Как это сделать в VS Code

  1. Установите Nginx Config Formatter & Lint из Marketplace или нажмите Ctrl+P (Cmd+P на macOS) и выполните ext install zovo.zovo-nginx-config.
  2. Откройте конфиг. Файл открывается как nginx, если он называется nginx.conf или заканчивается на .nginx или .nginxconf, если это файл .conf в папке с именем nginx (например, /etc/nginx/conf.d/default.conf) или файл в nginx/sites-available, nginx/sites-enabled или nginx/snippets. Для любого другого файла выберите "nginx" в качестве языкового режима.
  3. Нажмите Shift+Alt+F (Shift+Option+F на Mac). Каждая инструкция встаёт на свою строку с отступами из настроек редактора, длинные значения log_format сохраняют свои переносы строк, а подряд остаётся не больше одной пустой строки (настройка nginxConfig.format.maxBlankLines).
  4. Проблемы видны прямо при вводе: пропущенная ;, незакрытые или лишние фигурные скобки, незакрытые строки, директива не в том блоке, повторный root или listen, два сервера с одним именем на одном порту. Нажмите Ctrl+. (Cmd+. на Mac) для быстрого исправления, например "Add the missing ";"" или замены proxy_set_heder на proxy_set_header.
  5. Наведите курсор на директиву, чтобы увидеть её синтаксис, значение по умолчанию, блоки, где она допустима, и ссылку на документацию nginx. Автодополнение предлагает директивы, допустимые в текущем блоке, и переменные после $.
  6. Нажмите значок списка в заголовке редактора или выполните "Nginx: Show Config Overview", чтобы увидеть каждый server с его портами и именами и каждый location с тем, что он делает, с учётом файлов include. Нажмите на файл и строку, чтобы перейти туда.

Security Audit проверяет конфиг вместе со всеми файлами include и показывает каждую находку с файлом, строкой, объяснением, чем она опасна, и исправлением, с разбивкой на high, medium и low. Он ищет TLS 1.0 и 1.1, слабые шифры, HTTPS-серверы без HSTS и других заголовков безопасности, блоки location, чей собственный add_header незаметно отбрасывает эти заголовки, обход пути через alias (off-by-slash), proxy_pass на хост, взятый из запроса, отдаваемые наружу файлы .git и .env, листинг папок и тело запроса без ограничения размера. Так вы находите эти ошибки до выкладки конфига в продакшен, не перечитывая каждый файл include вручную.

Как установить в Cursor, Windsurf или VSCodium

  1. Откройте панель Extensions сочетанием Ctrl+Shift+X (Cmd+Shift+X на macOS).
  2. Найдите zovo.zovo-nginx-config и нажмите Install. Cursor, Windsurf и VSCodium ставят расширения из Open VSX, где это расширение опубликовано как zovo/zovo-nginx-config.
  3. Если в вашем редакторе нет каталога расширений, скачайте файл .vsix со страницы на Open VSX и выполните "Extensions: Install from VSIX...".
  4. Дальше всё работает так же, как в VS Code.

Что умеет Nginx Config Formatter & Lint

  • Директивы OpenResty/Lua, headers-more, Brotli, Passenger и других распространённых модулей известны расширению и никогда не помечаются.
  • Блоки Lua, такие как content_by_lua_block, подсвечиваются как Lua.
  • Панель Outline показывает серверы с именами и портами, блоки location, upstream и map.
  • Относительные include читаются из nginxConfig.prefix, папки файла, родительской папки или /etc/nginx, в этом порядке.
  • Обзор конфига и Pro-инструменты учитывают несохранённые изменения в открытых редакторах.

Чего расширение не делает

  • Форматировщик ставит один пробел между директивой и её значениями, поэтому выравнивание по колонкам вроде listen 80; не сохраняется.
  • Файл с незакрытой фигурной скобкой или строкой не форматируется. Он остаётся без изменений, а строка состояния объясняет причину.
  • Проверки читают ваши файлы и не запускают nginx -t. Отсутствующий файл сертификата или незагруженный модуль найдёт только сам nginx.
  • Регулярные выражения location проверяются регулярными выражениями JavaScript. Некоторые возможности, которые есть только в PCRE (захватывающие квантификаторы, рекурсия), проверить нельзя, и они отмечаются как пропущенные.

Частые вопросы

Это бесплатно?

Форматирование, проблемы с быстрыми исправлениями, подсказки при наведении, автодополнение, структура и обзор конфига бесплатны. У трёх Pro-инструментов, Security Audit, Location Tester и Convert .htaccess to nginx, есть по 3 бесплатные попытки. После этого нужен Zovo Pro, 19 USD один раз для всех расширений Zovo.

Может ли форматирование сломать конфиг?

Нет. Форматировщик разбирает собственный результат и ничего не меняет, если файл стал бы читаться иначе, поэтому рабочий конфиг остаётся рабочим.

Заменяет ли это nginx -t?

Нет. Расширение читает ваши файлы и проверяет синтаксис и место каждой директивы. Сертификаты и модули проверяйте командой nginx -t на сервере.

Работает ли это в Cursor?

Да. Cursor, Windsurf и VSCodium устанавливают расширение из Open VSX, где оно опубликовано как zovo/zovo-nginx-config.
