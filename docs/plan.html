What we do, in order

1. Ship the queue

Agents · 2026-11-07 to 2026-11-08 12:00

  1. A retry script (PID 71258) publishes the 14 queued extensions in order of expected installs. It waits for each Marketplace slot: 7 from 10:53 today, 7 from about 23:00. It stops at 12:00 on 2026-11-08.
  2. Before each upload it checks the real VS Code test result, the file age and every README image link.
  3. Updates have no cap. They ship as soon as their tests pass and a real VS Code check passes.

Result to measure. 29 VS Code extensions live by 2026-11-08 12:00.

2. Make money from every product

Agents · 2026-11-06 to 2026-11-07

  1. Add a Sponsor button, a support section and a small support line to every extension. No popup and no limit on free features.
  2. Add cross-selling of our own products in each product, each README, each Actor page and each site page.
  3. Add PayPal and Buy Me a Coffee links when the owner creates the accounts. One config file holds all links.
  4. Switch on Table Viewer Pro when a payment link exists.

Result to measure. Sponsor clicks and new sponsors each week. Baseline 11 sponsors.

3. Get more users from the stores

Agents · Each week

  1. Update the live extensions first. DOCX Viewer has 17 of our 37 installs because it is in the top 3 for "word viewer".
  2. Done 2026-11-07: new names for the table viewer ("CSV Viewer, Excel Viewer (XLSX) & Parquet Viewer") and the JSONL viewer, 5 new descriptions, new search words on 9 listings and a quiet Rate link in every footer.
  3. Re-measure 185 search phrases on 2026-11-08 at 07:30 (automatic job). Keep the names that climbed. Change the ones that did not.
  4. Fix the 5 small DOCX findings from the check on 2026-11-07, and pin README image links to a fixed commit so a later commit cannot break a live listing.
  5. Publish all extensions on Open VSX for Cursor and Windsurf users after the owner finishes the Eclipse profile.

Result to measure. Installs, page views and search rank for each extension, on the Traffic and Users pages.

4. Build the next products

Agents · Each day

  1. No new VS Code builds on 2026-11-07. The 14 queued extensions fill every slot until about 23:30.
  2. Go or no-go at 07:30 on 2026-11-08: build 2 new extensions (SVG viewer, then hex viewer) only if all 7 extensions from the second batch make at least 3 installs a day each, or more than half of the 7 renamed listings reach the top 3 on a new phrase.
  3. Each new product passes unit tests and a test in a real VS Code window before upload.

Result to measure. Installs in the first 14 days for each new product.

5. Stop what does not work

Agents · Each Monday

  1. A product with 0 outside users after 14 days gets no more work.
  2. A store channel with no users after 30 days gets no new products.
  3. Move the effort to the products and stores that grow.

Result to measure. Weekly review on the Insights page.

6. Owner steps

Owner · About 60 minutes in total

  1. Open VSX, before 20:00 on 2026-11-07. Sign in at accounts.eclipse.org, edit the profile, put theluckystrike in the GitHub Username field and save. Then on open-vsx.org click Log in with Eclipse and sign the Publisher Agreement. A script publishes 17 extensions once it sees the signed agreement.
  2. Apify. Identity check at verify-company.apify.com (5 minutes).
  3. Atlassian. Answer one GDPR question on the Gists app.
  4. Shopify. Partner account and development store (15 minutes).
  5. Roblox. ID check and one publish in Studio (35 minutes).
  6. Decide if the one-time rating notice (after 5 good uses) stays in all extensions.
  7. Optional. PayPal.me and Buy Me a Coffee links in funding.json.

Result to measure. Each step unblocks one store.
