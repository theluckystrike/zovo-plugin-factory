Minidump Viewer & Crash Dump

Minidump Viewer & Crash Dump, a VS Code extension by Zovo

Minidump viewer by Zovo for VS Code: open a crash dump (.dmp, .mdmp) from Windows, Linux, macOS or Android and see at once why the program crashed, where, and what each thread was doing. The dump is read by plain JavaScript inside VS Code: no debugger, no tools to download, nothing uploaded.

  • Summary: the exception in plain words (access violation with the read or write address, stack overflow, heap corruption, fast fail codes, POSIX signals, Mach exceptions), the faulting module and offset, the crashed thread, the process, OS, CPU and dump time.

How to use it

Click a .mdmp file: it opens in the viewer. Several other tools also use .dmp (kernel memory dumps, packet captures), so for .dmp the viewer is an option: right-click the file and choose Open in Minidump Viewer, or use Open With... When a .dmp file opens as text and starts with the MDMP signature, the viewer takes its place once; reopen it with the text editor and it stays there. The setting minidumpViewer.openDmpFiles turns that off.

Open the sample from the Command Palette: Minidump: Open the Sample Crash Dump. It is a made-up Windows app crash with a matching .sym file in samples/symbols, so the Pro symbol tool has something to load.

Settings

  • minidumpViewer.openDmpFiles: switch .dmp files that are minidumps from the text editor to the viewer (default on).
  • minidumpViewer.symbolPaths: local folders with .pdb or .sym files for the symbol tool. The dump's own folder is always searched.
  • minidumpViewer.maxFileSizeMB: size limit for dumps that are not on this computer's disk (default 512). Local dumps have no limit.
  • minidumpViewer.showProTools, minidumpViewer.askForRating, minidumpViewer.showSupportLinks.

Limits

  • The stack is walked with the frame-pointer chain and a stack scan. Code built without frame pointers (many optimized x64 builds) gives a short chain; the scan then shows the likely return addresses, which are not a checked call chain. Unwind tables (CFI and Windows unwind info) are not used.
  • Symbol names from PDB public symbols stay in their decorated C++ form.
  • Inline frames from Breakpad INLINE records are not shown.
  • Kernel memory dumps (PAGEDU64) and .dmp packet captures are not minidumps; the viewer says so.
