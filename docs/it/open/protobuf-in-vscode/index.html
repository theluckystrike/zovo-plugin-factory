Modificare i file .proto in VS Code con evidenziazione, formattazione e vai alla definizione

Installa l'estensione gratuita Protobuf & Proto3 Formatter e apri una cartella con file .proto. Aggiunge l'evidenziazione della sintassi, un formatter che conserva ogni commento, vai alla definizione, trova riferimenti ed errori con la stessa formulazione di protoc, per proto2, proto3 ed editions 2023 e 2024. Funziona offline con un proprio parser, quindi niente protoc, niente language server e nessuna configurazione, e tutto questo è gratuito. Zovo Pro (19 USD una tantum) aggiunge tre strumenti, Check Breaking Changes Against Git, Generate API Docs e Decode a Binary Message, e ognuno ha 3 tentativi gratuiti.

Passaggi in VS Code

  1. Installa Protobuf & Proto3 Formatter dal Marketplace, oppure premi Ctrl+P (Cmd+P su macOS) ed esegui ext install zovo.zovo-protobuf.
  2. Apri una cartella con file .proto. Evidenziazione, outline e breadcrumb partono subito.
  3. Premi Shift+Alt+F (Shift+Option+F su macOS) per formattare, oppure attiva editor.formatOnSave. Ottieni un'istruzione per riga, l'indentazione del tuo editor e spazi singoli attorno a =. Commenti, gruppi di righe vuote e i tuoi a capo nelle istruzioni lunghe restano dove erano.
  4. Premi F12 su un tipo o su un import per andare alla sua definizione, e Shift+F12 per elencarne gli usi. Ctrl+clic o Cmd+clic su un import apre il file. Passa il mouse su un tipo per vedere i suoi campi e il suo commento.
  5. Gli errori compaiono nel pannello Problems con la formulazione di protoc: numeri di campo duplicati (con il prossimo numero libero), tipi sconosciuti, tipi usati senza il loro import, numeri e nomi riservati, e le regole di proto3 e delle editions. Gli import non usati appaiono attenuati.
  6. Se i tuoi import partono da una cartella come proto/ o third_party/, vengono trovati risalendo da ogni file. Per altre radici, aggiungile all'impostazione zovoProto.importPaths, come faresti con protoc -I.

Cosa è gratis e cosa aggiunge Zovo Pro

Evidenziazione (anche per i blocchi di codice proto in Markdown), Format Document, vai alla definizione, trova riferimenti, errori come protoc, outline, Go to Symbol in workspace, hover e completamento, incluso il prossimo numero di campo libero dopo =, sono gratuiti. Non serve un login, e non ci sono richieste di rete né telemetria.

Prima di fare il merge di una modifica a un file .proto, Check Breaking Changes Against Git confronta i tuoi file con main (o con il branch che imposti) ed elenca campi rimossi, numeri, tipi ed etichette cambiati, campi e valori enum rinominati, e metodi rimossi o modificati. Ogni risultato dice se rompe i dati binari, il JSON o solo il codice generato, così vedi cosa leggeranno male i vecchi client prima che succeda. Puoi salvare i risultati come file JSON per la CI.

Usare Check Breaking Changes Against Git (Zovo Pro)

  1. Fai clic destro su un file .proto o su una cartella nell'Explorer e scegli "Zovo Pro: Check breaking changes against git", fai clic destro in un editor .proto e scegli "Check Breaking Changes Against Git (Pro)", oppure esegui "Protobuf: Check Breaking Changes Against Git (Pro)" dalla Command Palette. La cartella deve trovarsi in un repository git, e git deve essere installato.
  2. Il controllo confronta ogni file .proto del repository nella tua working tree, modifiche non salvate incluse, con il merge base di origin/main, main, origin/master o master (il primo che esiste), oppure del branch indicato nell'impostazione zovoProto.baseBranch. Si apre un report Markdown con i risultati raggruppati per file.
  3. Fai clic su "Save JSON for CI" nel messaggio per conservare i risultati come proto-breaking.json.
  4. Un tentativo conta solo quando il report si è aperto. Una cartella fuori da git o un branch di base mancante non ne consumano.

Check Breaking Changes Against Git funziona 3 volte sul tuo computer prima di chiedere una licenza. Non ci sono finestre a comparsa né conti alla rovescia.

Passaggi in Cursor, Windsurf o VSCodium

  1. Apri la vista Extensions con Ctrl+Maiusc+X (Cmd+Maiusc+X su macOS).
  2. Cerca zovo.zovo-protobuf e fai clic su Install. Cursor, Windsurf e VSCodium installano le estensioni da Open VSX, dove questa si chiama zovo/zovo-protobuf.
  3. Se il tuo editor non ha una galleria, scarica il file .vsix dalla pagina di Open VSX ed esegui "Extensions: Install from VSIX...".
  4. Da lì in poi funziona tutto come in VS Code.

Cosa fa Protobuf & Proto3 Formatter

  • proto2, proto3 ed editions (2023, 2024), e blocchi di codice proto in Markdown.
  • Le regole di scoping di protobuf per vai alla definizione e trova riferimenti attraverso gli import: tipi annidati, pacchetti e . iniziale.
  • Nomi integrati per i well-known types come google/protobuf/timestamp.proto.
  • Nessun falso segno rosso. Quando un import non è nel tuo workspace, la riga dell'import lo dice e i tipi che porterebbe non vengono indovinati.
  • Completamento per tipi, parole chiave, opzioni, percorsi di import e il prossimo numero di campo libero dopo =.

Cosa non fa

  • I nomi delle opzioni personalizzate vengono controllati per il loro import, ma non rispetto al tipo del campo dell'estensione.
  • I controlli delle feature delle editions coprono enum_type, le etichette, packed e i gruppi. Le altre regole delle feature sono lasciate a protoc.
  • Il formatter mantiene i tuoi a capo dentro le istruzioni lunghe. Non manda a capo le righe lunghe e non allinea = in colonna.
  • La formattazione richiede un file che si possa analizzare. Correggi prima l'errore nel pannello Problems.
  • Gli import tra file richiedono cartelle su disco. In un workspace virtuale funzionano solo evidenziazione, formattazione e outline.

Domande frequenti

È gratuito?

Evidenziazione, formattazione, vai alla definizione, trova riferimenti, errori come protoc, hover e completamento sono gratuiti. I tre strumenti Pro, Check Breaking Changes Against Git, Generate API Docs e Decode a Binary Message, hanno 3 tentativi gratuiti ciascuno. Dopo richiedono Zovo Pro, 19 USD una tantum per tutte le estensioni Zovo.

Serve protoc installato?

No. L'estensione ha un proprio parser e funziona offline. Gli errori usano la stessa formulazione di protoc.

Perché un import mostra una nota invece di segni rossi?

Il file importato non è nel tuo workspace. Aggiungi la sua cartella radice a zovoProto.importPaths, come con protoc -I.

Funziona in Cursor?

Sì. Cursor, Windsurf e VSCodium lo installano da Open VSX, dove è pubblicato come zovo/zovo-protobuf.
