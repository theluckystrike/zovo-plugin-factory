Vedere l'immagine dietro un percorso nel codice, nel gutter e al passaggio del mouse

Installa l'estensione gratuita Image Preview & Image Hover e apri un file che nomina un'immagine. Una miniatura compare nel gutter accanto alla riga, e passando il mouse sul percorso vedi l'immagine, il suo tipo, le dimensioni in pixel e il peso del file. Funziona negli import JavaScript e TypeScript, in JSX, negli url() dei CSS, in Markdown, negli attributi HTML src e srcset, in YAML e nei data URI, senza richieste di rete. Zovo Pro (19 USD una tantum) aggiunge tre strumenti, Find Unused Images, Find Broken Image References e Image Weight Report, e ognuno ha 3 tentativi gratuiti.

Passaggi in VS Code

  1. Installa Image Preview & Image Hover dal Marketplace, oppure premi Ctrl+P (Cmd+P su macOS) ed esegui ext install zovo.zovo-image-preview.
  2. Apri un file che nomina un'immagine, come import logo from './logo.png', un url() CSS o un <img src> HTML. Le miniature compaiono nel gutter, una per riga.
  3. Passa il mouse sul percorso. L'hover mostra l'immagine (ridotta per entrare nello spazio, mai ingrandita), il tipo, larghezza × altezza in pixel, il peso del file e la trasparenza, con link per aprire il file o mostrarlo nell'Explorer.
  4. Se un percorso non si risolve, l'hover lo dice ed elenca i percorsi che ha provato. Aggiungi i tuoi prefissi in imgPreview.aliases, per esempio { "@images": "src/assets/images" }, o le cartelle per i percorsi che iniziano con / in imgPreview.publicFolders.
  5. Per nascondere le miniature nel gutter, esegui "Image Preview: Show or Hide Gutter Thumbnails" dalla Command Palette.
  6. Non hai un progetto a portata di mano? Esegui "Image Preview: Open the Sample Files" per aprire un piccolo progetto demo con ogni tipo di percorso.

Cosa è gratis e cosa aggiunge Zovo Pro

Miniature nel gutter, hover, risoluzione dei percorsi con alias, paths di tsconfig.json e jsconfig.json e pacchetti di monorepo, e data URI sono gratuiti. Non serve un account, non ci sono richieste di rete né telemetria, e funziona offline.

Find Unused Images elenca le immagini del workspace (o di una cartella) che nessun file di codice, stile, Markdown, HTML, JSON o YAML nomina, dalla più grande, in un report Markdown con il loro peso. Se confermi, vengono spostate in una cartella _unused-images mantenendo la struttura delle cartelle, e Edit > Undo le riporta indietro. Così togli le vecchie immagini da un progetto senza controllare ogni nome a mano.

Usare Find Unused Images (Zovo Pro)

  1. Fai clic destro su una cartella nell'Explorer e scegli "Zovo Pro: Find unused images", oppure esegui "Image Preview: Find Unused Images (Pro)" dalla Command Palette. Se il workspace ha più di una cartella, scegli la cartella.
  2. Una notifica mostra l'avanzamento con un pulsante Cancel. Poi si apre un report Markdown con ogni immagine inutilizzata e il suo peso, dalla più grande.
  3. Fai clic su "Move N to _unused-images" per spostarle, oppure chiudi il messaggio per lasciarle dove sono. Edit > Undo le riporta indietro.
  4. Un tentativo conta solo quando il report si è aperto. Escape non ne consuma mai uno.

Passaggi in Cursor, Windsurf o VSCodium

  1. Apri la vista Extensions con Ctrl+Maiusc+X (Cmd+Maiusc+X su macOS).
  2. Cerca zovo.zovo-image-preview e fai clic su Install. Cursor, Windsurf e VSCodium installano le estensioni da Open VSX, dove questa si chiama zovo/zovo-image-preview.
  3. Se il tuo editor non ha una galleria, scarica il file .vsix dalla pagina di Open VSX ed esegui "Extensions: Install from VSIX...".
  4. Da lì in poi funziona tutto come in VS Code.

Cosa fa Image Preview & Image Hover

  • Miniature nel gutter per file PNG, JPEG, GIF, WebP, AVIF, SVG, BMP e ICO, e per gli URI data:image/.... Per i file TIFF e HEIC dimensioni e tipo vengono letti dall'intestazione del file.
  • Percorsi relativi al file, /logo.png da public/, static/ e altre cartelle radice del sito, @/ per src/, ~ per node_modules o per la cartella home, e i paths di tsconfig.json o jsconfig.json con extends.
  • Nomi di file con spazi, %20, ?v=2 o #id. Un nome semplice come beans.jpg in un file JSON viene abbinato all'immagine più vicina con quel nome.
  • Monorepo, dove vengono usati la cartella public/ e il tsconfig.json di ogni pacchetto.
  • Un URL remoto appare come link e non viene mai scaricato.

Cosa non fa

  • I percorsi costruiti durante l'esecuzione, come `icons/${name}.svg` o una concatenazione di stringhe, non hanno anteprima e possono far sembrare inutilizzata un'immagine. Controlla l'elenco delle immagini inutilizzate prima di spostare i file.
  • Una miniatura per riga, quella della prima immagine della riga. L'hover funziona per ogni percorso della riga.
  • I workspace remoti e virtuali (SSH, WSL, Codespaces, vscode.dev) non sono supportati in questa versione.
  • Gli alias di Webpack, Vite o Next.js che esistono solo in un file di configurazione JavaScript non vengono letti. Aggiungili a imgPreview.aliases o ai paths di tsconfig.json.
  • Le immagini oltre 20 MB vengono misurate ma non disegnate (impostazione imgPreview.maxFileSizeMB). Image Weight Report segnala i file pesanti ma non li comprime.

Domande frequenti

È gratuito?

Miniature nel gutter, hover e risoluzione dei percorsi sono gratuiti. I tre strumenti Pro, Find Unused Images, Find Broken Image References e Image Weight Report, hanno 3 tentativi gratuiti ciascuno. Dopo richiedono Zovo Pro, 19 USD una tantum per tutte le estensioni Zovo.

Perché il mio percorso con @/ o con un alias non mostra l'immagine?

L'alias potrebbe esistere solo in un file di configurazione di Webpack, Vite o Next.js, che non viene letto. Aggiungilo a imgPreview.aliases o ai paths di tsconfig.json.

Funziona con Remote SSH o WSL?

Non in questa versione. L'immagine dell'hover viene letta dal disco locale.

Funziona in Cursor?

Sì. Cursor, Windsurf e VSCodium lo installano da Open VSX, dove è pubblicato come zovo/zovo-image-preview.
