Ver archivos JAR y decompilar Java en VS Code

Instala JAR Viewer & Java Decompiler y haz clic en un archivo .jar, .war, .ear, .aar o .class en el Explorador: verás sus paquetes, la versión de Java de las clases, el bytecode y el código fuente decompilado. Todas las vistas son gratis, sin límite y sin inicio de sesión; para el código fuente decompilado necesitas Java 8 o superior. Zovo Pro (USD 19, un solo pago) añade la exportación de todo el código fuente de un JAR, la comparación de dos JAR y la búsqueda en todos los JAR de una carpeta, y puedes probar cada herramienta 3 veces gratis.

Instalar en VS CodePágina del MarketplaceOpen VSX (Cursor, Windsurf, VSCodium)

Gratis, licencia MIT. Extension ID zovo.zovo-jar-viewer.

Pasos en VS Code

  1. Instala JAR Viewer & Java Decompiler desde el Marketplace, o pulsa Ctrl+P (Cmd+P en macOS) y ejecuta ext install zovo.zovo-jar-viewer.
  2. Haz clic en un archivo .jar, .war, .ear, .aar o .class en el Explorador y se abrirá en el visor. Si abres un .class suelto, sus clases internas de la misma carpeta se decompilan con él.
  3. La vista Overview muestra el formato, el número de clases y paquetes, Main-Class, Created-By y un gráfico con las versiones de Java para las que se compilaron las clases.
  4. Busca una clase en el árbol de paquetes con el filtro, que encuentra clases y archivos entre 50.000 entradas mientras escribes. Al elegir una clase verás el código Java decompilado con CFR 0.152, que puedes copiar o abrir en una pestaña del editor.
  5. La pestaña de bytecode muestra un listado al estilo de javap -c -p y funciona sin Java. También tienes los miembros, el pool de constantes con filtro y los datos de la clase, como superclase, interfaces y anotaciones.
  6. Los JAR anidados, como los de BOOT-INF/lib en Spring Boot o WEB-INF/lib en un WAR, se abren un nivel hacia dentro. Los recursos de texto se abren como texto y los binarios con una vista hexadecimal.

En Cursor, Windsurf y VSCodium

Estos editores instalan extensiones desde Open VSX. Abre la vista Extensions (Ctrl+Shift+X), busca zovo.zovo-jar-viewer y pulsa Install. Su página en Open VSX es zovo/zovo-jar-viewer. Después se usa igual que en VS Code.

Qué es gratis

Todo lo que ves en el visor es gratis, sin límite y sin inicio de sesión: paquetes, clases, recursos, manifiesto, versiones de Java, bytecode, código fuente decompilado y JAR anidados. CFR 0.152 viene incluido, pero necesita un runtime de Java 8 o superior; la extensión lo busca en jarViewer.javaPath, después en JAVA_HOME y por último en el PATH. Sin Java, el resto de las vistas funciona y la pestaña de código fuente muestra una línea que explica cómo activar la decompilación, sin ventanas emergentes. El comando “JAR Viewer: Check the Java runtime used for decompiling” te dice qué Java se usa. El archivo se lee en un hilo aparte, nunca se modifica, y la extensión no usa la red ni tiene telemetría.

Qué añade Zovo Pro

Export decompiled sources of a JAR decompila un JAR completo y guarda el resultado como una carpeta de archivos .java, con una barra de progreso y la opción de cancelar. Así no tienes que abrir y copiar cada clase por separado. Las otras herramientas Pro son Compare two JARs, que crea un informe en Markdown con las clases añadidas, eliminadas y modificadas, los cambios en las firmas de métodos y campos y los cambios de versión de Java, y Find a class, method or string in every JAR of a folder, que busca una clase, un método, un campo o una constante de texto en todos los JAR de una carpeta, incluidos los anidados, como texto simple o como /regex/.

Cómo se usa Export decompiled sources of a JAR

  1. Haz clic derecho en el archivo JAR en el Explorador y elige “Zovo Pro: Export decompiled sources”, o ejecuta “JAR Viewer: Export decompiled sources of a JAR (Pro)” en la paleta de comandos.
  2. Elige la carpeta de destino. Las fuentes se guardan en una carpeta nueva con el nombre del JAR y el sufijo -src, y puedes cancelar mientras avanza. Sin Java, la herramienta guarda listados de bytecode en lugar de código Java.

Export decompiled sources of a JAR funciona 3 veces gratis antes de pedir una licencia. Al abrir un archivo no aparece ninguna ventana emergente ni cuenta atrás.

Lo que no hace

  • Para ver el código fuente decompilado necesitas un runtime de Java 8 o superior instalado. CFR se ejecuta en su propio proceso, con un límite de 45 segundos y 512 MB de memoria.
  • El código de CFR puede diferir del original en los nombres de las variables locales, en algunos genéricos y en las lambdas.
  • Los archivos anidados solo se abren un nivel hacia dentro, y los archivos APK y DEX no se leen. No puedes editar ni reempaquetar un JAR.
  • Cada entrada se descomprime hasta 64 MB, los archivos de clase hasta 16 MB y los archivos anidados hasta 128 MB, con un máximo de 200.000 entradas.

Preguntas

¿La extensión es gratis?

Sí. Ver paquetes, bytecode y código fuente decompilado es gratis y sin límite. La exportación de todo el código fuente, la comparación de dos JAR y la búsqueda en una carpeta forman parte de Zovo Pro (USD 19, un solo pago). Puedes probar cada una 3 veces gratis, y un intento solo cuenta cuando la herramienta te da un resultado.

¿Puedo decompilar sin tener Java instalado?

No. CFR es un programa Java y necesita Java 8 o superior. Sin Java, el árbol de paquetes, el bytecode, el pool de constantes y los recursos siguen funcionando.

¿Funciona en Cursor?

Sí. La extensión también está publicada en Open VSX, así que funciona en Cursor, Windsurf y VSCodium.

Todas las funciones y ajustes están en la página de JAR Viewer & Java Decompiler (en inglés).
