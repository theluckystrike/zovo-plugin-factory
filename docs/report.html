What we learned

  1. Code review is not enough. Run the app. A browser test on 2026-11-06 found that 7 of 19 Atlassian apps crashed at start, although all 7 passed review with scores of 92 to 100. We fixed and redeployed them the same morning. Now no app can be marked ready without a runtime pass on its deployed version. 17 of 19 apps pass. Bulk Page Ops is fixed (version 1.1.1 reads labels through the v2 API, because Confluence removed the old one). Portal SLA and StatusBeacon need a Jira Service Management project to test.
  2. Store search is where Apify users come from, and we are not in it. For 10 of our 11 main keywords, none of our Actors is in the top 100 Store results. The top 10 for "youtube transcript" have 15,238 users in 30 days. Free channels such as Discord and Reddit bring about 7 paying users in total.
  3. The Atlassian apps hold most of the expected money. The base case is about $92,000 in 12 months for all 19 apps. The first 5 to list are AskSpace ($23,000), SignOff ($13,600), Markdown + Mermaid ($8,100), MathBlock ($7,900) and EpicTotals ($5,700). These are estimates from rival install rates, and the method is on the Money page.
  4. VS Code is the only store with real pull. Context Drift has 95 downloads with no promotion (highest of 6 readings, because Marketplace servers return different counts). On 2026-11-06 we added 5 file-viewer extensions. They are Skill Shelf, Tensor Viewer, HDF5 NetCDF Explorer, DOCX Viewer and PPTX Slide Viewer. 8 extensions are now live. Each has a public repo and a landing page on this site.
  5. The Apify numbers are almost all ours. Each Actor shows 2 users, which are our account and the Apify daily auto-test. All runs are our tests and fixes. Apify Store search takes days to rank new Actors, so a quiet first day is normal.
  6. The 19 Atlassian apps are the largest stock of finished work. They are built, reviewed and deployed. They earn nothing until the owner adds partner payment and tax details and we submit paid Marketplace listings.
  7. Owner steps are the bottleneck, not building. The sprints shipped 46 products. 4 owner steps block the money. They are the Open VSX Publisher Agreement, Apify business verification, the Atlassian Partner Agreement and verification, and Atlassian payment details. Free Atlassian listings do not need bank details.
  8. Free on Atlassian is permanent. If an app moves from free to paid, existing installs lock until an admin subscribes. Apps that run in Jira and Confluence must keep licensing, so Issue Dates Calendar stays paid. 7 apps are now free builds, to collect installs and reviews first.
  9. The VS Code Marketplace limits new extensions to 7 in 12 hours. Updates have no limit. The web upload form dropped uploads with no error, so for 5 hours no new extension went live. Trusted publishing through GitHub Actions fixed it on 2026-11-06. 7 new extensions went live in 15 minutes, and the next ones publish by script when a slot opens.
  10. Building is fast. Store limits set the pace. Agents build and test a new viewer in 25 to 40 minutes, including a test in a real VS Code window. The queue holds 8 finished extensions and 3 more are being built. At about 7 new extensions each 12 hours, the queue is full until 2026-11-08.
  11. A test in real VS Code finds bugs that unit tests miss. The release test ran JSONL, SQLite and Agent Session viewers in a real VS Code window. It found and fixed 6 bugs. All unit tests had passed before.
  12. Search rank comes from the display name. In Marketplace search, the exact search words in the display name decide the rank group. Inside a group, shorter names that start with the words win, then installs. Keywords only break ties. We renamed all 8 live extensions to match this, for example "CSV Viewer, Excel Viewer & Parquet Viewer".
  13. Open VSX has real demand for the same viewers. On Open VSX (used by Cursor and Windsurf), one JSONL viewer has 24,478 downloads and one CSV extension has 361,835. We have 0 there. One script publishes all our extensions when the owner signs the Open VSX agreement.
  14. Ratings help search, so each extension now asks one time. All 15 of our extensions now ask for a rating one time, after 5 good uses over at least 2 days. The prompt never shows in the first session, and the user can turn it off. The extensions send no telemetry.
  15. The review loop worked. Each product went through independent reviews until it scored 92 to 100. Reviews caught an App Reviews run that could hang, a silent install failure in MathBlock, and a Secret Scanner setting that Atlassian does not allow.
  16. First builds always failed their first review. The median first score was 56. One fix round added 15 to 45 points. A reviewer on a different seat finds what the builder misses.
  17. Research prices were 3 to 4 times too high. We now price against the cheapest working rival, at $0.0001 per review, $0.001 per trends result and $0.0025 per transcript.
  18. A real platform run is part of the gate now. All 4 first Actors failed the Apify empty-input auto-test, and no reviewer caught it. Every prefill field now needs a default.

1. How the rating works

  • Each market gets 8 factors, each 0 to 100. Higher is better for a builder.
  • The weights (v2, fixed after the pass-3 review) are demand 15, gap 15, agent ease 15, monetization 12, revenue evidence 15, review speed 5, platform stability 8. Evidence confidence is used once, as the multiplier below.
  • Raw = weighted average of the 8 factors.
  • Final = Raw x (0.7 + 0.3 x evidence confidence / 100). Weak evidence lowers the final score by up to 30%.
  • A row marked provisional uses pass-1 inputs. Nobody researched its revenue in pass 2. Its confidence is 35.
  • Do not trust a gap of less than 5 points between two markets.

3. Biggest insights

  1. Money proof is rare. Only Modrinth, Tebex, JetBrains prices, Craft CMS and Atlassian Forge have fetched revenue data. For most other markets nobody published seller income.
  2. Top markets pay little to the average seller. Modrinth paid creators $176,855 in 29 days. That is about $31 per author per year across 71,756 authors. A typical paid Craft plugin has about 12 active installs at $49. Only the leaders earn well.
  3. JetBrains is the best paid-plugin market for an agent builder. It has 529 paid plugins, a 15% commission, and top personal prices of $10 to $39 per year. A person reviews each update.
  4. The agent-instruction validator gap is real but not empty. The rival agnix has 236,872 JetBrains downloads and 269 VS Code installs. It is not on Open VSX, which has smaller rivals (2,144 and 986). Hermes confirmed this from the store APIs.
  5. Pass 1 had errors. Canva can pay developers (Premium Apps Program). Steam open Workshops can sell paid items. Xero dropped revenue share and now charges developers AUD 35 to 1,445 per month. Joplin and SiYuan already have some of the plugin types we called gaps.
  6. Apify Store is the one proven payout channel near MCP. Apify paid developers $1.7M last month. 795 of its top 855 Actors charge per event. But buyers pay for data, not for an MCP wrapper. The best "mcp" Actor has 94 users in 30 days.
  7. Telegram Stars money is proven for games only. Durov posted $16M (Catizen) and $500k in 10 days (a solo Mini App). No public revenue exists for non-game utility bots. That niche is open, not proven. Stars pay $0.013 each after a 21-day hold.
  8. Discord keeps 15% of the first $1M (about 20% with fees), then 30%. Payouts start after $100 and a review. No public Premium App revenue exists.
  9. For chat bots, change the niche. AI moderation on Discord is crowded (832 apps). A standup or task bot has 10 apps. The biggest one is in 3,490 servers.
  10. Every market needs one human step. ID check, Stripe onboarding, KYC, first listing, or 2FA. An agent can do the rest. See the "Human steps" line in each row.
  11. Key dates. VS Code PAT publishing ends 2026-12-01. Use GitHub Actions OIDC. Gemini CLI lost its free tier on 2026-06-18.

  3. Find the market in section 2. Open its row. Read "Human steps" and "First command".
  4. Ask the owner to do the human steps. Do not skip them.
  5. Build in ~/<project>-work/. Do not use /private/tmp.
  6. For a private repo, run gh api repos/OWNER/REPO --jq .private. Push one time at the end.
  7. Run the first command. Record the listing URL and the date.
  8. Publish few items. Mass submission can get an account banned.
  9. Delete temporary folders. Write each deletion in a manifest.
