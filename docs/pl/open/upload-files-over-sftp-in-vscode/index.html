Jak wysyłać pliki na serwer przez SFTP lub FTP z VS Code

Zainstaluj darmowe rozszerzenie SFTP & FTP Sync and Upload i utwórz plik .vscode/sftp.json z hostem, użytkownikiem i folderem na serwerze. Od tej pory każdy plik jest wysyłany przy zapisie, przez SFTP, FTP lub FTPS. Po kliknięciu prawym przyciskiem pliku lub folderu można go wysłać albo pobrać, a plik można też porównać z kopią na serwerze. W widoku Remote Files pliki z serwera otwierają się w zwykłej karcie. Folder .vscode, pliki .env i klucze prywatne nigdy nie są wysyłane. Wszystko to jest darmowe i nie wymaga konta. Zovo Pro (19 USD jednorazowo) dodaje trzy narzędzia, Sync Folder with Remote, Roll Back a Remote File i Server Profiles and Jump Host, a każde z nich ma 3 darmowe próby.

Kroki w VS Code

  1. Zainstaluj SFTP & FTP Sync and Upload z Marketplace albo naciśnij Ctrl+P (Cmd+P w macOS) i uruchom ext install zovo.zovo-sftp.
  2. Uruchom „SFTP: Create sftp.json Config” z Command Palette albo kliknij Create sftp.json w widoku SFTP Remote.
  3. Uzupełnij protocol (sftp, ftp lub ftps), host, username, privateKeyPath (pomiń go, aby logować się hasłem) i remotePath, czyli folder na serwerze odpowiadający folderowi lokalnemu. Po najechaniu kursorem na dowolny klucz pojawia się jego opis.
  4. Ustaw "uploadOnSave": true. Od tej chwili każdy zapisany plik jest wysyłany. O wpisane hasło rozszerzenie pyta tylko raz i przechowuje je w bezpiecznym magazynie edytora (secret storage), nigdy w sftp.json.
  5. Kliknij prawym przyciskiem plik lub folder w Explorer albo kartę i wybierz Upload, Download lub Compare with Server Copy (Compare działa tylko dla plików).
  6. Otwórz widok Remote Files, aby przeglądać serwer. Plik można otworzyć w zwykłej karcie edytora i zapisać z powrotem, pobrać, skopiować jego ścieżkę lub usunąć. „SFTP: Show Transfer Log” pokazuje każde połączenie i każdy transfer.

Co jest za darmo, a co dodaje Zovo Pro

Wysyłanie przy zapisie, Upload, Download i Compare with Server Copy, widok Remote Files, SFTP, FTP i FTPS, sprawdzanie klucza hosta oraz dziennik transferów są darmowe, bez konta i bez logowania gdziekolwiek poza własnym serwerem. Rozszerzenie nie zbiera telemetrii.

Gdy zawartość serwera i folderu lokalnego się rozjedzie, Sync Folder with Remote porównuje je i pokazuje każdą różnicę, zanim cokolwiek zostanie przeniesione: pliki tylko lokalne, tylko na serwerze lub nowsze po jednej stronie. Dla każdego pliku wybierasz wysłanie, pobranie, usunięcie lub pominięcie, możesz otworzyć porównanie obok siebie i zapisać próbny przebieg jako tekst, a potem zastosować plan. Dokładnie widać, co zmieni się na serwerze, zanim to nastąpi.

Narzędzie Sync Folder with Remote (Zovo Pro)

  1. Kliknij prawym przyciskiem folder w Explorer i wybierz „Zovo Pro: Sync folder with remote (diff preview)” albo uruchom „SFTP: Sync Folder with Remote, Diff Preview (Pro)...” z Command Palette. Ten sam przycisk jest na pasku tytułu widoku Remote Files.
  2. Przeczytaj plan. Dla każdego pliku wybierz wysłanie, pobranie, usunięcie lub pominięcie, a w razie wątpliwości otwórz porównanie pliku.
  3. Zastosuj plan. Próba jest liczona tylko wtedy, gdy plan synchronizacji został wyświetlony. Escape ani Cancel nigdy jej nie zużywają.

Sync Folder with Remote działa 3 razy na twoim komputerze, zanim poprosi o licencję. Przy otwieraniu pliku nie ma wyskakujących okienek ani odliczania.

Kroki w Cursor, Windsurf lub VSCodium

  1. Otwórz widok Extensions skrótem Ctrl+Shift+X (Cmd+Shift+X w macOS).
  2. Wyszukaj zovo.zovo-sftp i kliknij Install. Cursor, Windsurf i VSCodium instalują rozszerzenia z Open VSX, gdzie to rozszerzenie ma nazwę zovo/zovo-sftp.
  3. Jeśli edytor nie ma galerii rozszerzeń, pobierz plik .vsix ze strony Open VSX i uruchom „Extensions: Install from VSIX...”.
  4. Dalej wszystko działa tak samo jak w VS Code.

Co otwiera SFTP & FTP Sync and Upload

  • SFTP z kluczami SSH, zaszyfrowanymi kluczami, agentem SSH lub hasłem; FTP; FTPS z jawnym lub niejawnym TLS.
  • .vscode, .git, pliki .env, klucze prywatne, .npmrc i inne pliki z sekretami nigdy nie są wysyłane. Własne wzorce można dodać w ignore, w stylu .gitignore.
  • Klucz hosta serwera jest sprawdzany: można go przypiąć w hostFingerprint albo potwierdzić przy pierwszym połączeniu. Zmieniony klucz zatrzymuje połączenie.
  • W folderze, który nie jest zaufany (Restricted Mode), rozszerzenie pozostaje wyłączone, więc pobrany projekt nie może nigdzie wysłać plików.
  • Są jeszcze dwa narzędzia Pro. Roll Back a Remote File przechowuje na komputerze 10 ostatnich kopii pliku z serwera, zanim wysyłanie go nadpisze. Server Profiles and Jump Host pozwala zapisać kilka serwerów (staging, produkcja) w jednym sftp.json i łączyć się przez pośredni host SSH (jump host).

Czego nie robi

  • Jedno połączenie z serwerem naraz, a transfery FTP odbywają się jeden po drugim.
  • Dowiązania symboliczne na serwerze działają dla plików, ale dowiązane foldery są pomijane przy wysyłaniu, pobieraniu i synchronizacji folderów.
  • Klucze w formacie PuTTY .ppk trzeba najpierw przekonwertować do OpenSSH (puttygen key.ppk -O private-openssh -o key).
  • Synchronizacja porównuje rozmiar i czas modyfikacji, a potem bajty plików o tym samym rozmiarze, do 300 plików lub 64 MB na jedno uruchomienie.
  • Kopie do wycofania zmian są domyślnie zachowywane dla plików do 5 MB i tylko na tym komputerze.

Pytania

Czy to jest darmowe?

Wysyłanie przy zapisie, Upload, Download, Compare with Server Copy, widok Remote Files i dziennik transferów są darmowe dla SFTP, FTP i FTPS. Trzy narzędzia Pro, Sync Folder with Remote, Roll Back a Remote File i Server Profiles and Jump Host, mają po 3 darmowe próby. Potem potrzebny jest Zovo Pro, 19 USD jednorazowo za wszystkie rozszerzenia Zovo.

Czy hasło jest zapisywane w sftp.json?

Nie. Wpisane hasło lub hasło do klucza jest przechowywane w bezpiecznym magazynie edytora. Jeśli w sftp.json nie ma password, rozszerzenie zapyta o hasło raz.

Czy plik .env zostanie wysłany?

Nie. .vscode, .git, pliki .env, klucze prywatne i .npmrc są na domyślnej liście wykluczeń i nigdy nie są wysyłane.

Czy VS Code może wysyłać pliki przez SFTP bez rozszerzenia?

Nie. VS Code nie ma wysyłania przez SFTP ani FTP. Remote SSH edytuje pliki bezpośrednio na serwerze. Do wysłania lokalnego projektu potrzebne jest rozszerzenie albo scp i rsync w terminalu.
