Edycja plików .proto w VS Code z kolorowaniem składni, formatowaniem i przejściem do definicji

Zainstaluj darmowe rozszerzenie Protobuf & Proto3 Formatter i otwórz folder z plikami .proto. Dodaje ono kolorowanie składni, formatter, który zachowuje każdy komentarz, przejście do definicji, wyszukiwanie odwołań i błędy w brzmieniu protoc, dla proto2, proto3 oraz edycji (editions) 2023 i 2024. Działa offline z własnym parserem, więc nie potrzeba protoc, serwera języka ani konfiguracji, a wszystko to jest darmowe. Zovo Pro (19 USD jednorazowo) dodaje trzy narzędzia, Check Breaking Changes Against Git, Generate API Docs i Decode a Binary Message, a każde z nich ma 3 darmowe próby.

Kroki w VS Code

  1. Zainstaluj Protobuf & Proto3 Formatter z Marketplace albo naciśnij Ctrl+P (Cmd+P w macOS) i uruchom ext install zovo.zovo-protobuf.
  2. Otwórz folder z plikami .proto. Kolorowanie składni, konspekt (outline) i ścieżka nawigacji (breadcrumbs) działają od razu.
  3. Naciśnij Shift+Alt+F (Shift+Option+F na macOS), aby sformatować plik, albo włącz editor.formatOnSave. Wynik to jedna instrukcja w wierszu, wcięcia ustawione w edytorze i pojedyncze spacje wokół =. Komentarze, grupy pustych wierszy i Twoje łamania wierszy w długich instrukcjach zostają na miejscu.
  4. Naciśnij F12 na typie lub imporcie, aby przejść do definicji, a Shift+F12, aby wyświetlić jego użycia. Ctrl+klik lub Cmd+klik na imporcie otwiera plik. Po najechaniu na typ widać jego pola i komentarz.
  5. Błędy pojawiają się w panelu Problems w brzmieniu protoc: zduplikowane numery pól (z kolejnym wolnym numerem), nieznane typy, typy użyte bez importu, zastrzeżone numery i nazwy oraz reguły proto3 i edycji. Nieużywane importy są wyszarzone.
  6. Jeśli importy zaczynają się od folderu takiego jak proto/ lub third_party/, rozszerzenie znajduje je, idąc w górę od każdego pliku. Inne katalogi główne dodaj do ustawienia zovoProto.importPaths, tak jak w protoc -I.

Co jest za darmo, a co dodaje Zovo Pro

Kolorowanie składni (także bloków kodu proto w Markdownie), Format Document, przejście do definicji, wyszukiwanie odwołań, błędy w stylu protoc, konspekt, Go to Symbol in workspace, podpowiedzi po najechaniu i uzupełnianie, w tym kolejny wolny numer pola po =, są darmowe. Nie ma logowania, żądań sieciowych ani telemetrii.

Przed scaleniem zmiany w pliku .proto narzędzie Check Breaking Changes Against Git porównuje Twoje pliki z main (lub z ustawioną gałęzią) i wypisuje usunięte pola, zmienione numery, typy i etykiety, pola i wartości enum o zmienionych nazwach oraz usunięte lub zmienione metody. Przy każdym wyniku widać, czy psuje dane binarne, JSON, czy tylko wygenerowany kod. Dzięki temu wiadomo, co starzy klienci odczytają źle, zanim to się stanie. Wyniki można zapisać w pliku JSON dla CI.

Narzędzie Check Breaking Changes Against Git (Zovo Pro)

  1. Kliknij prawym przyciskiem plik .proto lub folder w widoku Explorer i wybierz „Zovo Pro: Check breaking changes against git”, kliknij prawym przyciskiem w edytorze pliku .proto i wybierz „Check Breaking Changes Against Git (Pro)” albo uruchom „Protobuf: Check Breaking Changes Against Git (Pro)” z Command Palette. Folder musi być w repozytorium git, a git musi być zainstalowany.
  2. Sprawdzenie porównuje wszystkie pliki .proto repozytorium w kopii roboczej, łącznie z niezapisanymi zmianami, z merge base gałęzi origin/main, main, origin/master lub master (pierwszej, która istnieje) albo gałęzi z ustawienia zovoProto.baseBranch. Otwiera się raport Markdown z wynikami pogrupowanymi według plików.
  3. Kliknij „Save JSON for CI” w komunikacie, aby zachować wyniki w pliku proto-breaking.json.
  4. Próba liczy się tylko wtedy, gdy raport się otworzył. Folder poza gitem lub brak gałęzi bazowej nie zużywa próby.

Check Breaking Changes Against Git działa 3 razy na twoim komputerze, zanim poprosi o licencję. Przy otwieraniu pliku nie ma wyskakujących okienek ani odliczania.

Kroki w Cursor, Windsurf lub VSCodium

  1. Otwórz widok Extensions skrótem Ctrl+Shift+X (Cmd+Shift+X w macOS).
  2. Wyszukaj zovo.zovo-protobuf i kliknij Install. Cursor, Windsurf i VSCodium instalują rozszerzenia z Open VSX, gdzie to rozszerzenie ma nazwę zovo/zovo-protobuf.
  3. Jeśli edytor nie ma galerii rozszerzeń, pobierz plik .vsix ze strony Open VSX i uruchom „Extensions: Install from VSIX...”.
  4. Dalej wszystko działa tak samo jak w VS Code.

Co otwiera Protobuf & Proto3 Formatter

  • proto2, proto3 i edycje (2023, 2024) oraz bloki kodu proto w Markdownie.
  • Reguły zasięgu protobuf przy przejściu do definicji i wyszukiwaniu odwołań przez importy: typy zagnieżdżone, pakiety i początkowa ..
  • Wbudowane nazwy typów well-known, np. google/protobuf/timestamp.proto.
  • Bez fałszywych czerwonych oznaczeń: gdy importu nie ma w obszarze roboczym, informuje o tym wiersz importu, a typy, które by wnosił, nie są zgadywane.
  • Uzupełnianie typów, słów kluczowych, opcji, ścieżek importu i kolejnego wolnego numeru pola po =.

Czego nie robi

  • Nazwy opcji niestandardowych są sprawdzane pod kątem importu, ale nie względem typu pola rozszerzenia.
  • Sprawdzanie funkcji edycji obejmuje enum_type, etykiety, packed i grupy. Pozostałe reguły funkcji zostają dla protoc.
  • Formatter zachowuje Twoje łamania wierszy w długich instrukcjach. Nie zawija długich wierszy i nie wyrównuje = w kolumnach.
  • Formatowanie wymaga pliku, który da się sparsować. Najpierw popraw błąd pokazany w panelu Problems.
  • Importy między plikami wymagają folderów na dysku. W wirtualnym obszarze roboczym działają tylko kolorowanie, formatowanie i konspekt.

Pytania

Czy to jest darmowe?

Kolorowanie składni, formatowanie, przejście do definicji, wyszukiwanie odwołań, błędy w stylu protoc, podpowiedzi po najechaniu i uzupełnianie są darmowe. Trzy narzędzia Pro, Check Breaking Changes Against Git, Generate API Docs i Decode a Binary Message, mają po 3 darmowe próby. Potem wymagają Zovo Pro, 19 USD jednorazowo za wszystkie rozszerzenia Zovo.

Czy trzeba instalować protoc?

Nie. Rozszerzenie ma własny parser i działa offline. Błędy mają to samo brzmienie co w protoc.

Dlaczego przy imporcie jest uwaga zamiast czerwonych oznaczeń?

Importowanego pliku nie ma w obszarze roboczym. Dodaj jego folder główny do zovoProto.importPaths, tak jak w protoc -I.

Czy działa w Cursor?

Tak. Cursor, Windsurf i VSCodium instalują je z Open VSX, gdzie jest opublikowane jako zovo/zovo-protobuf.
