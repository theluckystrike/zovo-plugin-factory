Jak zobaczyć obraz ze ścieżki w kodzie, na marginesie i po najechaniu myszą

Zainstaluj darmowe rozszerzenie Image Preview & Image Hover i otwórz plik, który wskazuje obraz. Na marginesie (gutter) obok linii pojawia się miniatura, a po najechaniu myszą na ścieżkę widać obraz, jego typ, rozmiar w pikselach i rozmiar pliku. Działa w importach JavaScript i TypeScript, JSX, CSS url(), Markdown, HTML src i srcset, YAML oraz data URI, bez żądań sieciowych. Zovo Pro (19 USD jednorazowo) dodaje trzy narzędzia, Find Unused Images, Find Broken Image References i Image Weight Report, a każde z nich ma 3 darmowe próby.

Kroki w VS Code

  1. Zainstaluj Image Preview & Image Hover z Marketplace albo naciśnij Ctrl+P (Cmd+P w macOS) i uruchom ext install zovo.zovo-image-preview.
  2. Otwórz plik, który wskazuje obraz, np. import logo from './logo.png', CSS url() lub HTML <img src>. Miniatury pojawiają się na marginesie, jedna na linię.
  3. Najedź myszą na ścieżkę. Okienko pokazuje obraz (zmniejszony do rozmiaru okienka, nigdy powiększony), jego typ, szerokość × wysokość w pikselach, rozmiar pliku i przezroczystość, z linkami do otwarcia pliku lub pokazania go w widoku Explorer.
  4. Jeśli ścieżki nie da się odnaleźć, okienko o tym informuje i podaje sprawdzone ścieżki. Własne prefiksy dodaje się w imgPreview.aliases, np. { "@images": "src/assets/images" }, a foldery dla ścieżek zaczynających się od / w imgPreview.publicFolders.
  5. Aby ukryć miniatury na marginesie, uruchom z Command Palette polecenie „Image Preview: Show or Hide Gutter Thumbnails”.
  6. Brak projektu pod ręką? Uruchom polecenie „Image Preview: Open the Sample Files”, aby otworzyć mały projekt demonstracyjny ze wszystkimi rodzajami ścieżek.

Co jest za darmo, a co dodaje Zovo Pro

Miniatury na marginesie, okienko z podglądem, rozpoznawanie ścieżek z aliasami, paths z tsconfig.json i jsconfig.json, pakiety monorepo oraz data URI są darmowe. Nie ma konta, żądań sieciowych ani telemetrii, a rozszerzenie działa offline.

Find Unused Images wypisuje obrazy z przestrzeni roboczej (lub z jednego folderu), których nie wskazuje żaden plik kodu, stylów, Markdown, HTML, JSON ani YAML, od największego, w raporcie Markdown z ich rozmiarami. Po potwierdzeniu trafiają do folderu _unused-images z zachowaną strukturą folderów, a Edit > Undo przenosi je z powrotem. Stare obrazy znikają z projektu bez ręcznego sprawdzania każdej nazwy.

Narzędzie Find Unused Images (Zovo Pro)

  1. Kliknij prawym przyciskiem folder w widoku Explorer i wybierz „Zovo Pro: Find unused images” albo uruchom z Command Palette polecenie „Image Preview: Find Unused Images (Pro)”. Przy kilku folderach w przestrzeni roboczej wybierz folder.
  2. Powiadomienie pokazuje postęp z przyciskiem Cancel. Potem otwiera się raport Markdown z każdym nieużywanym obrazem i jego rozmiarem, od największego.
  3. Kliknij „Move N to _unused-images”, aby je przenieść, albo zamknij komunikat, aby zostały na miejscu. Edit > Undo przenosi je z powrotem.
  4. Próba liczy się tylko wtedy, gdy raport się otworzył. Escape nigdy jej nie zużywa.

Find Unused Images działa 3 razy na twoim komputerze, zanim poprosi o licencję. Przy otwieraniu pliku nie ma wyskakujących okienek ani odliczania.

Kroki w Cursor, Windsurf lub VSCodium

  1. Otwórz widok Extensions skrótem Ctrl+Shift+X (Cmd+Shift+X w macOS).
  2. Wyszukaj zovo.zovo-image-preview i kliknij Install. Cursor, Windsurf i VSCodium instalują rozszerzenia z Open VSX, gdzie to rozszerzenie ma nazwę zovo/zovo-image-preview.
  3. Jeśli edytor nie ma galerii rozszerzeń, pobierz plik .vsix ze strony Open VSX i uruchom „Extensions: Install from VSIX...”.
  4. Dalej wszystko działa tak samo jak w VS Code.

Co otwiera Image Preview & Image Hover

  • Miniatury dla plików PNG, JPEG, GIF, WebP, AVIF, SVG, BMP i ICO oraz dla URI data:image/.... Pliki TIFF i HEIC dostają rozmiar i typ odczytane z nagłówka.
  • Ścieżki względne wobec pliku, /logo.png z public/, static/ i innych folderów głównych serwisu, @/ dla src/, ~ dla node_modules lub folderu domowego oraz paths z tsconfig.json lub jsconfig.json razem z extends.
  • Nazwy plików ze spacjami, %20, ?v=2 lub #id. Sama nazwa, taka jak beans.jpg w JSON, jest dopasowywana do najbliższego obrazu o tej nazwie.
  • Monorepo, w którym dla każdego pakietu używany jest jego własny folder public/ i tsconfig.json.
  • Zdalny URL wyświetla się jako link i nigdy nie jest pobierany.

Czego nie robi

  • Ścieżek tworzonych w czasie działania kodu, takich jak `icons/${name}.svg` albo łączenie napisów, nie da się podejrzeć, a przez nie obraz może wyglądać na nieużywany. Przed przeniesieniem plików trzeba sprawdzić listę nieużywanych obrazów.
  • Jedna miniatura na linię, czyli pierwszy obraz w tej linii. Okienko po najechaniu myszą działa dla każdej ścieżki w linii.
  • Zdalne i wirtualne przestrzenie robocze (SSH, WSL, Codespaces, vscode.dev) nie są obsługiwane w tej wersji.
  • Aliasy Webpack, Vite lub Next.js, które istnieją tylko w pliku konfiguracyjnym JavaScript, nie są odczytywane. Należy je dodać do imgPreview.aliases lub do paths w tsconfig.json.
  • Obrazy większe niż 20 MB są mierzone, ale nie są rysowane (ustawienie imgPreview.maxFileSizeMB). Image Weight Report oznacza ciężkie pliki, ale ich nie kompresuje.

Pytania

Czy to jest darmowe?

Miniatury na marginesie, okienko z podglądem i rozpoznawanie ścieżek są darmowe. Trzy narzędzia Pro, Find Unused Images, Find Broken Image References i Image Weight Report, mają po 3 darmowe próby. Potem wymagają Zovo Pro, 19 USD jednorazowo za wszystkie rozszerzenia Zovo.

Dlaczego ścieżka z @/ lub aliasem nie pokazuje obrazu?

Alias może istnieć tylko w pliku konfiguracyjnym Webpack, Vite lub Next.js, który nie jest odczytywany. Należy go dodać do imgPreview.aliases lub do paths w tsconfig.json.

Czy działa przez Remote SSH lub WSL?

Nie w tej wersji. Obraz w okienku jest odczytywany z dysku lokalnego.

Czy działa w Cursor?

Tak. Cursor, Windsurf i VSCodium instalują je z Open VSX, gdzie jest opublikowane jako zovo/zovo-image-preview.
