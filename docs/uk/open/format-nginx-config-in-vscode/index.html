Як це зробити у VS Code

  1. Встановіть Nginx Config Formatter & Lint з Marketplace або натисніть Ctrl+P (Cmd+P на macOS) і виконайте ext install zovo.zovo-nginx-config.
  2. Відкрийте конфігурацію. Вона відкривається як nginx, коли файл має назву nginx.conf або закінчується на .nginx чи .nginxconf, коли це файл .conf у папці з назвою nginx (як-от /etc/nginx/conf.d/default.conf) або файл у nginx/sites-available, nginx/sites-enabled чи nginx/snippets. Для будь-якого іншого файлу виберіть мовний режим "nginx".
  3. Натисніть Shift+Alt+F (Shift+Option+F на Mac). Ви отримуєте одну інструкцію на рядок із відступами вашого редактора, довгі значення log_format зберігають свої розриви рядків, а поспіль лишається щонайбільше один порожній рядок (налаштування nginxConfig.format.maxBlankLines).
  4. Проблеми з'являються під час введення: пропущена ;, незакриті або зайві фігурні дужки, незакриті рядки, директива не в тому блоці, дубльовані root або listen, два сервери з однаковим ім'ям на одному порту. Натисніть Ctrl+. (Cmd+. на Mac), щоб застосувати швидке виправлення, як-от "Add the missing ";"" або заміну proxy_set_heder на proxy_set_header.
  5. Наведіть курсор на директиву, щоб побачити її синтаксис, значення за замовчуванням, дозволені блоки й посилання на документацію nginx. Автодоповнення пропонує директиви, дозволені в поточному блоці, і змінні після $.
  6. Натисніть значок списку в заголовку редактора або виконайте "Nginx: Show Config Overview", щоб побачити кожен сервер із його портами й іменами та кожен location з тим, що він робить, разом із файлами include. Клацніть файл і рядок, щоб перейти туди.

Він шукає TLS 1.0 і 1.1, слабкі шифри, HTTPS-сервери без HSTS та інших заголовків безпеки, location, чий власний add_header непомітно відкидає ці заголовки, обхід шляху через alias без скісної риски (off-by-slash), proxy_pass на хост, узятий із запиту, доступні файли .git і .env, перелік вмісту папок і необмежене тіло запиту. Ви знаходите ці помилки до того, як конфігурація потрапить у продакшн, не читаючи вручну кожен файл include.

Як встановити в Cursor, Windsurf або VSCodium

  1. Відкрийте панель Extensions клавішами Ctrl+Shift+X (Cmd+Shift+X на macOS).
  2. Знайдіть zovo.zovo-nginx-config і натисніть Install. Cursor, Windsurf і VSCodium встановлюють розширення з Open VSX, де це розширення опубліковано як zovo/zovo-nginx-config.
  3. Якщо у вашому редакторі немає каталогу розширень, завантажте файл .vsix зі сторінки Open VSX і виконайте «Extensions: Install from VSIX...».
  4. Далі все працює так само, як у VS Code.

Що вміє Nginx Config Formatter & Lint

  • Директиви OpenResty/Lua, headers-more, Brotli, Passenger та інших поширених модулів відомі й ніколи не позначаються як помилка.
  • Блоки Lua, як-от content_by_lua_block, підсвічуються як Lua.
  • Подання Outline перелічує сервери з їхніми іменами й портами, location, upstream і map.
  • Відносні include зчитуються з nginxConfig.prefix, папки файлу, її батьківської папки або /etc/nginx, саме в такому порядку.
  • Огляд і Pro-інструменти враховують незбережені зміни у відкритих редакторах.

Чого розширення не робить

  • Форматер ставить один пробіл між директивою та її значеннями, тому вирівнювання стовпцями, як-от listen 80;, не зберігається.
  • Файл із незакритою фігурною дужкою або рядком не форматується. Він лишається без змін, а рядок стану пояснює чому.
  • Перевірки читають ваші файли й не запускають nginx -t. Відсутній файл сертифіката або незавантажений модуль знайде лише сам nginx.
  • Регулярні вирази location перевіряються як регулярні вирази JavaScript. Кілька можливостей, які є лише в PCRE (possessive-квантифікатори, рекурсія), перевірити не можна, і про них повідомляється як про пропущені.

Чи може форматування зламати мою конфігурацію?

Ні. Форматер розбирає власний результат і нічого не змінює, якщо файл читався б інакше, тож коректна конфігурація лишається коректною.

Чи замінює воно nginx -t?

Ні. Воно читає ваші файли й перевіряє синтаксис і місце кожної директиви. Для сертифікатів і модулів запустіть nginx -t на сервері.
