Як це зробити у VS Code

  1. Встановіть Dotenv & .env File Editor з Marketplace або натисніть Ctrl+P (Cmd+P на macOS) і виконайте ext install zovo.zovo-dotenv.
  2. Відкрийте файл .env (а також .env.local, .env.production, *.env або .flaskenv). Ключі, export, значення, багаторядкові значення й посилання ${NAME} отримують кольори.
  3. Значення, схожі на секрети, показуються крапками, доки курсор не стане на їхній рядок. Щоб показати всі, натисніть кнопку з оком у заголовку редактора або виконайте "Dotenv: Show or Hide Secret Values". Шаблони на кшталт .env.example ніколи не приховуються.
  4. Проблеми з'являються в панелі Problems: ключ задано двічі, пробіли навколо =, лапка, яку не закрито, рядок без =, недопустиме ім'я, пробіли в кінці рядка або ${NAME}, який не задає жоден рядок. Натисніть Ctrl+. (Cmd+. на Mac) на проблемі, щоб виправити її.
  5. Виконайте Format Document, щоб прибрати пробіли навколо = і в кінці рядків. Коментарі, порядок і лапки лишаються як є.
  6. Щоб скопіювати значення, не показуючи його, виконайте "Dotenv: Copy the Value on This Line". Команда копіює значення без лапок і екранування, навіть коли воно приховане.
  7. У коді наведіть курсор на process.env.DB_HOST, os.getenv("X"), System.getenv("X") тощо, щоб побачити, який файл .env задає змінну, і натисніть F12, щоб відкрити цей рядок.

Що безкоштовно і що додає Zovo Pro

Підсвічування синтаксису, приховані секретні значення, проблеми зі швидкими виправленнями, Format Document, структура ключів, Copy the Value on This Line, а також підказки при наведенні, перехід до визначення й автодоповнення в коді безкоштовні. Немає облікового запису, мережевих запитів і телеметрії.

Compare .env with .env.example показує ключі, яких бракує в .env, ключі, яких не описано в .env.example, і порожні ключі у звіті поруч із файлом. Потім кнопки додають відсутні ключі в будь-який із двох файлів: у .env зі значеннями з прикладу або в .env.example з порожніми значеннями. Значення з .env ніколи не показуються й не копіюються, тож ви можете вирівняти налаштування колеги або деплой, що падає, не читаючи файл рядок за рядком.

Що вміє Dotenv & .env File Editor

  • Файли .env, .env.* (як-от .env.local і .env.production), *.env і .flaskenv.
  • Які значення приховано: імена з PASSWORD, TOKEN, SECRET, API_KEY, DSN, DATABASE_URL тощо, або всі значення, або жодне (налаштування envFile.maskValues).
  • Підказки й перехід до визначення в коді для process.env і import.meta.env (JavaScript, TypeScript), os.environ і os.getenv (Python), os.Getenv (Go), ENV (Ruby), System.getenv (Java), env() (PHP) та інших.
  • Автодоповнення ключів після process.env..
  • Приховані значення лишаються прихованими в структурі, підказках і автодоповненні, якщо це не вимкнути (налаштування envFile.hoverShowsSecrets).

Чого розширення не робить

  • Приховування діє лише на екрані. Текст і далі є у файлі, у результатах пошуку й у формі на мінікарті, а копіювання і вставлення переносять справжнє значення.
  • .envrc (direnv) є shell-скриптом і лишається для розширень shell.
  • Звіт за кодом бачить лише буквальні імена, як-от process.env.API_KEY. Імена, що будуються під час виконання, не знаходяться.
  • Проблеми визначаються за правилами пакета dotenv. Деякі інструменти (Docker Compose v1, systemd) суворіші, і саме на це вказують попередження.

Чи змінює воно мій файл .env, щоб приховати значення?

Ні. Змінюється лише відображення, файл ніколи не змінюється. Копіювання і вставлення й далі переносять справжнє значення.

Чому мій ключ позначено як заданий двічі?

Той самий ключ є у двох рядках. Пакет dotenv бере перше значення, а shell і Docker Compose беруть останнє. Швидке виправлення видаляє другий рядок.
