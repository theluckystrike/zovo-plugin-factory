Як редагувати файли .proto у VS Code з підсвічуванням, форматуванням і переходом до визначення

Встановіть безкоштовне розширення Protobuf & Proto3 Formatter і відкрийте папку з файлами .proto. Воно додає підсвічування, форматер, що зберігає кожен коментар, перехід до визначення, пошук посилань і помилки з формулюваннями protoc для proto2, proto3 і editions 2023 та 2024. Розширення працює офлайн із власним парсером, тому не потрібні ні protoc, ні мовний сервер, ні налаштування, і все це безкоштовно. Zovo Pro (19 USD один раз) додає три інструменти, Check Breaking Changes Against Git, Generate API Docs і Decode a Binary Message, і кожен має 3 безкоштовні спроби.

Як це зробити у VS Code

  1. Встановіть Protobuf & Proto3 Formatter з Marketplace або натисніть Ctrl+P (Cmd+P на macOS) і виконайте ext install zovo.zovo-protobuf.
  2. Відкрийте папку з файлами .proto. Підсвічування, структура (outline) і breadcrumbs з'являються одразу.
  3. Натисніть Shift+Alt+F (Shift+Option+F на macOS), щоб відформатувати файл, або ввімкніть editor.formatOnSave. Ви отримуєте одну інструкцію на рядок, відступи вашого редактора й по одному пробілу навколо =. Коментарі, групи, розділені порожніми рядками, і ваші розриви рядків у довгих інструкціях лишаються на місці.
  4. Натисніть F12 на типі або import, щоб перейти до визначення, і Shift+F12, щоб побачити всі використання. Ctrl або Cmd з клацанням на import відкриває файл. Наведіть курсор на тип, щоб побачити його поля й коментар.
  5. Помилки з'являються в панелі Problems з формулюваннями protoc: дубльовані номери полів (з наступним вільним номером), невідомі типи, типи без їхнього import, зарезервовані номери й імена, а також правила proto3 і editions. Невикористані import показано блідим.
  6. Якщо ваші import починаються з папки на кшталт proto/ або third_party/, вони знаходяться під час пошуку вгору від кожного файлу. Інші кореневі папки додайте в налаштування zovoProto.importPaths, як із protoc -I.

Що безкоштовно і що додає Zovo Pro

Підсвічування (також для блоків коду proto у Markdown), Format Document, перехід до визначення, пошук посилань, помилки в стилі protoc, структура, Go to Symbol in workspace, підказки при наведенні й автодоповнення, зокрема наступного вільного номера поля після =, безкоштовні. Входити в обліковий запис не потрібно, немає мережевих запитів і телеметрії.

Перш ніж ви зіллєте зміну у файлі .proto, Check Breaking Changes Against Git порівнює ваші файли з main (або з гілкою, яку ви задали) і перелічує видалені поля, змінені номери, типи й мітки, перейменовані поля та значення enum, а також видалені або змінені методи. Кожна знахідка вказує, що вона ламає: бінарні дані, JSON чи лише згенерований код, тож ви бачите, що старі клієнти прочитають неправильно, ще до того, як це станеться. Знахідки можна зберегти як файл JSON для CI.

Як запустити Check Breaking Changes Against Git (Zovo Pro)

  1. Клацніть правою кнопкою файл .proto або папку в Explorer і виберіть "Zovo Pro: Check breaking changes against git", клацніть правою кнопкою в редакторі .proto і виберіть "Check Breaking Changes Against Git (Pro)" або виконайте "Protobuf: Check Breaking Changes Against Git (Pro)" з Command Palette. Папка має бути в репозиторії git, і git має бути встановлено.
  2. Перевірка порівнює кожен файл .proto репозиторію у вашій робочій копії, разом із незбереженими змінами, з merge base гілки origin/main, main, origin/master або master (першої, яка існує) чи гілки з налаштування zovoProto.baseBranch. Відкривається звіт Markdown зі знахідками, згрупованими за файлами.
  3. Натисніть "Save JSON for CI" у повідомленні, щоб зберегти знахідки як proto-breaking.json.
  4. Спроба зараховується, лише коли звіт відкрився. Папка поза git або відсутня базова гілка спроби не витрачають.

Check Breaking Changes Against Git можна запустити на вашому комп’ютері 3 рази безкоштовно, після цього розширення попросить ліцензію. Жодних спливних вікон і жодного зворотного відліку.

Як встановити в Cursor, Windsurf або VSCodium

  1. Відкрийте панель Extensions клавішами Ctrl+Shift+X (Cmd+Shift+X на macOS).
  2. Знайдіть zovo.zovo-protobuf і натисніть Install. Cursor, Windsurf і VSCodium встановлюють розширення з Open VSX, де це розширення опубліковано як zovo/zovo-protobuf.
  3. Якщо у вашому редакторі немає каталогу розширень, завантажте файл .vsix зі сторінки Open VSX і виконайте «Extensions: Install from VSIX...».
  4. Далі все працює так само, як у VS Code.

Що вміє Protobuf & Proto3 Formatter

  • proto2, proto3 і editions (2023, 2024), а також блоки коду proto у Markdown.
  • Правила видимості protobuf для переходу до визначення й пошуку посилань через import: вкладені типи, пакети й початкова ..
  • Вбудовані імена для стандартних типів (well-known types), як-от google/protobuf/timestamp.proto.
  • Жодних хибних червоних позначок: коли import немає у вашій робочій області, рядок import повідомляє про це, а типи, які він мав би принести, не вгадуються.
  • Автодоповнення для типів, ключових слів, опцій, шляхів import і наступного вільного номера поля після =.

Чого розширення не робить

  • Імена власних опцій перевіряються на наявність import, але не на відповідність типу поля розширення.
  • Перевірки функцій editions охоплюють enum_type, мітки, packed і групи. Інші правила функцій лишаються для protoc.
  • Форматер зберігає ваші розриви рядків усередині довгих інструкцій. Він не переносить довгі рядки й не вирівнює = у стовпці.
  • Для форматування файл має розбиратися без помилок. Спершу виправте помилку з панелі Problems.
  • Для import між файлами потрібні папки на диску. У віртуальній робочій області працюють лише підсвічування, форматування й структура.

Це безкоштовно?

Підсвічування, форматування, перехід до визначення, пошук посилань, помилки в стилі protoc, підказки при наведенні й автодоповнення безкоштовні. Три Pro-інструменти, Check Breaking Changes Against Git, Generate API Docs і Decode a Binary Message, мають по 3 безкоштовні спроби. Після цього потрібен Zovo Pro, 19 USD один раз для всіх розширень Zovo.

Чи потрібно встановлювати protoc?

Ні. Розширення має власний парсер і працює офлайн. Помилки сформульовано так само, як у protoc.

Чому біля import замість червоних позначок примітка?

Імпортованого файлу немає у вашій робочій області. Додайте його кореневу папку в zovoProto.importPaths, як із protoc -I.

Чи працює воно в Cursor?

Так. Cursor, Windsurf і VSCodium встановлюють його з Open VSX, де воно опубліковане як zovo/zovo-protobuf.
