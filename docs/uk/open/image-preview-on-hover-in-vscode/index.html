Як побачити зображення за шляхом у коді, у гуттері й при наведенні

Встановіть безкоштовне розширення Image Preview & Image Hover і відкрийте файл, у якому згадано зображення. У гуттері поруч із рядком з'являється мініатюра, а наведення на шлях показує зображення, його тип, розмір у пікселях і розмір файлу. Це працює в імпортах JavaScript і TypeScript, JSX, CSS url(), Markdown, HTML src і srcset, YAML і data URI, без мережевих запитів. Zovo Pro (19 USD один раз) додає три інструменти, Find Unused Images, Find Broken Image References і Image Weight Report, і кожен має 3 безкоштовні спроби.

Як це зробити у VS Code

  1. Встановіть Image Preview & Image Hover з Marketplace або натисніть Ctrl+P (Cmd+P на macOS) і виконайте ext install zovo.zovo-image-preview.
  2. Відкрийте файл, у якому згадано зображення, наприклад import logo from './logo.png', CSS url() або HTML <img src>. У гуттері з'являються мініатюри, по одній на рядок.
  3. Наведіть курсор на шлях. Підказка показує зображення (зменшене за розміром, але ніколи не збільшене), його тип, ширину × висоту в пікселях, розмір файлу та прозорість, а також посилання, щоб відкрити файл або показати його в Explorer.
  4. Якщо шлях не вдається знайти, підказка повідомляє про це й перелічує шляхи, які перевірено. Додайте власні префікси в imgPreview.aliases, наприклад { "@images": "src/assets/images" }, або папки для шляхів, що починаються з /, в imgPreview.publicFolders.
  5. Щоб приховати мініатюри в гуттері, виконайте "Image Preview: Show or Hide Gutter Thumbnails" з Command Palette.
  6. Немає проєкту під рукою? Виконайте "Image Preview: Open the Sample Files", щоб відкрити невеликий демопроєкт з усіма видами шляхів.

Що безкоштовно і що додає Zovo Pro

Мініатюри в гуттері, підказка при наведенні, розпізнавання шляхів з аліасами, paths із tsconfig.json і jsconfig.json та пакетами monorepo, а також data URI безкоштовні. Немає облікового запису, мережевих запитів і телеметрії, і все працює офлайн.

Find Unused Images показує зображення в робочій області (або в одній папці), які не згадує жоден файл коду, стилів, Markdown, HTML, JSON чи YAML, від найбільшого, у звіті Markdown з їхніми розмірами. Після підтвердження вони переміщуються в папку _unused-images зі збереженням структури папок, а Edit > Undo повертає їх назад. Ви прибираєте старі зображення з проєкту, не перевіряючи кожне ім'я вручну.

Як запустити Find Unused Images (Zovo Pro)

  1. Клацніть правою кнопкою папку в Explorer і виберіть "Zovo Pro: Find unused images" або виконайте "Image Preview: Find Unused Images (Pro)" з Command Palette. Якщо в робочій області кілька папок, виберіть папку.
  2. Сповіщення показує прогрес із кнопкою Cancel. Потім відкривається звіт Markdown з кожним невикористаним зображенням і його розміром, від найбільшого.
  3. Натисніть "Move N to _unused-images", щоб перемістити їх, або закрийте повідомлення, щоб лишити їх на місці. Edit > Undo повертає їх назад.
  4. Спроба зараховується, лише коли звіт відкрився. Escape ніколи не витрачає спробу.

Find Unused Images можна запустити на вашому комп’ютері 3 рази безкоштовно, після цього розширення попросить ліцензію. Жодних спливних вікон і жодного зворотного відліку.

Як встановити в Cursor, Windsurf або VSCodium

  1. Відкрийте панель Extensions клавішами Ctrl+Shift+X (Cmd+Shift+X на macOS).
  2. Знайдіть zovo.zovo-image-preview і натисніть Install. Cursor, Windsurf і VSCodium встановлюють розширення з Open VSX, де це розширення опубліковано як zovo/zovo-image-preview.
  3. Якщо у вашому редакторі немає каталогу розширень, завантажте файл .vsix зі сторінки Open VSX і виконайте «Extensions: Install from VSIX...».
  4. Далі все працює так само, як у VS Code.

Що вміє Image Preview & Image Hover

  • Мініатюри в гуттері для файлів PNG, JPEG, GIF, WebP, AVIF, SVG, BMP і ICO та для URI data:image/.... Для файлів TIFF і HEIC розмір і тип зчитуються із заголовка.
  • Шляхи відносно файлу, /logo.png з public/, static/ та інших кореневих вебпапок, @/ для src/, ~ для node_modules або домашньої папки, а також paths із tsconfig.json чи jsconfig.json з extends.
  • Імена файлів із пробілами, %20, ?v=2 або #id. Просте ім'я, як-от beans.jpg у JSON, зіставляється з найближчим зображенням із таким ім'ям.
  • Monorepo: використовуються власна папка public/ і tsconfig.json кожного пакета.
  • Віддалений URL показується як посилання й ніколи не завантажується.

Чого розширення не робить

  • Шляхи, які будуються під час виконання коду, як-от `icons/${name}.svg` або склеювання рядків, не можна переглянути, і через них зображення може здаватися невикористаним. Перевірте список невикористаних, перш ніж переміщувати файли.
  • Одна мініатюра на рядок: перше зображення в цьому рядку. Підказка при наведенні працює для кожного шляху в рядку.
  • Віддалені й віртуальні робочі області (SSH, WSL, Codespaces, vscode.dev) у цій версії не підтримуються.
  • Аліаси Webpack, Vite або Next.js, які є лише у файлі конфігурації JavaScript, не зчитуються. Додайте їх в imgPreview.aliases або в paths у tsconfig.json.
  • Зображення понад 20 МБ вимірюються, але не відображаються (налаштування imgPreview.maxFileSizeMB). Image Weight Report позначає важкі файли, але не стискає їх.

Часті запитання

Це безкоштовно?

Мініатюри в гуттері, підказка при наведенні й розпізнавання шляхів безкоштовні. Три Pro-інструменти, Find Unused Images, Find Broken Image References і Image Weight Report, мають по 3 безкоштовні спроби. Після цього потрібен Zovo Pro, 19 USD один раз для всіх розширень Zovo.

Чому для мого шляху з @/ або аліасом немає зображення?

Аліас може бути лише у файлі конфігурації Webpack, Vite або Next.js, який не зчитується. Додайте його в imgPreview.aliases або в paths у tsconfig.json.

Чи працює воно через Remote SSH або WSL?

Не в цій версії. Зображення для підказки зчитується з локального диска.

Чи працює воно в Cursor?

Так. Cursor, Windsurf і VSCodium встановлюють його з Open VSX, де воно опубліковане як zovo/zovo-image-preview.
