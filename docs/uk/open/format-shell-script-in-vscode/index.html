Як форматувати скрипт bash або zsh у VS Code

Встановіть безкоштовне розширення Shell Formatter for Bash & Zsh, відкрийте shell-скрипт і натисніть Shift+Alt+F (Shift+Option+F на Mac). Рушій shfmt 3.14.1 постачається всередині розширення як WebAssembly, тому нічого не треба завантажувати, а результат байт у байт такий самий, як у shfmt з командного рядка. Format Document, Format Selection, форматування під час збереження, ключі .editorconfig і синтаксичні помилки в Problems безкоштовні й працюють офлайн. Zovo Pro (19 USD один раз) додає три інструменти, Format All Shell Scripts in a Folder, Formatting Check with a Patch File і Minify a Script to a Copy, і кожен має 3 безкоштовні спроби.

Як це зробити у VS Code

  1. Встановіть Shell Formatter for Bash & Zsh з Marketplace або натисніть Ctrl+P (Cmd+P на macOS) і виконайте ext install zovo.zovo-shell-formatter.
  2. Відкрийте shell-скрипт і натисніть Shift+Alt+F (Shift+Option+F на Mac). Якщо VS Code запитає, який форматер використати, виберіть Shell Formatter або виконайте "Shell Formatter: Use as Default Formatter for Shell Scripts".
  3. Щоб форматувати під час кожного збереження, виконайте "Shell Formatter: Turn On Format on Save for Shell Scripts".
  4. Діалект визначається з першого рядка (#!/bin/bash, #!/bin/sh, #!/usr/bin/env zsh), потім з імені файлу (.bash, .zsh, .zshrc, .bats, .ksh), а інакше це bash. Щоб вибрати його самостійно, задайте shellFormatter.dialect або shell_variant в .editorconfig.
  5. Клацніть shfmt 3.14.1 у рядку стану, щоб відкрити меню: форматування, вибір форматером за замовчуванням, форматування під час збереження, "Copy the matching shfmt command (for CI)" і налаштування.
  6. Якщо скрипт не є коректним shell-кодом, він лишається без змін, а панель Problems показує рядок і колонку.

Що безкоштовно і що додає Zovo Pro

Format Document, Format Selection, форматування під час збереження, визначення діалекту, ключі .editorconfig, меню в рядку стану, Copy the Matching shfmt Command (for CI) і синтаксичні помилки в Problems безкоштовні. Входити в обліковий запис не потрібно, немає мережевих запитів і телеметрії.

Format All Shell Scripts in a Folder перевіряє кожен скрипт у папці та її підпапках, знайдений за ім'ям або за рядком #! з назвою shell, і повідомляє, скільки з них зміниться. Потім він форматує їх усі або видає звіт Markdown, з тим самим рушієм, налаштуваннями й .editorconfig, що й Format Document. Репозиторій із десятками скриптів у різних стилях отримує один стиль за один запуск, а скрипти, які після форматування виконували б інші команди, лишаються як є.

Як запустити Format All Shell Scripts in a Folder (Zovo Pro)

  1. Клацніть правою кнопкою папку в Explorer і виберіть "Zovo Pro: Format All Shell Scripts in a Folder" або виконайте "Shell Formatter: Format All Shell Scripts in a Folder (Pro)" з Command Palette чи меню в рядку стану й виберіть папку.
  2. Заголовок наступного списку показує, скільки скриптів зміниться, наприклад "N of M scripts would change".
  3. Виберіть "Format N scripts", щоб відформатувати й зберегти кожен файл (Undo працює для кожного файлу окремо), або "Show the report only", щоб отримати список Markdown з усіма скриптами без жодних змін.
  4. Спроба зараховується, лише коли ви отримали результат. Папка без shell-скриптів або з уже відформатованими скриптами спроби не витрачає.

Format All Shell Scripts in a Folder можна запустити на вашому комп’ютері 3 рази безкоштовно, після цього розширення попросить ліцензію. Жодних спливних вікон і жодного зворотного відліку.

Як встановити в Cursor, Windsurf або VSCodium

  1. Відкрийте панель Extensions клавішами Ctrl+Shift+X (Cmd+Shift+X на macOS).
  2. Знайдіть zovo.zovo-shell-formatter і натисніть Install. Cursor, Windsurf і VSCodium встановлюють розширення з Open VSX, де це розширення опубліковано як zovo/zovo-shell-formatter.
  3. Якщо у вашому редакторі немає каталогу розширень, завантажте файл .vsix зі сторінки Open VSX і виконайте «Extensions: Install from VSIX...».
  4. Далі все працює так само, як у VS Code.

Що вміє Shell Formatter for Bash & Zsh

  • Скрипти bash, POSIX sh (а також dash і ash), mksh (а також ksh), bats і zsh.
  • Такий самий результат, як у shfmt 3.14.1 з командного рядка: 354 з 354 запусків на 178 реальних скриптах із проєктів GitHub і Homebrew збіглися байт у байт.
  • Перш ніж зміну буде застосовано, відформатований скрипт розбирається ще раз і має виконувати ті самі команди, що й оригінал (для файлів до 256 KB).
  • Параметри shfmt як налаштування або ключі .editorconfig: відступ, бінарні оператори на наступному рядку, відступ case у switch, пробіли в перенаправленнях, збереження вирівнювання, дужки функцій на наступному рядку, спрощення й мінімізація.
  • Закінчення рядків Windows (CRLF) лишаються CRLF, а скрипт на 2 МБ форматується приблизно за 0,2 секунди.

Чого розширення не робить

  • Розширення ніколи не чіпає Dockerfile, файли .env, скрипти fish або csh.
  • Підтримка zsh у shfmt нова. Скрипт zsh, який shfmt не може розібрати, лишається без змін.
  • Файли понад 10 МБ (налаштування shellFormatter.maxFileMB) і файли з бінарними байтами, як-от самостійно розпаковувані інсталятори, не форматуються.
  • shfmt працює з обмеженням часу (10 секунд за замовчуванням, налаштування shellFormatter.timeoutSeconds). Якщо його досягнуто, файл лишається без змін.

Чи треба встановлювати shfmt?

Ні. shfmt 3.14.1 постачається всередині розширення як WebAssembly, тому працює офлайн і нічого не треба завантажувати.

Чи не зламає воно мій скрипт?

Скрипт із синтаксичною помилкою лишається без змін. Перш ніж зміну буде застосовано, відформатований скрипт розбирається ще раз і має виконувати ті самі команди, що й оригінал.
