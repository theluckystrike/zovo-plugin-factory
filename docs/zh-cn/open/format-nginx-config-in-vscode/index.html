在 VS Code 中的步骤

  1. 从 Marketplace 安装 Nginx Config Formatter & Lint，或者按 Ctrl+P（macOS 上按 Cmd+P）后运行 ext install zovo.zovo-nginx-config。
  2. 打开配置文件。以下文件会自动按 nginx 打开：名为 nginx.conf 的文件，以 .nginx 或 .nginxconf 结尾的文件，名为 nginx 的文件夹里的 .conf 文件（例如 /etc/nginx/conf.d/default.conf），以及 nginx/sites-available、nginx/sites-enabled 或 nginx/snippets 中的文件。其他文件请把语言模式选为“nginx”。
  3. 按 Shift+Alt+F（Mac 上按 Shift+Option+F）。每条语句占一行，缩进跟随编辑器设置，较长的 log_format 值保留原有换行，连续空行最多保留一行（设置项 nginxConfig.format.maxBlankLines）。
  4. 输入时就会显示问题：缺少 ;、花括号未闭合或多余、字符串未闭合、指令放错了块、root 或 listen 重复、同一端口上有两个同名 server。按 Ctrl+.（Mac 上按 Cmd+.）使用快速修复，例如“Add the missing ";"”，或把 proxy_set_heder 改成 proxy_set_header。
  5. 把鼠标悬停在指令上，可以看到它的语法、默认值、允许出现的块，以及 nginx 文档的链接。补全会列出当前块中允许的指令，输入 $ 后会列出变量。
  6. 点击编辑器标题栏中的列表图标，或运行“Nginx: Show Config Overview”，查看跨 include 文件的每个 server 及其端口和名称，以及每个 location 的作用。点击文件和行号即可跳转过去。

Nginx Config Formatter & Lint 能做什么

  • OpenResty/Lua、headers-more、Brotli、Passenger 等常用模块的指令都能识别，不会被标为错误。
  • content_by_lua_block 这类 Lua 块按 Lua 着色。
  • 大纲（Outline）视图列出 server 及其名称和端口、location、upstream 和 map。
  • 相对路径的 include 依次从 nginxConfig.prefix、文件所在文件夹、上一级文件夹或 /etc/nginx 读取。
  • 配置概览和 Pro 工具会使用已打开编辑器中尚未保存的修改。

它做不到的事

  • 格式化时指令和参数之间只留一个空格，所以 listen 80; 这样的列对齐不会保留。
  • 有未闭合花括号或字符串的文件不会被格式化。文件保持不变，状态栏会说明原因。
  • 检查只读取你的文件，不会运行 nginx -t。证书文件缺失、模块未加载这类问题只有 nginx 本身才能发现。
  • location 的正则用 JavaScript 正则表达式测试。少数 PCRE 独有的功能（占有量词、递归）无法测试，会报告为已跳过。

常见问题

免费吗？

格式化、问题和快速修复、悬停帮助、补全、大纲和配置概览都是免费的。三个 Pro 工具 Security Audit、Location Tester 和 Convert .htaccess to nginx 各有 3 次免费试用。之后需要 Zovo Pro，一次性 19 美元，适用于所有 Zovo 扩展。

格式化会破坏我的配置吗？

不会。格式化程序会解析自己的输出结果，如果文件读起来和原来不一样，就什么都不改，所以有效的配置仍然有效。

它能代替 nginx -t 吗？

不能。它读取你的文件，检查语法和每条指令所在的位置。证书和模块请在服务器上运行 nginx -t 检查。

在 Cursor 中能用吗？

能。Cursor、Windsurf 和 VSCodium 从 Open VSX 安装它，发布名称为 zovo/zovo-nginx-config。
