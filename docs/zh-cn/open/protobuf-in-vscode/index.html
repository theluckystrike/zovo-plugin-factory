在 VS Code 中编辑 .proto 文件：语法高亮、格式化和转到定义

安装免费的 Protobuf & Proto3 Formatter，然后打开一个包含 .proto 文件的文件夹。它提供语法高亮、保留所有注释的格式化、转到定义、查找引用，以及与 protoc 措辞一致的错误提示，支持 proto2、proto3 以及 editions 2023 和 2024。它用自带的解析器离线运行，不需要 protoc，不需要语言服务器，也不需要任何配置，这些功能全部免费。Zovo Pro（一次性 19 美元）增加三个工具：Check Breaking Changes Against Git、Generate API Docs 和 Decode a Binary Message，每个工具可以免费试用 3 次。

在 VS Code 中的步骤

  1. 从 Marketplace 安装 Protobuf & Proto3 Formatter，或者按 Ctrl+P（macOS 上按 Cmd+P）后运行 ext install zovo.zovo-protobuf。
  2. 打开一个包含 .proto 文件的文件夹。语法高亮、大纲和面包屑导航会立即生效。
  3. 按 Shift+Alt+F（macOS 上为 Shift+Option+F）格式化，或者打开 editor.formatOnSave。格式化后每行一条语句，缩进跟随编辑器设置，= 两侧各一个空格。注释、空行分组以及你在长语句中的换行都保持原样。
  4. 在类型或 import 上按 F12 转到定义，按 Shift+F12 列出所有引用。按住 Ctrl 或 Cmd 点击 import 可以打开对应文件。将鼠标悬停在类型上，可以看到它的字段和注释。
  5. 错误显示在 Problems 面板中，措辞与 protoc 一致：重复的字段编号（并给出下一个可用编号）、未知类型、未导入就使用的类型、保留的编号和名称，以及 proto3 和 editions 的规则。未使用的 import 会变暗显示。
  6. 如果你的 import 从 proto/ 或 third_party/ 这样的文件夹开始写，扩展会从每个文件向上查找。其他根目录请添加到设置 zovoProto.importPaths 中，用法和 protoc -I 相同。

哪些免费，Zovo Pro 增加什么

语法高亮（包括 Markdown 中的 proto 代码块）、Format Document、转到定义、查找引用、protoc 风格的错误提示、大纲、Go to Symbol in workspace、悬停提示和自动补全（包括 = 后面的下一个可用字段编号）都免费。不需要登录，不发送网络请求，没有遥测。

在合并对 .proto 文件的修改之前，Check Breaking Changes Against Git 会把你的文件与 main（或你设置的分支）比较，列出被删除的字段，编号、类型和标签（label）的变化，重命名的字段和枚举值，以及被删除或修改的方法。每条结果都会说明它破坏的是二进制数据、JSON，还是只影响生成的代码。这样你能在旧客户端读错数据之前就发现问题。结果可以保存为 JSON 文件，供 CI 使用。

使用 Check Breaking Changes Against Git（Zovo Pro）

  1. 在 Explorer 中右键一个 .proto 文件或文件夹，选择 “Zovo Pro: Check breaking changes against git”；或者在 .proto 编辑器中右键，选择 “Check Breaking Changes Against Git (Pro)”；也可以在 Command Palette 中运行 “Protobuf: Check Breaking Changes Against Git (Pro)”。文件夹必须位于 git 仓库中，并且需要已安装 git。
  2. 检查会把工作区中仓库的所有 .proto 文件（包括未保存的修改）与 origin/main、main、origin/master 或 master（取第一个存在的分支）的 merge base 比较，或者与设置 zovoProto.baseBranch 中指定分支的 merge base 比较。随后会打开一份 Markdown 报告，结果按文件分组。
  3. 在提示消息中点击 “Save JSON for CI”，把结果保存为 proto-breaking.json。
  4. 只有报告成功打开才会消耗一次试用。文件夹不在 git 中或找不到基准分支时，不会消耗次数。

Protobuf & Proto3 Formatter 能做什么

  • proto2、proto3 和 editions（2023、2024），以及 Markdown 中的 proto 代码块。
  • 跨 import 转到定义和查找引用时遵循 protobuf 的作用域规则：嵌套类型、包（package）和开头的 .。
  • 内置 well-known 类型的名称，例如 google/protobuf/timestamp.proto。
  • 不会误报红线：如果某个 import 不在你的工作区中，import 那一行会说明这一点，不会去猜测它带来的类型。
  • 自动补全类型、关键字、选项、import 路径，以及 = 后面的下一个可用字段编号。

它做不到的事

  • 自定义选项名只检查是否已导入，不检查是否符合扩展字段的类型。
  • editions 的 feature 检查覆盖 enum_type、标签（label）、packed 和 group。其他 feature 规则交给 protoc。
  • 格式化会保留你在长语句中的换行。它不会自动折行，也不会把 = 按列对齐。
  • 格式化要求文件能被正确解析。请先修复 Problems 面板中显示的错误。
  • 跨文件的 import 需要磁盘上的文件夹。在虚拟工作区中，只有语法高亮、格式化和大纲可用。

常见问题

免费吗？

语法高亮、格式化、转到定义、查找引用、protoc 风格的错误提示、悬停提示和自动补全都免费。三个 Pro 工具 Check Breaking Changes Against Git、Generate API Docs 和 Decode a Binary Message 各可免费试用 3 次。之后需要 Zovo Pro，一次性 19 美元，适用于所有 Zovo 扩展。

需要安装 protoc 吗？

不需要。扩展自带解析器，可以离线运行。错误提示的措辞与 protoc 相同。

为什么 import 那一行显示提示，而不是红线？

被导入的文件不在你的工作区中。把它的根文件夹添加到 zovoProto.importPaths，用法和 protoc -I 相同。

能在 Cursor 中使用吗？

能。Cursor、Windsurf 和 VSCodium 从 Open VSX 安装它，这个扩展在那里的名称是 zovo/zovo-protobuf。
