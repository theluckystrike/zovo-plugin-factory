VS Code에서 nginx 설정 파일을 포맷하고 검사하는 방법

무료 확장 Nginx Config Formatter & Lint를 설치하고 nginx 설정 파일을 연 다음 Shift+Alt+F(Mac에서는 Shift+Option+F)를 누릅니다. 포맷터는 자신의 결과를 다시 파싱해 보고, 파일이 원래와 같은 뜻으로 읽히지 않으면 아무것도 바꾸지 않습니다. 그래서 올바른 설정은 포맷 후에도 올바릅니다. 구문 색상, 입력 중에 표시되는 문제와 빠른 수정, 약 300개 지시어의 호버 도움말, 자동 완성, 개요(Outline), include 파일까지 아우르는 설정 개요는 무료이며 내 컴퓨터에서 실행됩니다. Zovo Pro(USD 19 한 번)는 Security Audit, Location Tester, Convert .htaccess to nginx의 세 가지 도구를 더하며, 각 도구는 3번 무료로 쓸 수 있습니다.

VS Code에서 하는 방법

  1. Marketplace에서 Nginx Config Formatter & Lint 확장을 설치하거나, Ctrl+P(macOS에서는 Cmd+P)를 누르고 ext install zovo.zovo-nginx-config를 실행합니다.
  2. 설정 파일을 엽니다. 이름이 nginx.conf인 파일, .nginx 또는 .nginxconf로 끝나는 파일, nginx라는 폴더 안의 .conf 파일(예: /etc/nginx/conf.d/default.conf), nginx/sites-available, nginx/sites-enabled, nginx/snippets 안의 파일은 nginx로 열립니다. 그 밖의 파일은 언어 모드로 "nginx"를 고릅니다.
  3. Shift+Alt+F(Mac에서는 Shift+Option+F)를 누릅니다. 한 줄에 문장 하나씩, 편집기의 들여쓰기로 정리되고, 긴 log_format 값은 줄바꿈을 그대로 유지하며, 연속된 빈 줄은 최대 한 줄만 남습니다(설정 nginxConfig.format.maxBlankLines).
  4. 입력하는 동안 문제가 표시됩니다. 빠진 ;, 닫히지 않았거나 남는 중괄호, 닫히지 않은 문자열, 잘못된 블록에 있는 지시어, 중복된 root 또는 listen, 같은 포트에서 이름이 같은 두 server가 대상입니다. Ctrl+.(Mac에서는 Cmd+.)를 눌러 "Add the missing ";""나 proxy_set_heder를 proxy_set_header로 바꾸는 빠른 수정을 적용합니다.
  5. 지시어에 마우스를 올리면 구문, 기본값, 쓸 수 있는 블록, nginx 문서 링크가 보입니다. 자동 완성은 현재 블록에서 쓸 수 있는 지시어와 $ 뒤의 변수를 제안합니다.
  6. 편집기 제목 표시줄의 목록 아이콘을 클릭하거나 "Nginx: Show Config Overview"를 실행하면 include 파일까지 포함해 모든 server의 포트와 이름, 모든 location이 하는 일을 볼 수 있습니다. 파일과 줄을 클릭하면 그 위치로 이동합니다.

무료 기능과 Zovo Pro가 더하는 기능

구문 색상(Lua 블록은 Lua로 색칠), Format Document, 문제 표시와 빠른 수정, 호버 도움말, 자동 완성, 개요, 설정 개요는 무료입니다. 모든 기능이 내 컴퓨터에서 실행되며 네트워크 요청을 보내지 않습니다.

Security Audit는 설정을 모든 include 파일과 함께 검사하고, 찾은 항목마다 파일, 줄, 왜 문제인지, 고치는 방법을 high, medium, low로 나누어 보여 줍니다. TLS 1.0과 1.1, 약한 암호 스위트, HSTS와 다른 보안 헤더가 없는 HTTPS server, 자체 add_header 때문에 이 헤더들이 조용히 빠지는 location, alias의 off-by-slash 경로 탐색, 요청에서 가져온 호스트로 가는 proxy_pass, 외부에 제공되는 .git과 .env 파일, 폴더 목록 표시, 크기 제한이 없는 요청 본문을 찾습니다. 설정을 운영 환경에 올리기 전에 include 파일을 하나하나 직접 읽지 않고도 이런 실수를 찾을 수 있습니다.

  1. Ctrl+Shift+X(macOS에서는 Cmd+Shift+X)로 Extensions 보기를 엽니다.
  2. zovo.zovo-nginx-config를 검색하고 Install을 누릅니다. Cursor, Windsurf, VSCodium은 Open VSX에서 확장을 설치하며, 이 확장은 그곳에서 zovo/zovo-nginx-config라는 이름으로 올라가 있습니다.
  3. 에디터에 확장 갤러리가 없으면 Open VSX 페이지에서 .vsix 파일을 내려받고 "Extensions: Install from VSIX..."를 실행합니다.
  4. 그다음은 VS Code에서와 똑같이 동작합니다.

Nginx Config Formatter & Lint의 기능

  • OpenResty/Lua, headers-more, Brotli, Passenger 등 자주 쓰는 모듈의 지시어를 알고 있어 오류로 표시하지 않습니다.
  • content_by_lua_block 같은 Lua 블록은 Lua로 색칠됩니다.
  • 개요(Outline) 보기에 server와 그 이름과 포트, location, upstream, map이 나열됩니다.
  • 상대 경로 include는 nginxConfig.prefix, 파일이 있는 폴더, 그 상위 폴더, /etc/nginx 순서로 찾습니다.
  • 설정 개요와 Pro 도구는 열린 편집기의 저장하지 않은 변경 내용도 반영합니다.

할 수 없는 것

  • 포맷터는 지시어와 값 사이에 공백 한 칸을 넣으므로 listen 80; 같은 열 정렬은 유지되지 않습니다.
  • 닫히지 않은 중괄호나 문자열이 있는 파일은 포맷하지 않습니다. 파일은 그대로 두고 상태 표시줄에 이유를 보여 줍니다.
  • 검사는 파일을 읽기만 하며 nginx -t를 실행하지 않습니다. 인증서 파일이 없거나 모듈이 로드되지 않은 문제는 nginx 자체만 찾을 수 있습니다.
  • location 정규식은 JavaScript 정규 표현식으로 테스트합니다. PCRE에만 있는 일부 기능(소유 수량자, 재귀)은 테스트할 수 없어 건너뛴 것으로 표시됩니다.

자주 묻는 질문

무료인가요?

포맷, 문제 표시와 빠른 수정, 호버 도움말, 자동 완성, 개요, 설정 개요는 무료입니다. 세 가지 Pro 도구 Security Audit, Location Tester, Convert .htaccess to nginx는 각각 3번 무료로 쓸 수 있습니다. 그다음에는 모든 Zovo 확장에 적용되는 Zovo Pro(USD 19 한 번)가 필요합니다.

포맷하면 설정이 깨질 수 있나요?

아니요. 포맷터는 자신의 결과를 다시 파싱해 보고, 파일이 원래와 같은 뜻으로 읽히지 않으면 아무것도 바꾸지 않습니다. 그래서 올바른 설정은 그대로 올바릅니다.

nginx -t를 대신하나요?

아니요. 파일을 읽어 구문과 각 지시어의 위치를 검사합니다. 인증서와 모듈은 서버에서 nginx -t를 실행해 확인합니다.

Cursor에서도 되나요?

네. Cursor, Windsurf, VSCodium은 Open VSX에서 설치하며, 이 확장은 그곳에 zovo/zovo-nginx-config로 게시되어 있습니다.
