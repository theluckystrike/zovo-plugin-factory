VS Code에서 코드 속 이미지 경로의 이미지를 거터와 호버로 보기

무료 확장 Image Preview & Image Hover를 설치하고 이미지를 가리키는 파일을 엽니다. 해당 줄 옆 거터에 썸네일이 표시되고, 경로에 마우스를 올리면 이미지와 형식, 픽셀 크기, 파일 크기가 나옵니다. JavaScript와 TypeScript import, JSX, CSS url(), Markdown, HTML src와 srcset, YAML, data URI에서 동작하며 네트워크 요청은 보내지 않습니다. Zovo Pro(USD 19 한 번)는 Find Unused Images, Find Broken Image References, Image Weight Report의 세 가지 도구를 더하며, 각 도구는 3번 무료로 쓸 수 있습니다.

VS Code에서 하는 방법

  1. Marketplace에서 Image Preview & Image Hover 확장을 설치하거나, Ctrl+P(macOS에서는 Cmd+P)를 누르고 ext install zovo.zovo-image-preview를 실행합니다.
  2. import logo from './logo.png', CSS url(), HTML <img src>처럼 이미지를 가리키는 파일을 엽니다. 거터에 줄마다 썸네일이 하나씩 표시됩니다.
  3. 경로에 마우스를 올립니다. 호버에는 이미지(크기에 맞게 줄이며 확대하지는 않음), 형식, 너비 × 높이 픽셀, 파일 크기, 투명도가 나오고, 파일을 열거나 Explorer에서 보여 주는 링크가 있습니다.
  4. 경로를 찾지 못하면 호버에 그렇게 표시되고, 찾아본 경로 목록이 나옵니다. imgPreview.aliases에 { "@images": "src/assets/images" } 같은 접두사를 직접 추가하거나, /로 시작하는 경로에 쓸 폴더를 imgPreview.publicFolders에 추가합니다.
  5. 거터 썸네일을 숨기려면 Command Palette에서 "Image Preview: Show or Hide Gutter Thumbnails"를 실행합니다.
  6. 프로젝트가 없다면 "Image Preview: Open the Sample Files"를 실행해 모든 종류의 경로가 들어 있는 작은 데모 프로젝트를 엽니다.

무료 기능과 Zovo Pro가 더하는 기능

거터 썸네일, 호버, 별칭을 쓰는 경로 해석, tsconfig.json과 jsconfig.json의 paths, 모노레포 패키지, data URI는 무료입니다. 계정, 네트워크 요청, 원격 측정이 없으며 오프라인에서도 동작합니다.

Find Unused Images는 작업 영역(또는 한 폴더)에서 어떤 코드, 스타일, Markdown, HTML, JSON, YAML 파일도 가리키지 않는 이미지를 찾아, 큰 것부터 크기와 함께 Markdown 보고서로 보여 줍니다. 확인하면 이 이미지들은 폴더 구조를 유지한 채 _unused-images 폴더로 옮겨지고, Edit > Undo로 되돌릴 수 있습니다. 파일 이름을 하나하나 확인하지 않고도 프로젝트의 오래된 이미지를 정리할 수 있습니다.

Find Unused Images 사용하기 (Zovo Pro)

  1. Explorer에서 폴더를 마우스 오른쪽 버튼으로 클릭하고 "Zovo Pro: Find unused images"를 고르거나, Command Palette에서 "Image Preview: Find Unused Images (Pro)"를 실행합니다. 작업 영역 폴더가 여러 개면 폴더를 고릅니다.
  2. 알림에 진행 상황과 Cancel 버튼이 표시됩니다. 끝나면 사용하지 않는 이미지와 그 크기를 큰 것부터 나열한 Markdown 보고서가 열립니다.
  3. "Move N to _unused-images"를 클릭해 옮기거나, 메시지를 닫아 그대로 둡니다. Edit > Undo로 다시 원래 위치로 옮길 수 있습니다.
  4. 보고서가 열렸을 때만 시도 횟수가 차감됩니다. Escape를 누르면 차감되지 않습니다.

Find Unused Images 기능은 라이선스를 묻기 전에 내 컴퓨터에서 3번 무료로 쓸 수 있습니다. 팝업도 없고 카운트다운도 없습니다.

Cursor, Windsurf, VSCodium에서

  1. Ctrl+Shift+X(macOS에서는 Cmd+Shift+X)로 Extensions 보기를 엽니다.
  2. zovo.zovo-image-preview를 검색하고 Install을 누릅니다. Cursor, Windsurf, VSCodium은 Open VSX에서 확장을 설치하며, 이 확장은 그곳에서 zovo/zovo-image-preview라는 이름으로 올라가 있습니다.
  3. 에디터에 확장 갤러리가 없으면 Open VSX 페이지에서 .vsix 파일을 내려받고 "Extensions: Install from VSIX..."를 실행합니다.
  4. 그다음은 VS Code에서와 똑같이 동작합니다.

Image Preview & Image Hover의 기능

  • PNG, JPEG, GIF, WebP, AVIF, SVG, BMP, ICO 파일과 data:image/... URI의 거터 썸네일. TIFF와 HEIC 파일은 헤더에서 크기와 형식을 읽습니다.
  • 파일 기준 상대 경로, public/, static/ 같은 웹 루트 폴더의 /logo.png, src/를 가리키는 @/, node_modules나 홈 폴더를 가리키는 ~, extends를 포함한 tsconfig.json 또는 jsconfig.json의 paths.
  • 공백, %20, ?v=2, #id가 들어간 파일 이름. JSON 안의 beans.jpg처럼 이름만 있는 값은 가장 가까운 같은 이름의 이미지와 연결됩니다.
  • 모노레포에서는 패키지마다 자체 public/ 폴더와 tsconfig.json을 사용합니다.
  • 원격 URL은 링크로만 표시되며 다운로드하지 않습니다.

할 수 없는 것

  • `icons/${name}.svg`나 문자열 연결처럼 실행 시점에 만들어지는 경로는 미리 볼 수 없고, 이미지가 사용되지 않는 것처럼 보이게 할 수 있습니다. 파일을 옮기기 전에 미사용 목록을 확인하세요.
  • 썸네일은 줄마다 하나, 그 줄의 첫 번째 이미지만 표시됩니다. 호버는 줄의 모든 경로에서 동작합니다.
  • 이 버전은 원격 및 가상 작업 영역(SSH, WSL, Codespaces, vscode.dev)을 지원하지 않습니다.
  • JavaScript 설정 파일에만 있는 Webpack, Vite, Next.js 별칭은 읽지 않습니다. imgPreview.aliases나 tsconfig.json의 paths에 추가하세요.
  • 20 MB가 넘는 이미지는 크기만 재고 그리지 않습니다(설정 imgPreview.maxFileSizeMB). Image Weight Report는 무거운 파일을 표시하지만 압축하지는 않습니다.

자주 묻는 질문

무료인가요?

거터 썸네일, 호버, 경로 해석은 무료입니다. 세 가지 Pro 도구 Find Unused Images, Find Broken Image References, Image Weight Report는 각각 3번 무료로 쓸 수 있습니다. 그 뒤에는 Zovo Pro가 필요하며, USD 19 한 번으로 모든 Zovo 확장에 적용됩니다.

@/ 경로나 별칭 경로에 이미지가 안 보이는 이유는 무엇인가요?

그 별칭이 Webpack, Vite, Next.js 설정 파일에만 있을 수 있는데, 이 파일들은 읽지 않습니다. imgPreview.aliases나 tsconfig.json의 paths에 추가하세요.

Remote SSH나 WSL에서도 되나요?

이 버전에서는 되지 않습니다. 호버의 이미지는 로컬 디스크에서 읽습니다.

Cursor에서도 되나요?

네. Cursor, Windsurf, VSCodium은 Open VSX에서 설치하며, 그곳에는 zovo/zovo-image-preview로 게시되어 있습니다.
