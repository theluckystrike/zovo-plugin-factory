VS Code에서 하는 방법

  1. Marketplace에서 Run C++ and C Code 확장을 설치하거나, Ctrl+P(macOS에서는 Cmd+P)를 누르고 ext install zovo.zovo-run-cpp를 실행합니다.
  2. 컴파일러가 설치되어 있는지 확인합니다. "Run C++: Pick Compiler (gcc, g++, clang, clang++)"가 찾은 컴파일러를 보여 줍니다. 하나도 없으면 설정 페이지에 운영체제별 공식 설치 방법(Xcode Command Line Tools, MSYS2나 WinLibs, Linux 패키지 관리자)이 나옵니다.
  3. .cpp, .cc, .cxx, .c 파일을 열고 에디터 제목 줄의 Run 버튼을 누르거나 Ctrl+Alt+Enter(Mac에서는 Cmd+Alt+Enter)를 누릅니다.
  4. 프로그램은 "Run: file.cpp"라는 터미널에서 실행됩니다. 입력은 그 터미널에 입력합니다. 끝나면 종료 코드, 실행 시간, 최대 메모리 사용량이 나옵니다. 실행하는 동안 Run 버튼은 Stop으로 바뀝니다.
  5. 컴파일 플래그나 실행 인자는 파일의 처음 40줄 안에 // run: -O2 -lm, // args: "Hello World" 3처럼 적습니다. C++ 기본값은 -std=c++20 -Wall -Wextra -g -O0입니다.
  6. 저장한 입력으로 테스트하려면 "Run C++: Run with Input & Test Cases"를 실행합니다. 입력을 붙여 넣고 Run with input을 누른 다음 Save as test case를 누릅니다. Run all tests는 통과, 실패를 줄 단위 diff와 함께 보여 줍니다.

무료 기능과 Zovo Pro가 더하는 기능

Run, Build Only, Run Last Build, Debug, 폴더 빌드, Input & Tests 패널, 스트레스 테스트, 벤치마크는 무료입니다. 로그인이 필요 없고, 네트워크를 쓰지 않으며 텔레메트리도 없습니다.

테스트를 통과한 프로그램도 배열 끝을 넘어 읽거나 int 오버플로를 일으킬 수 있습니다. Sanitizer check는 AddressSanitizer와 UndefinedBehaviorSanitizer(-fsanitize=address,undefined)를 켠 두 번째 빌드를 만들어 패널의 입력과 저장한 모든 테스트 케이스로 실행하고, 힙이나 스택 오버플로, 해제 후 사용(use after free), 부호 있는 정수 오버플로 같은 정의되지 않은 동작을 Problems 패널의 해당 줄에 표시합니다. sanitizer 플래그를 손으로 설정하지 않고도 버그가 있는 줄을 찾습니다.

Sanitizer check 사용하기 (Zovo Pro)

  1. Input & Tests 패널에 입력을 넣고, 테스트 케이스가 있으면 저장합니다. 검사는 패널의 입력과 저장한 모든 테스트 케이스로 실행됩니다.
  2. 패널의 "Stress test, benchmark and more" 아래에서 "Sanitizer check (Pro)"를 누르거나, Command Palette에서 "Run C++: Sanitizer Check: AddressSanitizer and UBSan on the Input and Test Cases (Zovo Pro)"를 실행합니다.
  3. Problems 패널에서 항목을 클릭하면 해당 줄로 갑니다. 빌드 오류, Stop, Cancel로 끝나면 무료 횟수가 줄지 않습니다.

Sanitizer check 기능은 라이선스를 묻기 전에 내 컴퓨터에서 3번 무료로 쓸 수 있습니다. 팝업도 없고 카운트다운도 없습니다.

Cursor, Windsurf, VSCodium에서

  1. Ctrl+Shift+X(macOS에서는 Cmd+Shift+X)로 Extensions 보기를 엽니다.
  2. zovo.zovo-run-cpp를 검색하고 Install을 누릅니다. Cursor, Windsurf, VSCodium은 Open VSX에서 확장을 설치하며, 이 확장은 그곳에서 zovo/zovo-run-cpp라는 이름으로 올라가 있습니다.
  3. 에디터에 확장 갤러리가 없으면 Open VSX 페이지에서 .vsix 파일을 내려받고 "Extensions: Install from VSIX..."를 실행합니다.
  4. 그다음은 VS Code에서와 똑같이 동작합니다.

Run C++ and C Code의 기능

  • gcc, g++, clang, clang++로 컴파일하는 C, C++ 파일(.c, .cpp, .cc, .cxx).
  • Windows의 일반적인 폴더에 설치된 MSYS2, WinLibs, MinGW, TDM-GCC, LLVM, 그리고 g++-14 같은 Homebrew 이름.
  • 공백, &, ASCII가 아닌 글자가 들어간 경로. 셸이 경로를 해석하지 않기 때문입니다.
  • 백만 줄을 출력하는 프로그램. 패널은 처음 2,000줄을 보여 주고 나머지는 개수만 셉니다.

할 수 없는 것

  • 컴퓨터에 컴파일러가 있어야 하며, 확장이 컴파일러를 내려받지는 않습니다.
  • Input 패널과 테스트 케이스의 실행은 10초가 지나면 멈춥니다(설정 zovoRun.timeLimitSeconds).
  • 32 MB를 넘는 출력은 보관하지 않고 크기만 셉니다(설정 zovoRun.maxCapturedOutputMB).
  • Sanitizer check에는 sanitizer 런타임이 있는 컴파일러가 필요합니다. Windows의 MinGW gcc에는 없으므로 LLVM의 clang을 쓰세요. 이 경우 검사가 횟수를 쓰지 않고 알려 줍니다.
  • Debug를 쓰려면 CodeLLDB나 C/C++ 확장이 설치되어 있어야 합니다.

자주 묻는 질문

무료인가요?

Run, Build Only, Debug, 폴더 빌드, Input & Tests 패널, 스트레스 테스트, 벤치마크는 무료입니다. 세 Pro 도구 Sanitizer check, Compare -O0, -O2 and -O3, Test report는 각각 3번 무료로 써 볼 수 있습니다. 그다음에는 Zovo Pro가 필요하며, 모든 Zovo 확장에 쓰는 라이선스를 USD 19에 한 번 구매합니다.

프로그램에서 cin으로 입력을 받을 수 있나요?

네. 실제 터미널에서 실행되므로 cin과 scanf가 입력을 기다리고, 줄바꿈 없는 안내 문구도 먼저 보입니다.

settings.json이나 tasks.json이 바뀌나요?

아니요. 설정 파일에는 쓰지 않습니다. Debug를 누를 때만 .vscode/launch.json에 항목 하나를 추가합니다.

Cursor에서도 되나요?

네. 이 확장은 Open VSX에 올라가 있어 Cursor, Windsurf, VSCodium에서 설치할 수 있습니다.
