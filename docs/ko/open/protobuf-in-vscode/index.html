VS Code에서 구문 강조, 포맷, 정의로 이동으로 .proto 파일 편집하기

무료 확장 Protobuf & Proto3 Formatter를 설치하고 .proto 파일이 있는 폴더를 엽니다. 구문 강조, 모든 주석을 그대로 두는 포맷터, 정의로 이동, 참조 찾기, protoc과 같은 문구의 오류 표시를 proto2, proto3, editions 2023과 2024에 제공합니다. 자체 파서로 오프라인에서 동작하므로 protoc, 언어 서버, 설정이 필요 없으며 이 기능은 모두 무료입니다. Zovo Pro(USD 19 한 번)는 Check Breaking Changes Against Git, Generate API Docs, Decode a Binary Message의 세 가지 도구를 더하며, 각 도구는 3번 무료로 쓸 수 있습니다.

VS Code에서 하는 방법

  1. Marketplace에서 Protobuf & Proto3 Formatter 확장을 설치하거나, Ctrl+P(macOS에서는 Cmd+P)를 누르고 ext install zovo.zovo-protobuf를 실행합니다.
  2. .proto 파일이 있는 폴더를 엽니다. 구문 강조, 개요(outline), 이동 경로(breadcrumbs)가 바로 표시됩니다.
  3. Shift+Alt+F(macOS에서는 Shift+Option+F)를 눌러 포맷하거나 editor.formatOnSave를 켭니다. 한 줄에 문장 하나, 편집기의 들여쓰기, = 양쪽의 공백 한 칸으로 정리됩니다. 주석, 빈 줄로 나눈 묶음, 긴 문장 안에서 직접 넣은 줄바꿈은 그대로 남습니다.
  4. 타입이나 import에서 F12를 누르면 정의로 이동하고, Shift+F12를 누르면 사용된 곳이 나열됩니다. import를 Ctrl 또는 Cmd를 누른 채 클릭하면 그 파일이 열립니다. 타입에 마우스를 올리면 필드와 주석이 보입니다.
  5. 오류는 protoc과 같은 문구로 Problems 패널에 표시됩니다. 중복된 필드 번호(다음 빈 번호 함께 표시), 알 수 없는 타입, import 없이 쓴 타입, 예약된 번호와 이름, proto3와 editions 규칙이 대상입니다. 쓰지 않는 import는 흐리게 표시됩니다.
  6. import가 proto/나 third_party/ 같은 폴더에서 시작하면 각 파일에서 위로 올라가며 찾습니다. 다른 루트는 protoc -I처럼 zovoProto.importPaths 설정에 추가합니다.

무료 기능과 Zovo Pro가 더하는 기능

구문 강조(Markdown의 proto 코드 블록 포함), Format Document, 정의로 이동, 참조 찾기, protoc 스타일 오류, 개요, Go to Symbol in workspace, 호버, 자동 완성(= 뒤의 다음 빈 필드 번호 포함)은 무료입니다. 로그인, 네트워크 요청, 원격 측정이 없습니다.

.proto 파일 변경을 병합하기 전에 Check Breaking Changes Against Git이 파일을 main(또는 설정한 브랜치)과 비교해 삭제된 필드, 바뀐 번호, 타입, 레이블, 이름이 바뀐 필드와 enum 값, 삭제되거나 바뀐 메서드를 나열합니다. 각 결과에는 바이너리 데이터가 깨지는지, JSON이 깨지는지, 아니면 생성된 코드만 깨지는지가 표시됩니다. 그래서 이전 클라이언트가 데이터를 잘못 읽기 전에 미리 알 수 있습니다. 결과는 CI용 JSON 파일로 저장할 수 있습니다.

Check Breaking Changes Against Git 사용하기 (Zovo Pro)

  1. Explorer에서 .proto 파일이나 폴더를 마우스 오른쪽 버튼으로 클릭하고 "Zovo Pro: Check breaking changes against git"을 고르거나, .proto 편집기 안에서 마우스 오른쪽 버튼을 눌러 "Check Breaking Changes Against Git (Pro)"를 고르거나, Command Palette에서 "Protobuf: Check Breaking Changes Against Git (Pro)"를 실행합니다. 폴더가 git 저장소 안에 있어야 하고 git이 설치되어 있어야 합니다.
  2. 검사는 작업 트리에 있는 저장소의 모든 .proto 파일(저장하지 않은 편집 포함)을 origin/main, main, origin/master, master 중 처음 존재하는 브랜치, 또는 zovoProto.baseBranch 설정에 지정한 브랜치의 merge base와 비교합니다. 결과를 파일별로 묶은 Markdown 보고서가 열립니다.
  3. 메시지에서 "Save JSON for CI"를 클릭하면 결과가 proto-breaking.json으로 저장됩니다.
  4. 보고서가 열렸을 때만 시도 횟수가 차감됩니다. git 밖의 폴더이거나 기준 브랜치가 없으면 차감되지 않습니다.

Check Breaking Changes Against Git 기능은 라이선스를 묻기 전에 내 컴퓨터에서 3번 무료로 쓸 수 있습니다. 팝업도 없고 카운트다운도 없습니다.

  2. zovo.zovo-protobuf를 검색하고 Install을 누릅니다. Cursor, Windsurf, VSCodium은 Open VSX에서 확장을 설치하며, 이 확장은 그곳에서 zovo/zovo-protobuf라는 이름으로 올라가 있습니다.

Protobuf & Proto3 Formatter의 기능

  • proto2, proto3, editions(2023, 2024)와 Markdown의 proto 코드 블록.
  • import를 넘나드는 정의로 이동과 참조 찾기에 적용되는 protobuf 범위 규칙: 중첩 타입, 패키지, 맨 앞의 ..
  • google/protobuf/timestamp.proto 같은 well-known 타입의 내장 이름.
  • 잘못된 빨간 표시 없음: import한 파일이 작업 영역에 없으면 import 줄에 그 사실을 알리고, 그 파일이 가져올 타입을 추측하지 않습니다.
  • 타입, 키워드, 옵션, import 경로, = 뒤의 다음 빈 필드 번호 자동 완성.

할 수 없는 것

  • 사용자 지정 옵션 이름은 import 여부만 검사하고, extension 필드의 타입과는 비교하지 않습니다.
  • editions의 feature 검사는 enum_type, 레이블, packed, group만 다룹니다. 그 밖의 feature 규칙은 protoc에 맡깁니다.
  • 포맷터는 긴 문장 안의 줄바꿈을 그대로 둡니다. 긴 줄을 나누지 않고 =를 열에 맞춰 정렬하지도 않습니다.
  • 포맷하려면 파일이 파싱되어야 합니다. Problems 패널에 표시된 오류를 먼저 고칩니다.
  • 파일 간 import에는 디스크의 폴더가 필요합니다. 가상 작업 영역에서는 구문 강조, 포맷, 개요만 동작합니다.

자주 묻는 질문

무료인가요?

구문 강조, 포맷, 정의로 이동, 참조 찾기, protoc 스타일 오류, 호버, 자동 완성은 무료입니다. 세 가지 Pro 도구 Check Breaking Changes Against Git, Generate API Docs, Decode a Binary Message는 각각 3번 무료로 쓸 수 있습니다. 그 뒤에는 Zovo Pro가 필요하며, USD 19 한 번으로 모든 Zovo 확장에 적용됩니다.

protoc을 설치해야 하나요?

아니요. 확장에 자체 파서가 있어 오프라인에서 동작합니다. 오류 문구는 protoc과 같습니다.

import 줄에 빨간 표시 대신 안내가 나오는 이유는 무엇인가요?

import한 파일이 작업 영역에 없기 때문입니다. protoc -I처럼 그 파일의 루트 폴더를 zovoProto.importPaths에 추가합니다.

Cursor에서도 되나요?

네. Cursor, Windsurf, VSCodium은 Open VSX에서 설치하며, 그곳에는 zovo/zovo-protobuf로 게시되어 있습니다.
