Zovo Pro(USD 19 한 번)는 Compare .env with .env.example, Find Keys Missing in Code or .env, Convert .env to JSON, YAML, Kubernetes의 세 가지 도구를 더하며, 각 도구는 3번 무료로 쓸 수 있습니다.

VS Code에서 하는 방법

  1. Marketplace에서 Dotenv & .env File Editor 확장을 설치하거나, Ctrl+P(macOS에서는 Cmd+P)를 누르고 ext install zovo.zovo-dotenv를 실행합니다.
  2. .env 파일(.env.local, .env.production, *.env, .flaskenv도 포함)을 엽니다. 키, export, 값, 여러 줄 값, ${NAME} 참조에 색이 입혀집니다.
  3. 비밀처럼 보이는 값은 커서가 그 줄에 올 때까지 점으로 표시됩니다. 모두 보려면 편집기 제목 표시줄의 눈 모양 버튼을 클릭하거나 "Dotenv: Show or Hide Secret Values"를 실행합니다. .env.example 같은 템플릿은 가리지 않습니다.
  4. Problems 패널에 문제가 표시됩니다. 같은 키를 두 번 설정한 경우, = 앞뒤의 공백, 닫히지 않은 따옴표, =가 없는 줄, 잘못된 이름, 줄 끝 공백, 어느 줄에서도 설정하지 않은 ${NAME} 등입니다. 문제 위에서 Ctrl+.(Mac에서는 Cmd+.)를 누르면 수정 방법이 나옵니다.
  5. Format Document를 실행하면 = 앞뒤의 공백과 줄 끝 공백이 지워집니다. 주석, 순서, 따옴표는 그대로 남습니다.
  6. 값을 화면에 보이지 않고 복사하려면 "Dotenv: Copy the Value on This Line"을 실행합니다. 값이 가려져 있어도 따옴표와 이스케이프를 뺀 값을 복사합니다.
  7. 코드에서 process.env.DB_HOST, os.getenv("X"), System.getenv("X") 등에 마우스를 올리면 어느 .env 파일이 값을 설정하는지 보이고, F12를 누르면 그 줄이 열립니다.

무료 기능과 Zovo Pro가 더하는 기능

구문 색상, 비밀 값 가리기, 빠른 수정이 있는 문제 표시, Format Document, 키 개요, Copy the Value on This Line, 코드의 호버, 정의로 이동, 자동 완성은 무료입니다. 계정, 네트워크 요청, 원격 측정이 없습니다.

Compare .env with .env.example은 .env에 없는 키, .env.example에 문서화되지 않은 키, 비어 있는 키를 파일 옆에 열리는 보고서로 보여 줍니다. 그다음 버튼으로 빠진 키를 어느 파일에든 추가합니다. .env에는 예제 값으로, .env.example에는 빈 값으로 들어갑니다. .env의 값은 표시하거나 복사하지 않으므로, 파일을 한 줄씩 읽지 않고도 동료의 설정이나 실패한 배포 환경을 맞출 수 있습니다.

Compare .env with .env.example 사용하기 (Zovo Pro)

  1. Explorer에서 .env 파일을 마우스 오른쪽 버튼으로 클릭하고 "Zovo Pro: Compare .env with .env.example"을 고르거나, Command Palette에서 "Dotenv: Compare .env with .env.example (Pro)..."를 실행합니다. 활성 탭의 .env 파일을 쓰고, 없으면 어느 파일인지 묻습니다.

  4. 보고서가 열렸을 때만 시도 횟수가 차감됩니다. Escape나 Cancel을 누르면 차감되지 않습니다.

Dotenv & .env File Editor의 기능

  • .env, .env.*(.env.local, .env.production 등), *.env, .flaskenv 파일.
  • 이름에 PASSWORD, TOKEN, SECRET, API_KEY, DSN, DATABASE_URL 등이 들어간 키의 값만 가리거나, 모든 값을 가리거나, 가리지 않을 수 있습니다(설정 envFile.maskValues).
  • process.env와 import.meta.env(JavaScript, TypeScript), os.environ과 os.getenv(Python), os.Getenv(Go), ENV(Ruby), System.getenv(Java), env()(PHP) 등의 코드 호버와 정의로 이동.
  • process.env. 뒤에서 키 자동 완성.
  • 가린 값은 개요, 호버, 자동 완성에서도 가려진 채로 남습니다. 끄려면 설정 envFile.hoverShowsSecrets를 바꿉니다.

할 수 없는 것

  • 가리기는 화면에만 적용됩니다. 텍스트는 여전히 파일, 검색 결과, 미니맵 모양에 남아 있고, 복사해 붙여 넣으면 실제 값이 복사됩니다.
  • .envrc(direnv)는 셸 스크립트이므로 셸 확장에 맡깁니다.
  • 코드 보고서는 process.env.API_KEY 같은 리터럴 이름만 찾습니다. 실행 시점에 만들어지는 이름은 찾지 못합니다.
  • 문제 표시는 dotenv 패키지의 규칙을 따릅니다. 몇몇 도구(Docker Compose v1, systemd)는 더 엄격하며, 경고가 알려 주는 것이 바로 그 차이입니다.

자주 묻는 질문

무료인가요?

색상, 값 가리기, 빠른 수정이 있는 문제 표시, 서식 지정, 코드 호버는 무료입니다. 세 가지 Pro 도구 Compare .env with .env.example, Find Keys Missing in Code or .env, Convert .env to JSON, YAML, Kubernetes는 각각 3번 무료로 쓸 수 있습니다. 그 뒤에는 Zovo Pro가 필요하며, USD 19 한 번으로 모든 Zovo 확장에 적용됩니다.

값을 가리려고 .env 파일을 바꾸나요?

아니요. 표시만 바뀌고 파일은 절대 수정하지 않습니다. 복사해 붙여 넣으면 여전히 실제 값이 복사됩니다.

키가 두 번 설정되었다고 표시되는 이유는 무엇인가요?

같은 키가 두 줄에 있습니다. dotenv 패키지는 첫 번째 값을, 셸과 Docker Compose는 마지막 값을 씁니다. 빠른 수정은 두 번째 줄을 지웁니다.

Cursor에서도 되나요?

네. Cursor, Windsurf, VSCodium은 Open VSX에서 설치하며, 그곳에는 zovo/zovo-dotenv로 게시되어 있습니다.
