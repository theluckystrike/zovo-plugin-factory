Passo a passo no VS Code

  1. Instale o Dotenv & .env File Editor pelo Marketplace, ou aperte Ctrl+P (Cmd+P no macOS) e rode ext install zovo.zovo-dotenv.
  2. Abra um arquivo .env (ou .env.local, .env.production, *.env ou .flaskenv). Chaves, export, valores, valores de várias linhas e referências ${NAME} ganham cores.
  3. Os valores com cara de segredo aparecem como pontos até o cursor estar na linha deles. Clique no botão de olho no título do editor, ou rode "Dotenv: Show or Hide Secret Values", para mostrar todos. Modelos como .env.example nunca são escondidos.
  4. Os problemas aparecem no painel Problems: uma chave definida duas vezes, espaços em volta do =, uma aspa que nunca fecha, uma linha sem =, um nome inválido, espaços no fim da linha ou um ${NAME} que nenhuma linha define. Pressione Ctrl+. (Cmd+. no Mac) sobre um deles para ver a correção.
  5. Rode Format Document para tirar os espaços em volta do = e os espaços no fim das linhas. Comentários, ordem e aspas continuam como estão.
  6. Para copiar um valor sem mostrá-lo, rode "Dotenv: Copy the Value on This Line". O valor é copiado sem as aspas e os escapes, mesmo enquanto está escondido.
  7. No seu código, passe o mouse sobre process.env.DB_HOST, os.getenv("X"), System.getenv("X") e parecidos para ver qual arquivo .env define a variável, e pressione F12 para abrir essa linha.

Passo a passo no Cursor, Windsurf ou VSCodium

  1. Abra a visão Extensions com Ctrl+Shift+X (Cmd+Shift+X no macOS).
  2. Busque zovo.zovo-dotenv e clique em Install. Cursor, Windsurf e VSCodium instalam extensões do Open VSX, onde esta se chama zovo/zovo-dotenv.
  3. Se o seu editor não tiver galeria, baixe o arquivo .vsix na página do Open VSX e rode "Extensions: Install from VSIX...".
  4. Depois disso, tudo funciona como no VS Code.

O que o Dotenv & .env File Editor faz

  • Arquivos .env, .env.* (como .env.local e .env.production), *.env e .flaskenv.
  • Quais valores ficam escondidos: nomes com PASSWORD, TOKEN, SECRET, API_KEY, DSN, DATABASE_URL e parecidos, ou todos os valores, ou nenhum (configuração envFile.maskValues).
  • Hover e ir para a definição no código para process.env e import.meta.env (JavaScript, TypeScript), os.environ e os.getenv (Python), os.Getenv (Go), ENV (Ruby), System.getenv (Java), env() (PHP) e outros.
  • Autocompletar das chaves depois de process.env..
  • Os valores escondidos continuam escondidos na estrutura, nos hovers e no autocompletar, a menos que você desligue isso (configuração envFile.hoverShowsSecrets).

O que ele não faz

  • Esconder vale só para a tela. O texto continua no arquivo, nos resultados de busca e no desenho do minimapa, e copiar e colar copia o valor real.
  • .envrc (direnv) é um script de shell e fica com as extensões de shell.
  • O relatório de código enxerga nomes literais como process.env.API_KEY. Nomes montados quando o programa roda não são encontrados.
  • Os problemas seguem as regras do pacote dotenv. Algumas ferramentas (Docker Compose v1, systemd) são mais rígidas, e é isso que os avisos apontam.

Perguntas frequentes

É grátis?

As cores, os valores escondidos, os problemas com correções rápidas, a formatação e o hover no código são grátis. As três ferramentas Pro, Compare .env with .env.example, Find Keys Missing in Code or .env e Convert .env to JSON, YAML, Kubernetes, têm 3 usos grátis cada. Depois disso, elas precisam do Zovo Pro, 19 USD uma vez só para todas as extensões Zovo.

A extensão altera meu arquivo .env para esconder os valores?

Não. Só a exibição muda, e o arquivo nunca é modificado. Copiar e colar ainda copia o valor real.

Por que minha chave aparece como definida duas vezes?

A mesma chave está em duas linhas. O pacote dotenv fica com o primeiro valor, enquanto shells e o Docker Compose ficam com o último. A correção rápida remove a segunda linha.

Funciona no Cursor?

Sim. Cursor, Windsurf e VSCodium instalam a extensão pelo Open VSX, onde ela está publicada como zovo/zovo-dotenv.
