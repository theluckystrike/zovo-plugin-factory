Como ver a imagem de um caminho no seu código, na margem e no hover

Instale a extensão grátis Image Preview & Image Hover e abra um arquivo que cita uma imagem. Uma miniatura aparece na margem (gutter) ao lado da linha, e o hover sobre o caminho mostra a imagem, o tipo, o tamanho em pixels e o tamanho do arquivo. Funciona em imports de JavaScript e TypeScript, JSX, url() de CSS, Markdown, src e srcset de HTML, YAML e data URIs, sem nenhuma requisição de rede. O Zovo Pro (19 USD, pagos uma vez só) acrescenta três ferramentas, Find Unused Images, Find Broken Image References e o Image Weight Report, e cada uma tem 3 usos grátis.

Passo a passo no VS Code

  1. Instale o Image Preview & Image Hover pelo Marketplace, ou aperte Ctrl+P (Cmd+P no macOS) e rode ext install zovo.zovo-image-preview.
  2. Abra um arquivo que cita uma imagem, como import logo from './logo.png', um url() de CSS ou um <img src> de HTML. As miniaturas aparecem na margem, uma por linha.
  3. Passe o mouse sobre o caminho. O hover mostra a imagem (reduzida para caber, nunca ampliada), o tipo, largura × altura em pixels, o tamanho do arquivo e a transparência, com links para abrir o arquivo ou mostrá-lo no Explorer.
  4. Se um caminho não for encontrado, o hover avisa e lista os caminhos em que procurou. Adicione seus próprios prefixos em imgPreview.aliases, por exemplo { "@images": "src/assets/images" }, ou pastas para caminhos que começam com / em imgPreview.publicFolders.
  5. Para esconder as miniaturas da margem, rode "Image Preview: Show or Hide Gutter Thumbnails" pela Command Palette.
  6. Não tem um projeto à mão? Rode "Image Preview: Open the Sample Files" para abrir um pequeno projeto de demonstração com todos os tipos de caminho.

O que é grátis e o que o Zovo Pro acrescenta

As miniaturas na margem, o hover, a resolução de caminhos com aliases, os paths do tsconfig.json e do jsconfig.json e os pacotes de monorepo, além dos data URIs, são grátis. Não há conta, requisição de rede nem telemetria, e tudo funciona offline.

Find Unused Images lista as imagens do workspace (ou de uma pasta) que nenhum arquivo de código, estilo, Markdown, HTML, JSON ou YAML cita, das maiores para as menores, em um relatório Markdown com os tamanhos. Se você confirmar, elas são movidas para uma pasta _unused-images com a mesma estrutura de pastas, e Edit > Undo as traz de volta. Assim você limpa imagens antigas de um projeto sem conferir cada nome à mão.

Como usar Find Unused Images (Zovo Pro)

  1. Clique com o botão direito em uma pasta no Explorer e escolha "Zovo Pro: Find unused images", ou rode "Image Preview: Find Unused Images (Pro)" pela Command Palette. Com mais de uma pasta no workspace, escolha a pasta.
  2. Uma notificação mostra o progresso com um botão Cancel. Depois abre um relatório Markdown com cada imagem não usada e o tamanho dela, das maiores para as menores.
  3. Clique em "Move N to _unused-images" para movê-las, ou feche a mensagem para deixá-las onde estão. Edit > Undo as traz de volta.
  4. Um uso só conta quando o relatório abriu. Escape nunca gasta um.

Passo a passo no Cursor, Windsurf ou VSCodium

  1. Abra a visão Extensions com Ctrl+Shift+X (Cmd+Shift+X no macOS).
  2. Busque zovo.zovo-image-preview e clique em Install. Cursor, Windsurf e VSCodium instalam extensões do Open VSX, onde esta se chama zovo/zovo-image-preview.
  3. Se o seu editor não tiver galeria, baixe o arquivo .vsix na página do Open VSX e rode "Extensions: Install from VSIX...".
  4. Depois disso, tudo funciona como no VS Code.

O que o Image Preview & Image Hover faz

  • Miniaturas na margem para arquivos PNG, JPEG, GIF, WebP, AVIF, SVG, BMP e ICO e para URIs data:image/.... Arquivos TIFF e HEIC mostram o tamanho e o tipo lidos do cabeçalho.
  • Caminhos relativos ao arquivo, /logo.png a partir de public/, static/ e outras pastas raiz da web, @/ para src/, ~ para node_modules ou para a sua pasta pessoal, e paths do tsconfig.json ou jsconfig.json com extends.
  • Nomes de arquivo com espaços, %20, ?v=2 ou #id. Um nome simples como beans.jpg em JSON é associado à imagem mais próxima com esse nome.
  • Monorepos, usando a pasta public/ e o tsconfig.json de cada pacote.
  • Uma URL remota aparece como link e nunca é baixada.

O que ele não faz

  • Caminhos montados quando o código roda, como `icons/${name}.svg` ou concatenação de strings, não podem ser pré-visualizados e podem fazer uma imagem parecer não usada. Confira a lista de não usadas antes de mover arquivos.
  • Uma miniatura por linha, a da primeira imagem dessa linha. O hover funciona para cada caminho da linha.
  • Workspaces remotos e virtuais (SSH, WSL, Codespaces, vscode.dev) não são suportados nesta versão.
  • Aliases do Webpack, Vite ou Next.js que existem só em um arquivo de configuração JavaScript não são lidos. Adicione-os em imgPreview.aliases ou nos paths do tsconfig.json.
  • Imagens acima de 20 MB são medidas, mas não desenhadas (configuração imgPreview.maxFileSizeMB). O Image Weight Report aponta os arquivos pesados, mas não os comprime.

Perguntas frequentes

É grátis?

As miniaturas na margem, o hover e a resolução de caminhos são grátis. As três ferramentas Pro, Find Unused Images, Find Broken Image References e o Image Weight Report, têm 3 usos grátis cada. Depois disso, elas precisam do Zovo Pro, 19 USD uma vez só para todas as extensões Zovo.

Por que meu caminho com @/ ou com alias não mostra imagem?

O alias pode existir só em um arquivo de configuração do Webpack, Vite ou Next.js, que não é lido. Adicione-o em imgPreview.aliases ou nos paths do tsconfig.json.

Funciona via Remote SSH ou WSL?

Não nesta versão. A imagem do hover é lida do disco local.

Funciona no Cursor?

Sim. Cursor, Windsurf e VSCodium instalam a extensão pelo Open VSX, onde ela está publicada como zovo/zovo-image-preview.
